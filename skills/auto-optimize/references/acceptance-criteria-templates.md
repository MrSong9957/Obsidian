# 验收标准模板库

预定义的验收标准集合，按场景分类。每个场景包含 5-8 条可验证的验收标准，每条都有明确的 PASS/FAIL 定义和验证方法。

使用时直接选取匹配场景的模板，或混合多个模板的标准。研究者可以在此基础上增减标准，但每条新增标准也必须满足"可验证"的要求。

## UI / 前端界面

适用场景：登录页、仪表盘、表单、落地页、文件管理器、移动端界面

### AC-UI-1：核心功能可见性

- **验证方法**：Playwright `browser_navigate` 打开页面 + `browser_take_screenshot` 首屏截图 + `browser_snapshot` accessibility 快照
- **PASS 条件**：首屏截图中可见所有核心功能入口（如文件列表、上传按钮、搜索框等），accessibility 快照中包含对应的 ARIA 角色
- **FAIL 条件**：核心功能元素在首屏不可见，或 accessibility 快照中缺少关键元素

### AC-UI-2：主操作路径可完成

- **验证方法**：Playwright `browser_click` / `browser_type` 逐步执行主操作路径（如：选择文件 → 点击上传 → 等待完成提示）
- **PASS 条件**：主操作路径的每一步都有可操作的元素，操作后有视觉反馈（loading、成功提示、状态变化）
- **FAIL 条件**：操作步骤中元素不可点击、无反馈、或操作后无任何变化

### AC-UI-3：无 Console 错误

- **验证方法**：Playwright `browser_console_messages` 获取所有 console 消息，筛选 error 级别
- **PASS 条件**：error 级别消息为 0 条
- **FAIL 条件**：有 1 条或以上 error 级别 console 消息

### AC-UI-4：移动端响应式

- **验证方法**：Playwright `browser_resize` 到 375x667（iPhone SE），截图 + accessibility 快照
- **PASS 条件**：移动端截图显示布局正常（无水平滚动、文字可读、按钮可点击），核心功能仍可用
- **FAIL 条件**：出现水平滚动条、文字溢出、按钮重叠、或核心功能不可达

### AC-UI-5：交互反馈完整性

- **验证方法**：Playwright 逐一触发可交互元素（hover、click、focus），操作后截图
- **PASS 条件**：每个可交互元素在 hover/click/focus 时有视觉状态变化（颜色、阴影、动画等）
- **FAIL 条件**：任何可交互元素在操作时无任何视觉变化

### AC-UI-6：无未完成标记

- **验证方法**：代码内容搜索 `TODO`、`FIXME`、`placeholder`、`待实现`、`Lorem ipsum`
- **PASS 条件**：搜索结果为 0
- **FAIL 条件**：找到任何未完成标记

### AC-UI-7：色彩对比度

- **验证方法**：Playwright accessibility 快照检查 + 人工审查截图
- **PASS 条件**：文字和背景的对比度满足 WCAG AA 标准（4.5:1），截图中所有文字清晰可读
- **FAIL 条件**：有文字与背景对比度不足，难以辨认

### AC-UI-8：两种风格视觉可区分

- **验证方法**：对比两个变体的截图（首屏+全页）+ 提取 CSS 类名做独立性分析
- **PASS 条件**：两个变体在以下维度中至少满足 2 项：(1) 主色调不同（色相差异 ≥ 30°）(2) 排版风格不同（字体大小比例、间距节奏有明显差异）(3) CSS 类名 ≥50% 独有（不共享超过一半的类名）
- **FAIL 条件**：配色相似 + 布局雷同 + CSS 类名 >70% 共享——视觉上难以区分两个变体

## 后端 API / 服务

适用场景：REST API、微服务、数据接口、后台服务

### AC-API-1：核心端点可用

- **验证方法**：pytest 或 curl 测试所有核心端点，验证 HTTP 响应状态码
- **PASS 条件**：所有核心端点返回 200（GET）或 201（POST），响应体格式符合文档
- **FAIL 条件**：任何核心端点返回 4xx/5xx，或响应体格式不符合预期

### AC-API-2：输入验证完整

- **验证方法**：pytest 发送空值、超长字符串、特殊字符、负数等边界输入
- **PASS 条件**：非法输入返回 4xx 状态码 + 明确的错误消息，不抛出未处理异常
- **FAIL 条件**：非法输入导致 500 错误、数据库异常、或静默接受无效数据

### AC-API-3：错误响应不泄露内部信息

- **验证方法**：pytest 触发各种错误场景，检查错误响应体
- **PASS 条件**：错误响应不包含堆栈跟踪、SQL 语句、文件路径、内部 IP 等敏感信息
- **FAIL 条件**：错误响应中泄露任何内部实现细节

### AC-API-4：列表端点支持分页

- **验证方法**：pytest 请求列表端点，传入 page/limit/offset 参数
- **PASS 条件**：支持分页参数，返回正确数量的结果 + 总数信息
- **FAIL 条件**：忽略分页参数，一次性返回所有数据

### AC-API-5：无未处理异常

- **验证方法**：pytest 运行完整测试套件，包括边界情况和异常场景
- **PASS 条件**：所有测试通过，无未捕获的异常
- **FAIL 条件**：任何测试抛出未处理异常（TypeError、KeyError、AttributeError 等）

### AC-API-6：无未完成标记

- **验证方法**：代码搜索 `TODO`、`FIXME`、`NotImplemented`、`pass`（空函数体）
- **PASS 条件**：搜索结果为 0
- **FAIL 条件**：找到任何未完成标记或空实现

## 自动化工具 / 脚本

适用场景：文件处理、批量操作、CI/CD、运维脚本

### AC-TOOL-1：核心流程可运行

- **验证方法**：bash 运行脚本/工具，检查退出码和输出
- **PASS 条件**：脚本正常退出（exit code 0），输出预期结果
- **FAIL 条件**：脚本崩溃（非零退出码）或无输出

### AC-TOOL-2：空输入不崩溃

- **验证方法**：传入空文件、空目录、空字符串作为输入
- **PASS 条件**：优雅处理空输入，输出有意义的提示信息（如"没有找到输入文件"），退出码 0
- **FAIL 条件**：抛出 IndexError、FileNotFoundError、或返回非零退出码

### AC-TOOL-3：有帮助信息

- **验证方法**：运行 `python script.py --help` 或 `./script --help`
- **PASS 条件**：显示使用说明，包含参数列表和示例
- **FAIL 条件**：无帮助信息，或帮助信息缺少关键参数说明

### AC-TOOL-4：错误处理完整

- **验证方法**：传入不存在的路径、无权限文件、损坏的输入格式
- **PASS 条件**：每个错误场景输出有意义的错误信息，退出码非零但可区分
- **FAIL 条件**：抛出未处理异常（traceback 直接输出），或静默忽略错误

### AC-TOOL-5：进度反馈

- **验证方法**：运行处理大量数据或耗时操作
- **PASS 条件**：有进度指示（进度条、百分比、已处理/总数）
- **FAIL 条件**：长时间无任何输出，用户无法判断是否在运行

### AC-TOOL-6：幂等性

- **验证方法**：连续运行两次相同操作
- **PASS 条件**：第二次运行结果与第一次一致，不产生重复数据或副作用
- **FAIL 条件**：每次运行产生不同的结果或累积副作用

## 数据处理 / 管道

适用场景：ETL、数据清洗、分析管道、报表生成

### AC-DATA-1：数据准确性

- **验证方法**：pytest 用已知输入和期望输出对比，检查计算结果
- **PASS 条件**：所有测试用例的计算结果与期望输出完全匹配（数值误差在允许范围内）
- **FAIL 条件**：任何计算结果与期望不符

### AC-DATA-2：脏数据处理

- **验证方法**：pytest 传入包含缺失值、重复行、编码异常的测试数据
- **PASS 条件**：脏数据被正确处理（跳过+记录、填充默认值、或转换），不影响正常数据处理
- **FAIL 条件**：脏数据导致崩溃或影响其他数据的处理

### AC-DATA-3：大文件处理

- **验证方法**：传入大于内存的数据集或 10K+ 行数据
- **PASS 条件**：在合理时间内完成处理（不超过小文件时间的 10 倍），内存不无限增长
- **FAIL 条件**：内存溢出（OOM）、处理时间爆炸性增长

### AC-DATA-4：输出格式正确

- **验证方法**：检查输出文件格式（CSV 列数、JSON 结构、编码）
- **PASS 条件**：输出格式完全符合规范，编码正确（中文不乱码）
- **FAIL 条件**：格式错误、列数不对、编码乱码

### AC-DATA-5：空数据集不崩溃

- **验证方法**：传入 0 行数据
- **PASS 条件**：输出空结果文件（正确的表头/结构），退出码 0
- **FAIL 条件**：崩溃或无法处理空输入

## 通用软件开发

适用场景：无法归类的通用编程任务、算法实现、系统集成

### AC-GEN-1：核心功能正确

- **验证方法**：pytest 运行核心功能的测试用例（正常输入 + 边界输入）
- **PASS 条件**：所有测试用例通过
- **FAIL 条件**：任何测试失败

### AC-GEN-2：代码可直接运行

- **验证方法**：在干净环境中运行，检查是否缺少依赖
- **PASS 条件**：无需手动安装额外依赖即可运行（所有依赖在 requirements.txt / pyproject.toml 中声明）
- **FAIL 条件**：运行时报 ImportError 或 ModuleNotFoundError

### AC-GEN-3：空值/null 安全

- **验证方法**：pytest 传入 None、空字符串、空列表
- **PASS 条件**：优雅处理空值输入，返回合理的默认值或明确的错误
- **FAIL 条件**：抛出 TypeError、AttributeError、IndexError

### AC-GEN-4：错误处理完整

- **验证方法**：pytest 触发异常场景（网络错误、文件不存在、权限不足）
- **PASS 条件**：异常被捕获并转化为有意义的错误信息，不抛出未处理异常
- **FAIL 条件**：未处理的异常直接传播到调用者

### AC-GEN-5：无未完成标记

- **验证方法**：代码搜索 `TODO`、`FIXME`、`NotImplemented`、`pass`（空函数体）
- **PASS 条件**：搜索结果为 0
- **FAIL 条件**：找到任何未完成标记或空实现

## 文档 / 内容创作

适用场景：技术文档、用户手册、教程、README

### AC-DOC-1：代码示例可运行

- **验证方法**：逐个复制文档中的代码示例，在终端执行
- **PASS 条件**：所有代码示例直接运行无报错
- **FAIL 条件**：任何代码示例报错或输出与文档描述不符

### AC-DOC-2：结构完整

- **验证方法**：检查文档包含标题、目录、正文、示例
- **PASS 条件**：有清晰的标题层级、有目录或导航、有代码示例、有版本/日期信息
- **FAIL 条件**：缺少目录、标题层级混乱、无代码示例

### AC-DOC-3：术语一致性

- **验证方法**：搜索文档中关键术语的使用
- **PASS 条件**：同一概念使用一致的术语，首次出现时有定义或链接
- **FAIL 条件**：同一概念使用不同术语，缺少定义

### AC-DOC-4：实操性

- **验证方法**：按文档步骤从头到尾执行一次
- **PASS 条件**：每一步都可以直接操作完成，不需要额外的"你应该知道"知识
- **FAIL 条件**：步骤跳过关键信息，或假设读者有未说明的前置知识
