# 大白话知识萃取

把技术内容整理到零基础读者能理解、以后能快速复习的程度。先保证准确和关键信息完整，再保证通俗，最后压缩表达。精简不能以删掉因果、前提或关键实现为代价。

## 萃取流程

1. 读懂原文，找出它解决什么问题、为什么需要解决、核心机制、关键证据与适用边界。已有正文直接整理；仅有链接或文件名时先读取正文，读不到就说明缺失并请用户补充，不凭标题、摘要或记忆猜测。
2. 筛选高价值内容：保留支撑理解、判断或实践的概念、因果、实体、数据、代码、风险与限制。删除铺垫、重复解释、无关故事与没有信息增量的总结。
3. 按知识关系重组：先用一句话讲清本质和为什么需要，再解释怎样运作。先交代基本意思、必要条件和前后关系，再讲细节与例外。不要逐段缩写原文，也不要机械填满固定模板。
4. 用短句和常用词说清“谁做了什么、结果怎样”，一段一个重点。术语、缩写和关键符号首次出现就地解释，不用陌生词解释陌生词。
5. 抽象难点优先配最小具体例子或代码，讲清过程、结果和对应原理；同一主题尽量沿用一个例子。类比有帮助才用，并说明会误导的边界。
6. 核对准确性。确认有误的内容采用正确表述；无法核实且影响结论的疑点，以及必要的适用条件和局限，就近说明。

## 技术细节的取舍

- 概念型内容讲清问题、机制、原因和适用条件；实现型内容保留输入、准备、组装、处理、输出，以及关键错误或结束条件。
- 保留承担解释作用的真实 API、字段、数据结构、工具和模型名称。不要为了简短，用自造函数隐藏关键处理过程，也不要扩展成与原文无关的大型实现。
- 区分可运行代码与伪代码；伪代码标明身份，配精简大白话注释。新增教学例子注明是说明示例，不冒充原文或实测证据。
- 保留数值的单位、比较基准和实验条件。特定模型、版本或平台的行为不得写成通用定律。
- 必要补充只用于填补理解缺口或保证核心结论准确，不因相关而扩展。补充事实须有依据，推论须说明前提，不能冒充原文结论。

## 实验与证据

按来源实际提供的证据措辞，不强制为每篇笔记增加实验章节：

- **实验设计**：只给步骤、变量、指标或预期时，明确写“原文仅提供实验设计，未提供实测结果”。不能写成已验证，也不能仅省略结果，让读者误以为测试已经做过。
- **真实实验结果**：保留来源、条件、观察值和局限。原文报告的结果写成“原文报告”，不声称自己已复测。
- **模拟示例或预期**：明确标注模拟、示意、预期或待验证，不能用确定语气当作实测结论。
- 区分模型声称执行、工具实际执行和外部状态实际改变；只有相应证据才能支持相应结论。

## 输出规范

默认在对话中输出可独立复习的 Markdown 笔记，仅在用户明确要求时创建文件。正文直接讲知识，不展示改写或审校过程。讨论、解释和审核按问题回答，不强制生成笔记或元数据。

用简短小标题方便回看；过程用步骤讲，适合比较时才用表格。

正式笔记直接从以下 YAML 元数据代码块开始，前面不加示例提问、任务复述或开场说明；块内不加首尾 `---`。按内容填写，不照抄占位值。已有元数据按内容更新。

```yaml
name: 准确概括核心知识的标题
description: 一句话说明笔记解决什么问题
type: tech-concept
updated: YYYY-MM-DD
tags: [topic, content-type, key-entity]
source: "真实 URL、已知 wikilink 或资料说明"
```

- `name` 直接描述知识；`description` 不超过 80 字。
- `type` 单选：`methodology`、`resource-list`、`insight`、`case-study`、`research`、`tech-concept`、`hybrid`。
- `updated` 用整理或修订日期，格式为 `YYYY-MM-DD`；有价值的原文日期另行注明。
- `tags` 用 3–7 个有检索价值的英文小写标签，覆盖主题域、内容类型和关键实体。
- `source` 使用真实来源；wikilink 必须加引号，如 `"[[sources/资料名]]"`。只有粘贴正文时，可写 `"用户提供原文：资料名或章节名"`，不编造链接或文件路径。

## 交付前自检

- 正文开头是否讲清为什么需要？零基础是否能顺着短句读懂？
- 必要前提、核心因果、关键条件、数据流和高价值技术细节是否完整？
- 难点是否有必要的小例子，过程和结果是否自洽？有没有重复解释、术语堆叠或强行类比？
- 实验设计、来源报告、模拟示例、推论是否分清？是否虚构结果或泛化结论？
- 脱离原文和聊天记录后，笔记是否仍能独立复习？
- 元数据是否完整合规，Markdown 排版是否正确？

## 取舍示例

- Agent 循环：保留 `response.choices[0].message` 及其前后的请求、取值、追加历史流程；不要只剩“调用模型并保存结果”。
- KV Cache：保留它与 Prompt Cache 的层级区别、前缀改变后的失效条件；不要只说“缓存能省钱”。
- 提示注入实验：若原文只有攻防步骤，写清只有设计、没有实测结果；不编造攻击成功率。

只在用户要求时应用于具体材料；单纯创建或修改本技能时，不顺带生成章节笔记。
