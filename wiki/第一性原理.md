# 核心认知

第一性原理：
> 不接受现成答案，而是回到底层事实重新推导。

人话：不要问“别人怎么做”，先问“为什么必须这样做”。

目标：
- 找到真正问题，而不是表面现象；
- 区分事实、假设和推论；
- 从底层约束重新设计方案。

---

# 核心原则：事实、假设、推论分离

最大风险：
> 把自己的推理结果，当成客观事实。

必须区分：

| 类型 | 含义 |
|---|---|
| 事实 | 可验证的信息，有数据或证据支持 |
| 假设 | 对事实的解释，需要继续验证 |
| 推论 | 基于事实产生的结论 |

规则：
- 事实说明依据；
- 假设明确标记；
- 推论说明推导过程；
- 方案说明解决的底层约束。

避免：
> 信息堆积 ≠ 深度分析。

# 第一性原理流程

## 1. 定义真正问题

不要直接解决表象。

错误：
```
销量下降
↓
增加营销
```

正确：
```
销量下降
↓
为什么？
↓
需求变化？
产品价值下降？
竞争变化？
```

---

## 2. 找到底层事实

持续追问：
> 为什么？

直到无法继续拆解。如果还能问“为什么”，说明还没有找到底层约束。

---

## 3. 质疑隐藏假设

检查：

| 表面观点 | 隐藏假设 |
|---|---|
| 行业都是这样做 | 必须这样做 |
| 成本无法降低 | 当前生产方式不可改变 |
| 功能越多越好 | 用户需要更多功能 |

---

## 4. 重新构建方案

不要复制已有方案。流程：
```
事实
↓
重新组合
↓
方案
↓
验证
```

# AI 分析输出规范

## 1. 推理顺序

必须遵循：
```
事实
↓
假设
↓
推论
↓
方案
↓
验证
```

禁止：
```
观点
↓
寻找支持观点的信息
```

---

## 2. 结论必须带条件

不要：
> 这个方向一定成功。

应该：
> 在满足哪些条件时，这个方向可能成立。

示例：

事实：Rust 提供内存安全保障。

假设：未来项目更重视安全和维护成本。

推论：Rust 可能扩大系统编程市场份额。

验证：观察采用率、生态和迁移成本。

---

## 3. 指出关键变量

好的分析必须说明：
> 什么变化会让结论失效。

例如：

判断：
> Agent Runtime 可能比 Agent Framework 更有机会。

关键变量：
- 企业是否长期运行 Agent；
- Runtime 是否形成标准；
- 用户是否接受新工作流。

---

## 4. 标记确定性

结论分级：
- 事实：已确认；
- 高概率推论：有多个事实支持；
- 可能方向：需要实验验证；
- 未知：缺少关键数据。

---

## 5. 优先寻找最小验证

目标不是证明自己正确，而是快速发现错误。

优先：
```
低成本实验
↓
验证关键假设
↓
修正判断
```

# 实战模板

分析复杂问题：
```
1. 真正的问题是什么？
2. 哪些是事实？
   哪些是假设？
3. 最底层约束是什么？
4. 哪些默认规则可以推翻？
5. 如果重新设计，会怎么做？
6. 哪些变量决定结果？
7. 如何最低成本验证？
```

---

# 适用边界

适合：
- 创新设计；
- 商业决策；
- 技术路线选择；
- 复杂问题分析。

不适合：
- 紧急决策；
- 缺少基础事实的问题；
- 已验证成熟流程。

# 高价值案例

## Tesla

传统：
```
电池贵
↓
电动车无法普及
```

第一性原理：
```
电池由什么组成？
↓
材料成本是多少？
↓
为什么售价高？
```

结论：限制可能来自生产方式和供应链，而不是材料本身。

---

# 总结

第一性原理不是寻找更好的旧答案，而是重新判断：
> 这个限制是真实存在，还是过去形成的假设？

完整流程：
```
提出问题
↓
识别隐藏前提
↓
收集底层事实
↓
区分事实/假设/推论
↓
找到关键约束
↓
重新设计方案
↓
验证结果
↓
修正判断
```
