# 卡帕西推荐的拼接编程法

思想来源是库内 Karpathy「拼贴工作流」关于在代码位置写片段或注释的整理；下文的逐行数据说明、示例和验收步骤是个人实践归纳。[^1]

## 核心思想

**保留传统手写编程的流程，一个函数、一行代码地推进；写的内容改为半代码半注释，或纯注释，由 Agent 生成或修改对应代码。**

我可以不记住具体函数或 API 的名称和调用写法，但必须掌握它处理前后的数据类型、结构和变化。**上一步得到什么数据，决定下一行可以怎么写。**

我还必须掌握决定结果正确的关键规则。**类型相同，不代表结果正确；最后执行的几行，也未必是决定结果正确的几行。** 具体代码可以交给 Agent 编写，正确结果和关键规则由我明确并验收。

## 详细说明

### 写法

我依然深入到代码层，决定变量、判断、循环、函数调用和每一步逻辑。代码和注释可以混用，也可以完全用注释表达。

注释直接写在对应位置，说明当前这一步的数据变化和关键动作：

| 要写清的内容 | 具体说明 |
| --- | --- |
| 输入 | 使用哪个变量，是什么类型，包含哪些相关数据。 |
| 处理与规则 | 对数据做什么操作；哪些条件、计算或执行顺序决定结果正确。 |
| 输出与状态 | 得到什么类型的数据，正确的值或应满足的条件是什么；原变量、数组、对象或其他状态有没有变化。 |
| 外部动作（涉及时） | 哪一步真正把内容写到文件、发到网络或送到终端；分清创建指令、写入缓冲区、发送内容和实际执行。 |
| 触发与次数（涉及时） | 动作由谁触发，何时执行，执行几次；需要等待什么完成才能继续。 |

只补当前步骤需要的信息，不必每一行重复全部项目。如果“调用某函数”遮住了决定结果的关键规则或动作，就补清它实际做了什么。

存在空值、错误或异步返回时，也要明确相关类型、分支和后续处理；说明失败后哪些变化已经发生，以及是否允许重试。

### 示例：把数据变化写进注释

```typescript
function parseCommand(userInput: string) {
    // 规则：第一个非空白片段作为命令，其余片段按原顺序作为参数。
    // 全空白输入返回 null；本函数只解析，不执行命令。

    // userInput: string，例如 "  run task  "。
    // 去掉首尾空白，得到 text: string，值为 "run task"。
    // userInput 的值不变。
    const text = userInput.trim();

    // 按连续空白拆分 text，得到 parts: string[]。
    // 此例 parts 为 ["run", "task"]；text 的值不变。

    // 从 parts 中移除并取出第一项，得到 command: string | undefined。
    // 此例 command 为 "run"，parts 同时变为 ["task"]。

    // 如果 command 为 undefined 或空字符串，返回 null，结束函数。
    // 否则，后续分支中的 command 为非空 string。

    // 返回 { command, args: parts }。
    // 成功结果类型为 { command: string; args: string[] }。
    // 整个函数的返回类型为 { command: string; args: string[] } | null。
}
```

这里既要知道取出的命令是什么类型，也要知道数组已移除了第一项。下一步才能把剩余数组用作参数。

本例的验收应检查具体结果，不能只检查返回类型：

| 输入 | 预期结果 |
| --- | --- |
| `"  run task  "` | `{ command: "run", args: ["task"] }` |
| `"run"` | `{ command: "run", args: [] }` |
| `""` 或 `"   "` | `null` |

使用纯注释时，函数声明和现有代码也可以改成对应说明；每一步的数据信息仍要保留。

### 流程

1. **逐行写**：先明确正确结果和关键规则，再明确当前输入，用代码或注释写清处理动作、结果类型和状态变化；涉及外部动作时，补清触发条件、执行时机和次数。
2. **指定位置**：写好一个模块，或修改一行代码、注释后，告诉 Agent 具体位置，要求生成或修改对应代码。
3. **检查结果**：阅读生成的代码，核对关键规则、实际结果、数据类型、状态变化和外部动作是否符合注释。测试边界和预期结果由我定义，Agent 负责编写测试、运行测试并修复实现，直到全部通过。测试应按需验证结果、状态和外部变化；不得为通过测试而擅自放宽预期结果。
4. **继续推进**：根据当前得到的数据及其类型，结合目标和关键规则，决定下一行、下一个函数或模块怎么写。

不需要另外编写提示词。代码和注释就是我给 Agent 的实现说明，沟通时只需指出具体位置和要做的操作。
