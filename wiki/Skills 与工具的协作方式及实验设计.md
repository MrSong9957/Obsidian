### 1. Skill 提供方法，工具执行动作[^1]

以“把论文做成 PPT”为例：

| 部件      | 负责什么                   | 示例                      |
| ------- | ---------------------- | ----------------------- |
| Skill   | 告诉 Agent 按什么流程做、怎样检查结果 | 先提取论文内容，再组织幻灯片、检查版面。    |
| 工具      | 执行读取、写入、运行程序等动作        | 读取论文，保存文件，运行 Python 脚本。 |
| 配套脚本与模板 | 提供现成代码和文件，供流程使用        | 生成缩略图的脚本、PPT 模板。        |

**通用执行器**就是能运行多种程序的工具，例如运行 Python 或命令行程序的工具。Agent 读完 Skill 后，可以通过它执行配套脚本。

这样，不必把每段专用代码都注册成一个独立工具，也不必提前把所有工具说明和操作流程发给模型。系统可以保留少量通用工具，再按任务加载 Skill。核心工具的数量取决于系统设计，并没有固定要求。

如果已有的工具定义和消息保持不变，新读取的 Skill 内容追加在后面，就有利于复用前缀缓存。但新增内容仍要处理，也仍然占用上下文。

### 2. 实验设计：从论文生成 PPT

**以下两项都是实验方案，原文没有报告实际执行结果。**

这个实验要检查两件事：Agent 是否按需加载了专业说明，以及生成的 PPT 是否符合要求。

**准备材料**

* 一篇学术论文 PDF，至少包含 3 张可用的图表。
* Anthropic 官方 PPTX Skill。
* Claude Code，或其他支持 Skill 目录、按需加载，并能运行配套脚本的 Agent。

**执行步骤**

1. Agent 先从目录中看到 PPTX Skill 的名称和描述。
2. 判断任务需要它，再加载完整 `SKILL.md`。
3. 根据所选方法，读取必要的详细文档。例如采用 HTML 制作方案时，读取相应指南。
4. 提取论文内容和图表，利用模板制作 **10–15 页**的演示文稿。
5. 运行预览脚本，检查文字、图表和排版，再修正问题。

原文中的 `html2pptx.md`、`scripts/thumbnail.py` 是示例文件名，实际应以所用 Skill 的版本和引用路径为准。

**怎样验收**

* **加载过程**：从调用记录中确认，先看到目录，再读取正文和必要的子文档。
* **内容完整**：包含标题页、问题背景、方法概述、关键结果和结论。
* **图文一致**：至少包含 3 张从论文提取的图表，文字说明与图表含义一致。
* **文件可用**：页数符合要求，格式正确，能在 PowerPoint 或兼容软件中正常打开。

### 3. 实验设计：从个人范文提炼写作 Skill

这里的“去 AI 味”，具体指**让新文章更贴近作者自己的用词、句式、段落和语气习惯**。

**执行步骤**

1. 准备 **3–5 篇**自己满意的原创文章。
2. 让 Agent 提炼表达偏好，生成简短的 `SKILL.md`。
3. 选一个新题目，让 Agent 加载 Skill 后起草文章。
4. 作者逐句修改，保留修改前后的版本。
5. 比较差异，把反复出现、适用于其他文章的规律写回 Skill，再用新任务检查。

例如，作者多次把一段中的多个重点拆开，可以提炼为“一段集中讲一个重点”。但某篇文章偶尔使用短句，不足以得出“所有句子都必须很短”。

**怎样验收**

* Skill 能被运行时发现并加载，触发条件明确。
* 包含 **3–5 条**核心原则，每条都有示例，并说明适用范围和例外。
* 能从修改前后的差异中，看出规则依据。
* 换一个题目后，仍能检查这些规则是否适用。

一次觉得“更像我写的”，只能说明这篇文章的体验。要把某项偏好写成长期规则，需要在不同任务中继续验证。
