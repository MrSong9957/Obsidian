# 代码质量约束（自动发现机制）

**核心原则：用户不需要知道"什么是好的"，AI 负责发现最佳实践。**

## 实现前必须做的事

- **强制研究**：实现新功能前，AI 必须先研究成熟开源项目（至少 1 个），说明采用了什么模式
- **说明来源**：设计决策必须标注"参考自 [项目名] 的 [模块]"
- **列出备选**：写代码前，列出 2-3 个实现方案及取舍理由

## 类型安全要求

- **禁止 `any` 类型**：必须使用具体类型
- **参数验证用 Zod**：定义 schema 一次，自动推导类型 + 运行时验证，避免手写 JSON Schema
- **类型从定义推导**：不要重复定义（改一处参数要改两处代码是错误的）

## 模块设计要求

- **高内聚**：相关逻辑放在一起，不要散落在多个文件
- **低耦合**：模块间通过明确接口通信，不依赖内部实现
- **单一职责**：一个函数/模块只做一件事

## 代码审查要求

- 新功能完成后，用 `code-reviewer` agent 审查
- 审查重点：安全漏洞、类型安全、是否遵循上述原则
