**传统稀疏检索先找相同的词，再按这些词的重要性给文档排序。** 找到关键词，只说明文档可能相关；还需要判断哪些匹配更有区分力。[^1]

**稀疏向量的每个位置对应一个固定词，数值记录次数或权重。** 例如，假设词表依次是“模型、蒸馏、检索、苹果”，文本“模型 模型 蒸馏”的计数向量就是：

\[
[2,\ 1,\ 0,\ 0]
\]

实际词表很大，一篇文档只用到其中少量词，所以向量大部分位置为零，这就是“稀疏”。

这种只记录词及其数量、不记录词序的表示叫**词袋模型（BoW）**。“猫追狗”和“狗追猫”虽然意思不同，但分词后的词及次数相同，因此词袋表示相同。

**TF-IDF 给词加权：在当前文档里出现得多，在整个文档集合里出现得少，权重就高。**

- **TF：词频。** 一个词在当前文档中出现几次。
- **DF：文档频率。** 有多少篇文档包含这个词。同一篇出现十次，DF 仍只增加一。
- **IDF：逆文档频率。** 根据 DF 衡量词的稀有程度。

原文采用的朴素公式是：

\[
\mathrm{TFIDF}(t,D)
=
\mathrm{TF}(t,D)\times
\underbrace{\ln\frac{N}{\mathrm{DF}(t)}}_{\mathrm{IDF}(t)}
\]

其中，\(t\) 是词，\(D\) 是文档，\(N\) 是文档总数，\(\ln\) 是自然对数。

例如，100 篇文章中，60 篇包含“模型”，只有 3 篇包含“蒸馏”。“蒸馏”的 IDF 更高，因为它更能缩小查找范围。

这个**原始词频、未做长度校正的版本**有两个局限：出现十次的词频权重是五次的两倍；长文档也容易因为词多而得分更高。TF-IDF 还有对数词频等变体，不能把这两个局限推广到所有实现。[Stanford NLP Group](https://nlp.stanford.edu/IR-book/html/htmledition/sublinear-tf-scaling-1.html?utm_source=chatgpt.com)

**BM25 保留稀有词加权，同时限制重复次数的收益，并调整文档长度的影响。**

它对查询中的每个词计算贡献，再把贡献相加：

\[
\mathrm{Score}(Q,D)=
\sum_{t\in Q}
\mathrm{IDF}_{BM25}(t)
\frac{\mathrm{TF}(t,D)(k_1+1)}
{\mathrm{TF}(t,D)+k_1\left(1-b+b\frac{|D|}{\mathrm{avgdl}}\right)}
\]

\(Q\) 是查询；\(|D|\) 是文档分词后的长度；\(\mathrm{avgdl}\) 是文档集合的平均长度。两个参数控制调整强度：

| 参数 | 控制什么 | 直观含义 |
|---|---|---|
| \(k_1\) | 词频饱和 | 较小，重复几次就接近上限；较大，重复出现还能继续增加较多贡献 |
| \(b\) | 文档长度调整 | `0` 忽略长度；`1` 完整使用长度比例；中间值只做部分调整 |

“饱和”就是**次数继续增加，得分增加得越来越少**。公式计算示例：令 \(k_1=1.5\)，文档长度等于平均长度，词频从 5 增加到 10，公式中的词频权重只从约 **1.92 增加到 2.17**。

对 IDF 为正的词，当其他条件相同、\(k_1>0\) 且 \(b>0\) 时，相同词频在更长文档中的贡献更低。这两项调整用于减轻重复词和文档长度对排序的影响。[nlp.stanford.edu](https://nlp.stanford.edu/IR-book/html/htmledition/okapi-bm25-a-non-binary-model-1.html?utm_source=chatgpt.com)

**BM25 的 IDF 有不同写法，复现分数时必须保持一致。** 原文日志采用：

\[
\mathrm{IDF}_{BM25}(t)
=
\ln\frac{N-\mathrm{DF}(t)+0.5}{\mathrm{DF}(t)+0.5}
\]

加 `0.5` 是平滑处理，让 DF 为 `0` 或 `N` 时仍能计算。但当词出现在超过半数文档中时，这个 IDF 会变成负数。有些实现将负值截为零。[nlp.stanford.edu](https://nlp.stanford.edu/IR-book/html/htmledition/okapi-bm25-a-non-binary-model-1.html?utm_source=chatgpt.com)

Lucene 则采用另一种写法：

\[
\mathrm{IDF}(t)
=
\ln\left(1+
\frac{N-\mathrm{DF}(t)+0.5}{\mathrm{DF}(t)+0.5}\right)
\]

它在对数内部多加了 `1`，避免上述负值。使用这种版本时，不能直接期待得到原文日志里的相同分数。[lucene.apache.org](https://lucene.apache.org/core/9_12_1/core/org/apache/lucene/search/similarities/BM25Similarity.html?utm_source=chatgpt.com)

**倒排索引负责快速找到需要打分的文档。** 它保存“词对应哪些文档”，而不是每次打开所有文档找词。

检索过程是：

1. **处理文档。** 分词，按任务需要去除停用词，即“的、了”等通常缺少区分力的词。
2. **建立索引和统计。** 保存各词对应的文档列表及词频，同时记录文档长度、DF、文档总数和平均长度。
3. **处理查询。** 使用一致的分词规则，查倒排索引，给命中的文档逐项累加 BM25 贡献，按总分排序。

原文查询“模型蒸馏”，分词为 `["模型", "蒸馏"]`。示例条件为：

- 文档总数 `N=10`，平均长度 `avgdl=250 词`。
- 参数 `k₁=1.5`、`b=0.75`。
- “模型”出现在 3 篇文档中，IDF 约为 `0.7621`。
- “蒸馏”出现在 2 篇文档中，IDF 约为 `1.2238`。
- IDF 使用原文未在对数内部加 `1` 的版本。

倒排索引找到“模型”所在的 `doc_1、doc_3、doc_7`，以及“蒸馏”所在的 `doc_1、doc_5`，然后得到：

| 文档 | 长度（词） | “模型”：词频 → 贡献 | “蒸馏”：词频 → 贡献 | 总分 |
|---|---:|---:|---:|---:|
| doc_1 | 200 | 5 → 1.52 | 3 → 2.15 | **3.67** |
| doc_7 | 150 | 8 → 1.68 | 0 → 0 | **1.68** |
| doc_5 | 250 | 0 → 0 | 1 → 1.22 | **1.22** |
| doc_3 | 500 | 2 → 0.82 | 0 → 0 | **0.82** |

在 `doc_1` 中，“蒸馏”出现次数更少，但由于更稀有，贡献反而更大。该文档同时命中两个查询词，因此两项贡献相加后排第一。**精确匹配指词项相同，文档命中部分查询词也可以得分。**

原文提供了示例运行日志。按给定公式和统计量复算，上表数值四舍五入后与日志一致；这只核对了计算，未独立运行项目或验证原始语料统计。这个例子展示了评分机制，没有提供检索质量的对比评测。

这种方法适合强调人名、型号、报错码等确切词项的查询，前提是分词和预处理保留了这些词项。基础 BM25 未加入同义词扩展时，查询“医生”不会仅凭同义关系匹配只含“大夫”的文档。

这一局限属于传统词项匹配。SPLADE 等现代稀疏模型可以学习相关词扩展，给原文未出现的词分配非零权重，因此“稀疏”也可以结合语义信息。[NAVER LABS Europe](https://europe.naverlabs.com/blog/splade-a-sparse-bi-encoder-bert-based-model-achieves-effective-and-efficient-first-stage-ranking/?utm_source=chatgpt.com)
