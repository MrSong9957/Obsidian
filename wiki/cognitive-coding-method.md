# 认知学习编程法

## 核心原则

> **vibe coding = 你描述结果，AI 完成一切。**
> **认知学习 coding = 你描述过程，AI 执行步骤。**

区别在于：你是**导演**还是**观众**。导演不需要亲自演戏，但必须知道每场戏要什么效果、为什么这样演、哪里不对怎么调。

**铁律：AI 代替打字可以，但不能代替思考。禁止跳过认知过程。**

---

## 四层认知分离法

### 第 1 层：你做设计，AI 做打字

**你的工作：**
1. 把需求拆成 5-10 分钟的小任务
2. 每个任务写出伪代码/逻辑草图
3. 明确输入、输出、边界条件

**AI 的工作：** 把你的伪代码翻译成真实代码

**关键动作：** 用自然语言描述逻辑细节，而不是描述结果。

```
❌ "写个排序"
✅ "写一个函数，输入是整数列表，用快排，选第一个元素为 pivot，
   小于 pivot 的放左边，等于的放中间，大于的放右边，
   递归直到长度 <= 1。"
```

这逼你先理解算法，而不是让 AI 选算法。

---

### 第 2 层：你做验证，AI 做实现

**你的工作：**
1. 写测试用例（预期行为）
2. 审查生成的代码，逐行理解
3. 发现问题后指出具体错误

**AI 的工作：** 实现代码、修复你说出的问题

**关键动作：** 先写测试，再让 AI 写实现。测试就是你对"正确行为"的理解。如果测试写不对，说明你还没想清楚。

```
你：写一个测试，验证 fibonacci(0)==0, fibonacci(1)==1, fibonacci(7)==13
AI：[写测试代码]
你：现在实现 fibonacci 函数让它通过
AI：[写实现]
你：这里为什么要用递归？改成迭代会不会更好？解释一下空间复杂度的差异
```

---

### 第 3 层：你做诊断，AI 做修复

这是学习最深的一层——**调试**。调试中的因果推理是手写编程最宝贵的认知收益。

**你的工作：**
1. 观察错误现象
2. 形成假设（哪里可能出错）
3. 设计验证假设的实验

**AI 的工作：** 执行你的诊断指令，报告结果

**对话模式：**
```
你：运行这个函数，输入 [3, 1, 2]，结果不对
AI：输出是 [1, 2, 3]，期望是 [3, 2, 1]
你：我觉得是 pivot 选的位置有问题，打印一下每一轮的 pivot 值和分区结果
AI：[添加日志，运行]
你：看到了，第二轮 pivot 选了 1 导致分区不对，应该选中间元素
AI：[修改代码]
你：再跑一次 [5, 3, 7, 1] 验证
```

**你始终在做因果推理**，AI 只是你的手和眼。

---

### 第 4 层：你做决策，AI 做评估

**你的工作：** 提出架构/方案选择，给出理由

**AI 的工作：** 指出你方案的优劣，提供替代方案

```
你：我想用字典存缓存，用 LRU 策略淘汰，自己实现双向链表
AI：可以，但 Python 有 OrderedDict 内置 LRU。自己实现的好处是学习链表操作，
    但生产代码建议用标准库。你想要学习还是生产效率？
你：学习，自己实现
AI：那从 Node 类开始？每个节点需要 key, value, prev, next 四个属性
你：为什么需要 key？value 不够吗？
AI：因为 LRU 删除最久未用的节点时，需要同时从字典里删除对应的条目，
    没有 key 就无法反向查找字典键。
你：原来如此，那先写 Node 类，再写双向链表的 add/remove/move_to_head 操作
```

## 每次会话的节奏模板

```
1. 【拆】  把任务拆成 5-10 分钟的小步骤（你做）
2. 【写】  用自然语言描述每步的逻辑细节（你做）
3. 【生】  让 AI 根据你的描述生成代码（AI 做）
4. 【读】  逐行读生成的代码，不懂就问"这行为什么这样写"（你做）
5. 【测】  写测试，运行，观察结果（你做 + AI 做）
6. 【错】  如果不对，先自己猜原因，再让 AI 验证你的猜测（你做）
7. 【改】  告诉 AI 怎么改，而不是让 AI 自己想办法（你做决策）
```

---

## 自检清单

每次编程会话结束前，问自己：

- [ ] 我能解释每一行代码的作用吗？
- [ ] 我知道为什么用这个算法/数据结构，而不是其他选择？
- [ ] 遇到 bug 时，我是先猜原因还是直接让 AI 修？
- [ ] 测试是我写的还是 AI 写的？我理解每个测试在验证什么吗？
- [ ] 如果没有 AI，我能手写出这个程序的核心逻辑吗？

如果任何一个答案是"否"，说明跳过了认知过程，需要补课。

---

## 与其他方法的关系

- **TDD**：认知学习法天然兼容 TDD——写测试本身就是第 2 层"你做验证"
- **调试铁律**：第 3 层"你做诊断"对应调试铁律"没有根因调查，不实施修复"
- **极简主义**：拆小任务自然导向最小实现
- **[[dev-practice.md|开发实践]]**：本方法是开发实践的核心编程策略
