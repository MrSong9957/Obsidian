## Harness Engineering 核心原则

- **人类驾驶，Agent 执行**（Humans steer. Agents execute.）— 设计环境、指定意图、构建反馈循环
- **给 Agent 一张地图，而不是 1000 页的说明书** — AGENTS.md ~100 行作为目录，深度知识放 docs/ 目录
- **约束比指导更重要** — 边界严格（依赖方向、架构层级），实现自由（Agent 自选方案）
- **上下文是稀缺资源** — 巨大指令文件挤占任务空间，当一切都是"重要"的就没有什么是重要的
- **可观测性是 Agent 的眼睛** — 让日志（LogQL）、指标（PromQL）、UI（Chrome DevTools Protocol）对 Agent 可见
- **技术债务像垃圾回收** — 持续小额偿还，人类品味捕获一次然后持续强制执行
- 禁止：不设计环境就让 Agent 自由工作
  原因：没有日志/指标/UI 验证能力，Agent 无法知道自己做对没有
  替代：先暴露结构化查询能力再让 Agent 执行任务
- 禁止：AGENTS.md 写成百科全书
  原因：挤占上下文，难以验证，会腐烂
  替代：~100 行目录 + docs/ 子目录 + CI 验证文档新鲜度

> 详细内容见 [[sources/agent-arch-p2.md]]

## 反馈循环关键教训

- **反馈信号金字塔**：编译/lint（最快）→ 单元测试 → 集成测试 → E2E 测试 → 生产数据（最真实但最慢）
- 层次越往上信号越有价值，但 Agent 越难自己获取 — 人需要提前搭建测试代码和 UI 驱动能力
- **人的角色是定义期望，不是监督 Agent** — 把期望变成可验证的断言（测试的本质）
- 三种反馈机制：Agent 自我审查（自动化）、Agent 间审查（并行任务）、后台清理任务（定期扫描）
- 纠正成本低，等待成本高 — PR 短生命周期，测试失败就重跑

## 人话编程核心规则

- **缩进即结构** — 1 个 TAB = 一层代码块，缩进层级与目标语言一一对应
- **冒号开块** — 行尾冒号表示接下来是缩进块（函数体、条件体、循环体）
- **自然语言表达** — 结构框架内用中文自由描述逻辑，AI 精确翻译
- **原始名标注** — 反向翻译时函数名/变量名后用括号标注原始名称，如 `获取天气（get_weather）：`
- **字面量直写** — 数字、字符串、URL、正则直接写原文不加引号
- **双向无损** — 代码 → 人话 → 代码，结构信息不丢失；注释用 `注：` 双向保留
- 禁止：用伪代码代替人话编程
  原因：伪代码不够严格，无法精确双向翻译
  替代：严格遵循 7 条基本规则，保持缩进/冒号/原始名标注

> 详细内容见 [[sources/agent-arch-p2.md]]

## 人话编程适用范围与生产级要求

- **适用**：通用编程语言（Python/JS/Go/Rust/Java 等），覆盖函数/类/条件/循环/异常/并发
- **不适用**：DSL（SQL/HTML/CSS/正则/Shell），因为缺乏过程式结构
- 教程级只描述核心逻辑，**生产级必须额外覆盖**：前置校验、超时、重试策略、错误分类、边界值、资源释放
- 意图指定分三个层次：业务意图（Level 3）→ 功能意图（Level 2）→ 实现意图（Level 1），工程师应在 Level 2-3 工作
