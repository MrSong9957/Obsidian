# 核心思路

Agent 安全不能只靠一句“不要做危险操作”。

真正可靠的做法是：

> **把防线一层层放到模型之外，即使模型判断错了，系统也不能轻易出事。**

三层护栏：

```text
上下文层：模型能看到什么
    ↓
执行层：模型能做什么
    ↓
数据层：世界最终允许被改成什么
```

越往下，越不依赖 LLM 自己判断，因此越可靠。

# 三层护栏

| 层级   | 管什么     | 典型措施                  |
| ---- | ------- | --------------------- |
| 上下文层 | 模型能看到什么 | 提示注入检测、内容审核、长度限制、来源标注 |
| 执行层  | 模型能做什么  | 工具权限、风险评级、沙盒、人工审批     |
| 数据层  | 最终允许改什么 | 数据库权限、约束、行级安全、受控存储过程  |

## 1. 上下文层：先过滤模型看到的信息

常见机制：

* **相关性分类**：拒绝与任务无关的请求。
* **Jailbreak 检测**：防用户直接诱导模型绕过限制。
* **Prompt Injection 检测**：防网页、文档等外部数据偷偷夹带指令。
* **内容审核**：检测有害内容。
* **规则过滤**：黑名单、长度限制、正则、SQL 注入检查。
* **来源标注**：区分“系统指令”和“外部数据”。

一个重要区别：

```text
Jailbreak
= 用户直接骗模型

Prompt Injection
= 外部内容间接骗模型
```

### Constitutional Classifiers

Anthropic 的代表性方案，核心有三点：

1. **规则驱动**：用自然语言写成的规则（明确规定哪些内容允许、哪些禁止）生成合成训练数据，训练输入输出分类器；
2. **上下文联合判断**：把**用户输入 + 模型回答**一起判断；
3. **两级筛查**：先用一个极轻量的探针（直接读取模型内部激活，几乎零成本）检查所有对话，可疑内容再交给更强分类器。

这样可以降低成本，同时减少误拒绝。

但上下文层有天然弱点：

> **已经被注入的 Agent，很难可靠判断“自己已经被注入”。**

所以它只能降低风险，不能作为最后一道防线。

# 2. 执行层：模型决定了，也不代表能执行

核心原则：

> **LLM 提出动作，系统再决定这个动作是否真的允许发生。**

例如给工具分级：

```text
低风险：读文件
中风险：修改代码
高风险：付款、删数据、改权限
```

高风险动作可以要求：

* 独立审查；
* 最小权限凭证；
* 沙盒执行；
* 人工确认。

关键点是：

> **审查机制不能和 Agent 共用同一个被污染的上下文。**

否则 Agent 被注入后，连“审查自己”也会一起失效。

回复用户本身也属于一次动作，因此还需要：

* PII 过滤：防泄露身份证号、手机号等个人信息；
* 输出验证：检查最终回复是否符合要求。

# 3. 数据层：最后一道硬防线

这一层解决：

> **即使上面全错了，数据系统还能不能拒绝非法操作？**

例如数据库直接规定：

```text
普通用户只能修改自己的订单
```

那么即使 Agent：

* 被提示注入；
* 生成了错误代码；
* 忘记检查权限；

数据库仍然拒绝修改别人的数据。

常见机制：

* Row-Level Security（行级安全）；
* 数据库约束；
* 校验器；
* 受控 View；
* Stored Procedure；
* 可信运行时绑定的访问身份。

这是最重要的设计思想：

> **真正关键的权限，不要只写在 Prompt 或 Agent 代码里，要下沉到底层系统强制执行。**

# 护栏也会犯另一种错：误拒绝

护栏不是越严格越好。

可能出现：

```text
危险请求 → 正确拒绝
合法安全测试 → 也被拒绝
```

因此评估必须同时测试：

```text
应该拒绝的 → 能否拦住
应该允许的 → 能否正常完成
```

否则系统虽然“安全”，但可能已经不好用了。

# Human in the Loop

人工干预不是失败，而是 Agent 的正常安全机制。

主要两类触发条件：

### 1. Agent 连续失败

例如：

```text
重试 5 次仍失败
→ 停止
→ 交给人工
```

避免 Agent 无限循环。

### 2. 高风险操作

例如：

* 大额付款；
* 大额退款；
* 删除关键数据；
* 修改权限。

这类动作即使 Agent 判断“应该执行”，也可以要求人类最终批准。

# 最值得记住的模型

```text
Prompt 告诉 Agent：应该怎么做
        ↓
执行层限制 Agent：最多能做什么
        ↓
数据层保证：最终绝对不能越过什么
```

核心原则：

> **越重要的安全规则，越不能只依赖模型自己记住和遵守。**

真正可靠的 Agent 安全，不是让模型“更听话”，而是让模型即使犯错，也没有能力造成不可接受的后果。
