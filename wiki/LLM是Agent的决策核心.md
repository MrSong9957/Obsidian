## 一句话理解

**LLM 负责决定“下一步做什么”；Harness 负责让这个决定安全、可靠地落地。**

Agent 的行为提升，则有三条路：

> **当前上下文学会 → 外部知识/程序沉淀 → 最终训练进模型参数。**

---

## LLM 在 Agent 里负责什么

收到任务后，模型主要做：

```text
理解用户真正想要什么
↓
拆解任务
↓
决定下一步
↓
判断是否调用工具
↓
选择工具和参数
↓
根据结果继续调整
```

所以 LLM 更接近 Agent 的 **Policy（决策策略）**。

它不是自己执行工具，而是决定：

> **现在应该采取什么行动。**

---

## LLM Agent 为什么不是“瞎试”

传统 RL Agent 往往需要大量探索才能学会策略。

LLM 不一样，因为预训练已经让它学到了大量：

* 世界知识；
* 因果关系；
* 数学规律；
* 问题分解方式；
* 人类解决问题的经验。

所以它行动前可以先内部推演：

```text
先想
↓
预测哪种方案更合理
↓
再行动
```

这也是 LLM Agent 能处理复杂任务的重要基础。

# Model as Agent：模型自己学会怎么调用工具

先进模型经过后训练，尤其强化学习后，可以直接学会：

* 什么时候调用工具；
* 调哪个；
* 参数怎么填；
* 工具返回以后是否继续。

以前这些逻辑可能写在外部流程里：

```text
人工工作流
→ 决定什么时候搜索
→ 决定什么时候执行代码
```

现在越来越变成：

```text
Model
→ 自己决定下一步
```

这就是 **Model as Agent（模型即 Agent）**。

---

## 模型越强，为什么 Harness 反而越重要

因为：

```text
自主权越大
↓
能做的事情越多
↓
犯错后的影响也越大
```

所以 Harness 仍然需要负责：

* Context 管理；
* Tool 接口；
* 权限；
* 验证；
* 纠错；
* 恢复。

可以理解成：

> **Model 决定怎么开车，Harness 提供道路规则、安全带和刹车。**

---

# Harness 会不会最终被模型吃掉？

这里涉及 Rich Sutton 的 **《苦涩的教训》（The Bitter Lesson）**。

它的核心观点是：

> 长期来看，能够随着算力和数据扩展的通用搜索、学习方法，往往会战胜大量人工写进去的领域规则。

这意味着很多今天由 Harness 完成的事情，未来可能逐渐被模型学进去。

事实上已经发生过：

```text
过去：
工具调用 → 外部编排

后来：
模型原生 Tool Calling


过去：
复杂规划 → 外部 Workflow

后来：
模型越来越能自己规划
```

但这不代表现在应该删除 Harness。

更实际的原则是：

> **模型现在做不稳的，Harness 先补；模型以后学会了，再把这一层 Harness 去掉。**

可以记成：

```text
能力前沿不断往外扩
↓
Model 吃掉旧 Harness
↓
Harness 转去保护新的能力边界
```

所以 Harness 不是在对抗模型进步，而是在填补**当前模型能力与生产可靠性之间的差距**。

# Agent 的三种学习方式

“Agent 学习了”其实可能指三种完全不同的事情。

## 1. Context Adaptation：当前任务临场学习

把新的：

* 示例；
* 状态；
* RAG 结果；
* 用户要求；

放进当前 Context。

模型马上改变行为。

例如：

```text
用户：
以后这个任务里的代码都用 Rust。

↓
进入 Context

↓
模型之后都生成 Rust
```

特点：

```text
快
便宜
立即生效
但任务结束后通常不保留
```

可以理解为：

> **临时记住。**

---

## 2. External Artifacts：把经验写到模型外面

如果希望下次任务还能够使用，就把经验沉淀为：

* 知识文档；
* Prompt；
* Skill；
* 程序；
* Harness 规则。

例如发现：

```text
提交代码前必须运行 cargo clippy
```

可以把它写进：

```text
AGENTS.md
Skill
Harness
CI
```

以后其他任务继续使用。

特点：

```text
跨任务保留
可查看
可修改
可审计
```

但 Agent 必须通过 Context 或 Tool 再把这些信息读进来。

可以理解为：

> **写进外部笔记和程序。**

---

## 3. Parameter Update：真正训练进模型

有些能力很难写成规则。

例如：

* 医疗影像理解；
* 写作风格；
* 复杂隐式决策；
* 长链工具调用策略。

这时可以通过：

* SFT；
* 偏好训练；
* RL；

修改模型权重。

特点：

```text
成本高
训练慢
需要回归测试
但能形成更自然、广泛的能力
```

可以理解为：

> **真正学进大脑。**

---

# 三层之间的关系

```text
第一层：Context
临场适应
↓
快，但短暂

第二层：External Artifacts
Prompt / Skill / Knowledge / Harness
↓
可控、持久、可审计

第三层：Model Parameters
SFT / RL
↓
真正能力内化
```

它们不是三选一，而是三个时间尺度：

| 层级                 | 解决什么        | 特点      |
| ------------------ | ----------- | ------- |
| Context            | 这一次怎么适应     | 快、临时    |
| External Artifacts | 怎么把经验留下来    | 持久、可控   |
| Parameters         | 怎么让模型真正掌握能力 | 泛化强、成本高 |

## 最值得记住的判断

遇到“我要让 Agent 学会这个”时，不要马上想到训练模型。

先判断：

```text
只影响当前任务？
→ Context

以后还要重复使用，而且能写成规则？
→ Knowledge / Prompt / Skill / Harness

很难显式描述，希望模型自然掌握？
→ Parameter Update
```

这三层可以压缩成：

> **Context 负责临场适应，Artifact 负责经验沉淀，Parameter 负责能力内化。**
