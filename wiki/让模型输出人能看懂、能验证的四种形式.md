# 换个输出形式，模型的答案才真正可用

**为什么需要**：模型给的长篇文字，人读起来慢、核对起来更慢。Karpathy 的思路是别只优化"问什么"，还要指定"用什么形式回答"——形式对了，理解成本和验证成本都会降下来。四种形式按"越往后越花哨、也越接近亲手验证"排列。

**来源说明**：本文是对 Karpathy 分享内容的二手转述，不是原帖。[^1]原文只给建议和理由，未提供任何对比实验或量化效果，下面的收益都是原文的说法，不是实测数据。

## 1. 受控语言：ASD-STE100 风格

**ASD-STE100 是什么**：一套受控写作规范（Simplified Technical English，简化技术英语），最早为航空维修手册制定。修飞机容不得歧义，所以规矩很硬：句子要短、一句只说一件事、能用简单词不用难词、不写模棱两可的话。

**怎么用**：告诉模型"用 80% 的 ASD-STE100 风格解释这个问题"。

**为什么要 80%**：完整的规范太严，全文照搬输出会僵硬；折中一下，既拿到干净好懂的句子，又不至于把话说死。

**适用边界**：原文说模型对这套规范掌握得不错，输出反而更干净。但这是经验判断，没有对照实验支持。

## 2. 直接画图

- 让模型生成流程图、架构图或概念图。
- 适合画的东西：结构、关系、流程。这些用文字写会是长篇大论，图扫一眼就能看到节点怎么连、数据往哪流、问题可能卡在哪。
- 原理：文字是线性的，图是并排的，人处理空间关系比处理长句快。

## 3. 交互式 HTML 网页

- 让模型把结果直接输出成 HTML 网页文件。当前模型写网页已经拿手，能带交互和动画：点一下、拖一下，内容跟着变。
- 关键收益（原文的核心说法）：把"读结论"变成"亲手验证"——用户可以改参数、看结果变化。
- 与图的区别：图是静态的，看的是"结构长什么样"；网页是可操作的，看的是"条件变了结论会不会变"。

## 4. 定制讲解视频

原文称这是 Karpathy 最看好的形态：为任意主题量身生成一支讲解视频。

- **参照对象**：3Blue1Brown 风格。3Blue1Brown 是数学家 Grant Sanderson 的频道，用精致动态画面讲抽象数学概念，圈内知名。
- **配音**：可以接 ElevenLabs（把文字转成人声、念旁白的在线服务）。
- **没有付费配音服务时**：可以让模型找免费、用本机算力跑的替代方案。

## 整体趋势：人的工作往上挪

- 模型会把跑腿打杂的活揽下更多，人的工作往层级上方移，越来越多落在**监督、判断和理解**上。
- 智能和代码资源越丰富，越能要求模型生成大型、定制化的软件产物——原文说这类产物以前完全做不出来（这是趋势判断，未给例子或数据）。
- 原文的行动建议：多尝试，慢慢摸清该让模型干到哪一步。

## 可回看的一句话

别只问"怎么问"，还要定"怎么答"：短句看得懂，图看得快，网页能动手验，视频能跟着想——形式本身就是提效。
