# 一句话理解

自主 Agent 解决的是：

> **任务下一步无法提前写死时，让模型根据当前环境自己决定接下来做什么。**

工作流是“代码决定路线”，自主 Agent 是“模型边走边决定路线”。

# 自主 Agent 怎么工作

本质就是一个不断循环的 ReAct：

```text
思考：现在缺什么？
  ↓
行动：调用工具
  ↓
观察：拿到工具结果
  ↓
重新判断下一步
  ↓
继续 / 结束
```

例如订机票：

```text
用户：订下周三去上海的机票
↓
搜索航班
↓
发现需要登录
↓
验证身份
↓
继续搜索
↓
发现便宜航班要转机
↓
询问用户是否接受
↓
用户：不要转机
↓
调整搜索条件
↓
继续
```

这些步骤事先并没有完全写死。

这也是自主 Agent 和 Workflow 最核心的区别：

| Workflow | Autonomous Agent |
| -------- | ---------------- |
| 开发者决定下一步 | 模型决定下一步          |
| 路线基本固定   | 路线动态生成           |
| 可预测、容易控制 | 灵活、适合开放任务        |
| 异常依赖预设分支 | 可以根据失败调整策略       |

# 自主不等于无限执行

Agent 必须有明确的**退出条件**。

常见条件：

* 任务已经完成；
* 调用了 `final_answer` 一类最终输出工具；
* 模型不再请求工具；
* 错误次数超过限制；
* 达到最大循环次数；
* 遇到不可恢复错误。

否则就可能出现：

```text
搜索
↓
结果不满意
↓
继续搜索
↓
继续搜索
↓
……
```

最后变成死循环、烧 Token 或做出过多操作。

所以一个最小自主 Agent 可以理解成：

```text
while 没有结束:
    LLM 根据当前上下文决定下一步

    如果要调用工具:
        执行工具
        把结果放回上下文
    否则:
        输出结果
        结束
```

# 什么时候适合自主 Agent

适合**提前不知道要走多少步**的问题。

典型场景：

* Coding Agent 修复真实 GitHub Issue；
* SWE-bench 软件工程任务；
* Computer Use 操作电脑界面；
* Deep Research；
* 多轮搜索、分析、验证任务。

例如修 Bug 时，路线很难提前确定：

```text
读 Issue
→ 搜代码
→ 找可疑模块
→ 跑测试
→ 失败
→ 换假设
→ 改代码
→ 再测试
```

这种任务如果硬写成固定 Workflow，往往会非常复杂。

# 自主性的代价

自主性越强，系统通常越难控制。

主要风险：

1. **成本更高**
   一个任务可能触发很多轮模型和工具调用。

2. **错误会累积**
   前面判断错了，后面的行动可能建立在错误基础上。

3. **可能过度执行**
   Agent 可能继续搜索、修改或调用工具，而实际上任务已经够了。

4. **安全风险更高**
   因为模型拥有更大的行动自由。

因此生产环境通常需要：

```text
自主 Agent
    +
沙盒
    +
权限控制
    +
最大轮数
    +
验证
    +
日志 / 监控
    +
关键节点人工确认
```

# Workflow 和 Agent 不必二选一

实际系统通常是**混合模式**。

一个很好理解的原则：

> **需要可靠性的地方写死，需要灵活性的地方交给 Agent。**

例如：

```text
固定工作流
身份验证
   ↓
权限检查
   ↓
┌──────────────────┐
│ 自主 Agent       │
│ 搜索、分析、决策 │
└──────────────────┘
   ↓
人工审批
   ↓
固定支付流程
```

像付款、删除数据、权限修改这类高风险操作，通常不应该完全由 Agent 自由决定。

而“搜索哪些资料”“查看哪些代码”“下一步调查什么”则很适合自主决策。

# 框架怎么选

原文列举的框架可以按定位快速记：

| 工具                    | 核心特点                   |
| --------------------- | ---------------------- |
| Codex Harness         | Coding Agent 自主运行时     |
| Claude Agent SDK      | 生产级自主 Agent SDK        |
| LangChain / LangGraph | Workflow + Agent 编排    |
| n8n                   | 可视化 Workflow + Agent   |
| Dify                  | 低代码 LLM / RAG 应用       |
| CrewAI                | 多 Agent 角色协作           |
| OpenClaw              | 自主 + 事件驱动个人 Agent      |
| DeepSeek Harness      | Everything is a Plugin |
| Pi                    | 极简 Coding Agent 框架     |

真正重要的不是记住这些框架，而是理解：

> **框架只是实现编排的工具，编排原理比具体框架更重要。**

选框架时优先问：

```text
它能不能让我少写没必要的框架代码，
直接处理真正的业务问题？
```

而不是：

```text
哪个框架功能最多？
```

# 最值得记住的模型

整个编排选择可以压缩成：

```text
任务简单？
    ↓
单次 LLM

步骤能提前确定？
    ↓
Workflow

步骤无法提前确定？
    ↓
Autonomous Agent

既有高风险固定步骤，
又有开放式问题？
    ↓
Workflow + Agent 混合
```

核心原则：

> **Agent 的价值不是“自主”本身，而是在无法提前写死执行路径时，仍能根据反馈继续完成任务。**
