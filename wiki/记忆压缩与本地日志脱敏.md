**记忆压缩减少重复和无用信息，让检索更有效；日志脱敏隐藏敏感内容，减少信息暴露。两者都需要保留任务真正需要的信息。**[^1]

**记忆越积越多，可以分三层整理。**

| 层次         | 怎么做                               | 原文示例                       |
| ---------- | --------------------------------- | -------------------------- |
| **重要性筛选**  | 综合访问频率、时间、情感强度和信息独特性，标记可以压缩或删除的记忆 | 常被访问、较新、情感强且不重复的记录，优先保留    |
| **相似内容合并** | 把相似记忆分组，这叫“聚类”；每组生成摘要，详细记录可以另行归档  | 多次天气对话合并为“用户经常询问天气，特别关心降雨” |
| **抽象出规律**  | 从具体经历中提炼稳定偏好，或从反复出现的做事步骤中整理通用流程   | 从多次购物对话中提炼“重视性价比和用户评价”     |

重要性评分中的四个因素，分别回答：

* **访问频率**：这条记忆是否经常用到？
* **时间衰减**：随着时间过去，它是否可能不再重要？
* **情感强度**：它是否涉及用户特别在意的经历？
* **信息独特性**：它提供了新信息，还是与其他记录重复？

原文用“访问 5 次、创建于 3 天前、情感强、无重复”和“访问 1 次、创建于 90 天前、无情感标记、与其他 3 条记录高度重复”作比较。这是评分思路的示意，**没有提供统一公式、权重或删除阈值**。

这些因素只能辅助判断。用户明确要求长期遵守的约束，即使很久没有访问，也可能十分重要。

**压缩会舍弃细节，整理时要防止改变原意。**

摘要应保留影响判断的人物、时间和条件；一次临时选择，也不足以证明长期偏好。需要追溯时，可以保留原始记录供回查。归档主要减少日常检索的负担，并不等于减少全部存储空间。

**日志脱敏要先找出敏感片段，再把它们隐藏或替换。**

需要处理的内容包括个人身份信息，即 **PII（Personally Identifiable Information）**，以及密码等机密数据。例如：

* 身份证号、银行卡号等格式较固定的内容。
* 地址等格式不完全固定的信息。
* “我的密码是 abc123”这类需要结合语境判断的表达。

说明示例：`我的密码是 abc123` → `我的密码是 [已隐藏]`。

实验 3-3 的 `log-sanitization` 项目通过 **Ollama（运行和调用本地模型的工具）** 使用 `qwen3:0.6b`，也可切换到 `qwen3:1.7b`、`qwen3:4b` 等更大规格。[Ollama 模型页面](https://ollama.com/library/qwen3:0.6b)

如果要求原始日志不离开本机，检测就应在本地完成。**本地脱敏模型仍然需要读取原文；对外发送和常规日志保存，应使用处理后的版本。**

完整流程需要包括：

1. **检测**：本地模型找出敏感内容。
2. **结构化输出**：返回敏感信息的类型、位置和置信度。JSON Schema 用来约束这些字段及其格式，Ollama 支持通过 `format` 参数传入。[结构化输出文档](https://docs.ollama.com/capabilities/structured-outputs)
3. **校验并替换**：程序检查返回结果和位置，再生成脱敏文本。
4. **使用脱敏结果**：把处理后的文本写入常规日志，或发送给后续服务。

JSON 格式正确，不代表敏感信息一定找全。模型给出的“置信度”也只是判断信号，不能直接当成经过验证的正确概率。

**原文报告“召回率达到 95% 以上，并显著降低误报”，但所给段落没有提供完整评测条件。**

这里要分清两个指标：

* **召回率**：实际存在的敏感信息，有多少被找到了。说明示例：100 处敏感信息找到 95 处，召回率就是 95%，仍漏掉 5 处。
* **误报**：把普通内容错当成敏感信息，导致不必要的隐藏。

原文没有给出测试集、样本量、正则方案的具体成绩，以及不同模型配置的结果。因此，这个数字应保留为**原文报告**，不能当作所有日志上的效果保证。

处理量很大时，可以采用混合策略：**正则表达式先匹配明显格式，本地模型再检查剩余文本中的语境信息。** 正则没有匹配到内容，并不能证明文本没有敏感信息。

整理好记忆之后，还需要解决“怎样找到相关的几条”。**RAG，即检索增强生成，就是先从记忆或知识库中找资料，再把相关内容交给模型回答。**
