## 3. 读数

1. **线程客户端复现了 diag 基线，且换用独立 C 回显服务器后结论不变**：T-E 跳转 p95 中位 15.20ms（三次 14.75/15.20/16.42），与 verifier-diag 的 Python 回显基线（15.88/14.94）同一量级——证明 ~15ms 下限来自客户端机制（50 Python 线程 + GIL/调度 + http.client），不是 diag 回显服务器的成本。
2. **替代客户端把回显基线压低一个数量级**：P-E 跳转 p95 中位 1.42ms（极差 2.8%），创建 1.96ms——测量开销不再主导 10.00/15.00ms 阈值量级的判定。
3. **替代客户端开始具备区分度**：P-A 跳转 2.77 vs P-E 1.42（服务端真实成本 ~1.4ms）；P-A 创建 2.76 vs P-E 1.96（~0.8ms）。线程客户端无区分度（T-A 17.24 vs T-E 15.20，且 T-E 创建 rep1 出现 24.63 离群使该格创建不稳定——47.2% > 30%，正是线程客户端噪声本性的又一佐证）。
4. **不挑轮次、不减基线**：以上均为全部 3 次重复全量报告，无剔除。
