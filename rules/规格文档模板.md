# 规格文档模板

本文件是写规格时的填空骨架。填写规则见 AGENTS.md 第 2 节。写作用简化技术规范（ASD-STE100 中文版）：句子短，一词一义，不用抽象术语代替具体行为。

## 用法

- 一个功能一份规格。文件名 `编号-功能英文名.md`，放 `docs/specs/`。
- 按下方 8 块填写。「必填」不得省略；「条件」无内容写「无」或「不适用」。
- 填完交用户确认。确认后把状态行改为「已确认」，注明用户和日期。
- 实现变化后更新原文件，按原结构补内容，不建新文件。参考已有规格 `001-daily-checkin.md`。

## 简写

简单任务可缩短篇幅，但必须保留：第 1、2、3、6 块和状态行。其余块写「简写：见讨论」。约束内容不减。

## 与计划的分工

规格写做什么、什么算通过，给用户核对。计划写哪步测、输入什么、期望什么，给 Agent 执行。测试场景写进计划，不写进本规格。

## 八个块

### 1. 标题（必填）

与文件名一致：`编号-功能英文名`。

### 2. 本轮目标（必填；简写保留）

- 做：两三句，说明本轮实现什么。
- 不做：明确排除的内容。防止自动扩功能。

### 3. 触发与行为（必填；简写保留）

- 触发条件：什么情况下启动。
- 执行动作：做什么，按顺序写。
- 可观察结果：做完后用户能看到什么。

### 4. 输入输出与边界（必填；简写时并入第 3 块）

- 输入：来源和格式。
- 输出：去向和格式。
- 边界：逐条列，每条写清输入和预期行为。

### 5. 约束与取舍（条件必填；无则写「无」）

- 必须保持的行为：接口、配置、已有数据的兼容性。
- 取舍：被否决的方案和原因。
- 名称：沿用讨论中已定的名称和说法。

### 6. 验收结果（必填；简写保留）

每条可观察、可复核，对应第 3 块的结果。标注验证场景，引用 AGENTS.md 第 4 节的场景名，不复述方法。

- [ ] 1.
- [ ] 2.

### 7. 术语（条件必填；无则写「无」）

必要术语就地解释，一句话一个词。

### 8. 调研链接（条件必填；未调研写「不适用」）

调研汇总和专家原始输出的链接。
