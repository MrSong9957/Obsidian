# 简化技术规范（ASD-STE100 中文版写作细则）

本文件细化「用简化技术规范（ASD-STE100 中文版）解释或写作，极简、说人话」这条要求，供写作和审查对照。

ASD-STE100 只有英文版。本文件的「中文版」指 ste-zh。

适用范围：全部中文写作（文档、规格、计划、日志、注释与对话解释）。

翻译内容先忠实原文。本细则只用来把话说清。翻译时不得增删原意。

条目编号规则：

- R 编号摘自 ste-zh，编号保留以便对照。
- S 编号是本文件增补，来自官方 STE 和 ste-zh 术语表。
- 总则是通用增补。

## 总则（增补）

- **极简**：一句话够用时，只写一句；一个词够用时，只用一个。不带信息的字，必须删除。
- **说人话**：写口语读得顺的句子。检验标准：读者一遍读懂，不回看、不猜。
- **行内源码对照**：解释代码时，按下面两条写。
  - 讲到具体变量、类型或行为时，紧跟括号附上对应源码。例：「输入是字符串（`let mut guess = String::new();`）」。
  - 补全零基础读者需要的前置知识。读者不必自己猜上下文。

## 词

- R1 一词一义：一个词全文只有一个意思；一个意思只用一个词。项目有术语表时，以术语表为准。
- R2 先定义后使用：专用词先给定义再使用。只有一两个专用词时，可以在首次出现处用括号定义。
- R3 用具体动词：不拿虚化动词包装动作（「对配置进行修改」→「修改配置」）。替换写法见附表 B。
- R4 字面量保持原样：代码、命令、路径、按钮名保持原文，写进反引号。
- R5 名词串（几个名词直接连写，中间没有「的」）不超过 3 个名词：超了就拆开，或加「的」。

## 句

- R6 一句一事：一句只写一个动作或一个事实。
- R7 句长上限：步骤句（告诉读者做什么）≤30 字，描述句（说明事实）≤40 字。汉字计 1，英文单词、数字、标识符计 1，标点不计。
- R8 主动语态：写出执行者；执行者不明或不重要，才用「被」字句。
- R9 条件在前，动作在后：「连接失败时，显示错误。」
- R10 不得用双重否定：「必须确认」，不写「不能不确认」。
- R11 情态词只用三个：必须、不得、可以。不得使用的近义词见附表 A。
- R12 主语明确：省略主语会产生两种读法时，必须补出。
- S1 不省略词语：不得为了缩短句子省略词语。句子超长时，拆成两句。

## 段与结构

- R13 一段一个主题，不超过 6 句。
- R14 步骤用祈使句、编号列表；每步一个动作，结果写下一句。
- R15 三个以上并列项，且每项不是单个词时，写成列表。（本条比 ste-zh 原文宽松，单个词的并列可以写在行内。）
- R16 警告先写命令，第二句写不遵守的后果。
- S2 安全提示分三级。「警告」和「注意」按 R16 写。
  - 「警告」：有人身伤害风险。
  - 「注意」：有设备或数据损坏风险。
  - 「说明」：只给补充信息，不得写指令。
- R17 列举不开放：不得用「等」「之类」收尾。必须列全，或指出完整清单的位置。

## 内容可信

- R18 关键信息先行：首句写结论或核心答复。细节和证据写在后面。
- R22 证据可定位：引用代码写 `路径:行号`。引用提交写提交号。引用命令写完整命令。
- R24 不确定时写明：没有确认的事实，标「未确认」，并写出确认方法。不得用「可能」「大概」「应该是」掩盖不确定。
- R25 不编造：每个事实必须能在来源中找到。来源是用户的输入、文件内容和工具输出。来源没有的内容，不得自行补充，必须列入「待确认」。

ste-zh 的 R19–R21、R23（状态词、不叙述过程、选项编号）属于 Agent 汇报格式，未收入本细则。

## 标点与混排

- S3 中文正文用全角标点。
- S3 引用界面文案或强调词语，用直角引号「」。
- S3 代码、命令、路径、标识符写在反引号内，内部用半角。
- S3 中文与英文单词、数字之间加一个半角空格。中文与全角标点之间不加空格。

## 附表 A：情态词

| 用词 | 词义 | 不得使用的近义词 |
|---|---|---|
| 必须 | 强制要求 | 应、应当、应该、需要、务必、要 |
| 不得 | 禁止 | 不应、不要、避免、禁止、切勿、不允许 |
| 可以 | 允许，不强制 | 可、能够、允许、可选 |

本表只限制情态用法。情态用法指表示要求、禁止或允许。以下用法不受本表限制：

- 「需要」表示缺少或依赖某物。例：「读者需要的证据」。
- 引用来源原文时，保留原文用词，并用引号标出。

## 附表 B：虚化动词替换

| 不得使用 | 改写为 |
|---|---|
| 对 X 进行修改 / 处理 / 检查 | 修改 / 处理 / 检查 X |
| 实现 X 功能 | 增加 X；或写出 X 的具体行为 |
| 予以 X / 加以 X | X |
| 做好 X 工作 | X |
| 完成 X 的操作 | X |
| 将会 X | 会 X |
| 进行 X | X |
| 作出 X 决定 | 决定 X |
| 通过 X 的方式 | 用 X |
| 存在 X 问题 | 写出具体现象 |
| 有一定的 X | 写出具体的量；没有量时删除 |

「处理」本身也是虚化动词。可以写出具体动作时，不得用「处理」。
