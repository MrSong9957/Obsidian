# 简化技术规范（ASD-STE100 中文版写作细则）

本文件细化「用简化技术规范（ASD-STE100 中文版）解释或写作，极简、说人话」这条要求，供写作和审查对照。

ASD-STE100 只有英文版。本文件的「中文版」指 ste-zh。

适用范围：全部中文技术写作（文档、规格、计划、日志、注释、解释与文档重构）。

例外与跨语言规则：

- **翻译原则**：翻译内容先忠实原文。本细则只用来把话说清。翻译时不得增删原意。
- **原样引用**：引用原文、日志、报错和命令输出时，必须一字不改，不按本细则改写。
- **格式优先**：文档有既定格式（例如 JSON、配置文件、固定接口表）时，不得为套用本细则破坏格式。
- **英文写作**：写英文时，步骤句不超过 20 词，描述句不超过 25 词。与语言无关的规则照常生效。

两类文体：

- **步骤性写作**：告诉读者做什么操作。步骤句用祈使句，每句一个动作。
- **描述性写作**：说明原理、状态、结构或事实。

条目编号规则：

- R 编号摘自 ste-zh，编号保留以便对照。
- S 编号是本文件增补，来自官方 STE 和 ste-zh 术语表。
- 总则是通用增补。

## 总则（增补）

- **极简**：一句话够用时，只写一句；一个词够用时，只用一个。不带信息的字，必须删除。
- **说人话**：写口语读得顺的句子。检验标准：读者一遍读懂，不回看、不猜。
- **行内源码对照**：解释代码时，按下面两条写。
  - 讲到具体变量、类型或行为时，紧跟括号附上对应源码。例：「输入是字符串（`let mut guess = String::new();`）」。
  - 补全零基础读者需要的前置知识。读者不必自己猜上下文。

## 词

- R1 一词一义：一个词全文只有一个意思；一个意思只用一个词。项目有术语表时，以术语表为准。例：选了「卡」，全文不再写「任务」「工单」「ticket」。
- R2 先定义后使用：专用词先给定义再使用；读者已知的通用词不定义。专用词超过两个时，集中在「术语」节定义；只有一两个时，可以在首次出现处用括号定义。
- R3 用具体动词：不拿虚化动词包装动作（「对配置进行修改」→「修改配置」）。替换写法见附表 B。
- R4 字面量保持原样：界面文案、按钮名、代码、命令、路径、标识符保持原文。界面文案和按钮名用直角引号「」；代码、命令、路径、标识符写进反引号。
- R5 名词串（几个名词直接连写，中间没有「的」）不超过 3 个名词：超了就拆开，或加「的」。例：「终端会话失败反馈界面状态」改为「终端会话失败时的界面状态」。

## 句

- R6 一句一事：一句只写一个动作或一个事实。
- R7 句长上限：中文步骤句不超过 30 字，描述句不超过 40 字。汉字计 1，英文单词、数字、标识符计 1，标点不计。英文步骤句不超过 20 词，描述句不超过 25 词。
- R8 主动语态：写出执行者；执行者不明或不重要，才用「被」字句。
- R9 条件在前，动作在后：写「连接失败时，显示错误。」，不写「显示错误，如果连接失败的话。」
- R10 不得用双重否定：「必须确认」，不写「不能不确认」。
- R11 情态词只用三个：必须、不得、可以。不得使用的近义词见附表 A。
- R12 主语明确：省略主语会产生两种读法时，必须补出。
- S1 不省略词语：不得为了缩短句子省略词语。句子超长时，拆成两句。

## 段与结构

- R13 一段一个主题，不超过 6 句。
- R14 步骤用祈使句、编号列表；每步一个动作，结果写下一句。
- R15 三个以上并列项，且每项不是单个词时，写成列表。（本条比 ste-zh 原文宽松，单个词的并列可以写在行内。）
- R16 警告先写命令，第二句写不遵守的后果。
- S2 安全提示分三级。「警告」和「注意」按 R16 写。
  - 「警告」：有人身伤害风险。
  - 「注意」：有设备或数据损坏风险。
  - 「说明」：只给补充信息，不得写指令。
- R17 列举不开放：不得用「等」「之类」收尾。必须列全，或指出完整清单的位置。

## 内容可信

- R18 关键信息先行：首句写主题或结论。细节、背景和依据写在后面。
- R22 依据可定位：引用代码写 `路径:行号`。引用提交写提交号。引用命令写完整命令。引用文档写路径和节名。
- R24 不确定时写明：没有证实的事实，标「未确认」，并写出确认方法。不得用「可能」「大概」「应该是」掩盖不确定。
- R25 不编造：每个事实必须有明确来源（例如原文、源码、实测输出）。来源没有的内容，不得自行补充，必须单独标明缺少的信息。

ste-zh 的 R19–R21、R23（状态词、运行验证模板、不叙述过程、选项编号）和汇报模板属于 Agent 回复格式，未收入本细则。

## 标点与混排

- S3 中文正文用全角标点。
- S3 引用界面文案、按钮名或强调词语，用直角引号「」。
- S3 代码、命令、路径、标识符写在反引号内，内部用半角。
- S3 中文与英文单词、数字之间加一个半角空格。中文与全角标点之间不加空格。

## 改写对照示例

改写前：

> 如果你想要对备份服务自动同步配置参数进行修改的话，应该先做好 backup.yaml 配置文件的备份工作，然后修改端口和超时时间，点击保存按钮并重启 backupd 服务，这样将会使配置生效，不要在同步任务运行时强制关闭进程，否则可能会存在数据损坏问题。

改写后：

> 修改备份服务的同步参数，按以下步骤执行：
>
> 1. 备份 `backup.yaml`。
> 2. 修改 `backup.yaml` 中的端口和超时时间。
> 3. 点击「保存」。
> 4. 重启 `backupd` 服务。新参数立即生效。
>
> **注意**：同步任务运行时，不得强制终止进程。强制终止会损坏数据。

改写要点：

- 拆短名词串，删掉「进行修改」「做好……工作」「将会」「存在……问题」（R3、R5）。
- 去掉「想要」「应该」「不要」「可能」，改用「不得」（R11、R24）。
- 把长句拆成单动作编号祈使句，结果另起一句（R6、R14）。
- 按钮名加「」，文件名和服务名加反引号（R4、S3）。
- 数据损坏风险标「注意」，条件在前，命令先于后果（R9、R16、S2）。

## 自检清单

写作或重构文档后，逐项核对：

- [ ] 首句写出主题或结论（R18）。
- [ ] 全文一词一义，专用词先定义后使用（R1、R2）。
- [ ] 没有虚化动词（R3，见附表 B）。
- [ ] 名词串不超过 3 个名词（R5）。
- [ ] 一句一事，不超字数上限（R6、R7）。
- [ ] 主动语态，条件在动作前，没有双重否定（R8、R9、R10）。
- [ ] 情态词只用「必须」「不得」「可以」（R11，见附表 A）。
- [ ] 没有用「等」「之类」结束列举（R17）。
- [ ] 事实有来源，未证实内容标「未确认」且不用「可能」「大概」「应该是」（R22、R24、R25）。
- [ ] 界面文案和按钮名用「」，代码、命令、路径、标识符用反引号，中英数字间加空格（R4、S3）。

## 附表 A：情态词

| 用词 | 词义 | 不得使用的近义词 |
|---|---|---|
| 必须 | 强制要求 | 应、应当、应该、需要、务必、要 |
| 不得 | 禁止 | 不应、不要、避免、禁止、切勿、不允许 |
| 可以 | 允许，不强制 | 可、能够、允许、可选 |

本表只限制情态用法。情态用法指表示要求、禁止或允许。以下用法不受本表限制：

- 「需要」表示缺少或依赖某物。例：「读者需要的证据」。
- 引用来源原文时，保留原文用词，并用引号标出。

## 附表 B：虚化动词替换

| 不得使用 | 改写为 |
|---|---|
| 对 X 进行修改 / 处理 / 检查 | 修改 / 处理 / 检查 X |
| 实现 X 功能 | 增加 X；或写出 X 的具体行为 |
| 予以 X / 加以 X | X |
| 做好 X 工作 | X |
| 完成 X 的操作 | X |
| 将会 X | 会 X |
| 进行 X | X |
| 作出 X 决定 | 决定 X |
| 通过 X 的方式 | 用 X |
| 存在 X 问题 | 写出具体现象 |
| 有一定的 X | 写出具体的量；没有量时删除 |

「处理」本身也是虚化动词。可以写出具体动作时，不得用「处理」。

## 附表 C：ASD-STE100 核心术语固定译法

讨论 ASD-STE100 或解释规则来源时，使用以下译法。完整 40 条译法表见本地 [skills/ste-zh/references/terminology.md](../skills/ste-zh/references/terminology.md)。

| 英文 | 中文 | 说明 |
|---|---|---|
| ASD-STE100 | ASD-STE100 | 标准编号，不翻译。 |
| Simplified Technical English (STE) | 简化技术英语 | 缩写 STE 不翻译。 |
| standard | 标准 | 第 9 版起的定位（第 8 版及更早称 `specification` 规范）。 |
| approved word | 核准词 | 词典规定可以使用的词。 |
| unapproved word | 非核准词 | 词典规定不得使用的词，改用词典给出的替代词。 |
| approved meaning | 核准词义 | 一个核准词只有一个核准词义。 |
| technical noun | 技术名词 | 第 9 版起取代 `technical name`（技术名称）。 |
| technical verb | 技术动词 | 领域专用的动作词。 |
| noun cluster | 名词串 | 多个名词直接连写。 |
| procedure / procedural writing | 步骤 / 步骤性写作 | 不译作「程序」，防止与软件程序混淆。 |
| descriptive writing | 描述性写作 | 说明原理、状态、结构或事实的文本。 |
| instruction | 指令 | 要求读者执行的单个动作。 |
| safety instruction | 安全说明 | 包含「警告」与「注意」两级提示。 |
| warning / caution / note | 警告 / 注意 / 说明 | 「说明」不写作「注释」，防止与代码注释混淆。 |
