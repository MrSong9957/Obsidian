## Obsidian 仓库规则

### obsidian-vault 同步规则

obsidian-vault 仓库**只保存全局记忆**，不保存项目记忆。修改时同步到 `/home/app/.claude/projects/-home-app-project/memory/MEMORY.md`。

### MEMORY.md 文档结构

文档固定三个板块，按顺序排列：

1. **仓库规则** — 同步规则、管理方法
2. **索引** — 所有详细文档的链接（学习进度、独立文档等）
3. **用户偏好** — 纯规则，不放链接

**新增内容归类原则：**
- 有独立文档的内容 → 只在索引加链接，偏好里不放链接
- 学习进度、详细文档 → 统一放索引
- 行为规则、偏好 → 放用户偏好

### Obsidian 管理方法

**文件夹结构：**
```
obsidian-vault/
├── README.md           # 管理方法说明（根目录）
├── Attachments/        # 图片、PDF 等附件
├── Templates/          # 笔记模板
├── References/         # 长期参考材料（方法、原则、最佳实践）
├── Projects/           # 项目相关笔记
├── Learning/           # 学习笔记、知识整理
├── claude-memory/      # Claude Code 全局记忆
└── Inbox/              # 待整理笔记
```

**分类原则：**
- 新笔记先放 Inbox/，定期整理
- 根目录只放 README.md，保持简洁
- References/ 存放长期可复用的知识

## 用户偏好

### 沟通语言

**使用中文**

### 代码学习偏好

只关心**原理和逻辑**，默认不逐行讲解代码。无法自动解决时才需逐行讲解。

### 解释风格

**嵌入术语的形象比喻** — 用比喻建直觉，同时嵌入真实专业术语。

### 项目推进

面向零基础，小步推进，每步可验证。

### 核心工作流

**自主闭环：** 自动验证、测试、迭代修复；多次失败才请求介入。

### 调试原则

**先观察再假设。** 第一件事：加日志，打印变量。

### 技术选型

优先复用成熟方案，避免重复造轮子。

### 避免过度工程化

只做必要的更改。不加功能、不重构、不提前设计抽象。

### 子代理

**用子代理：** 可并行、需隔离上下文、无共享状态。**直接做：** 简单任务、顺序操作、需跨步骤上下文。

### 前端美学

避免"AI 泛滥"美学。

### 代码解决方案

通用方案，不搞变通方法。测试验证正确性，不定义解决方案。

### 状态栏配置

详见状态栏配置。

### 代码质量

AI 负责发现最佳实践。
