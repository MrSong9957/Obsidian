# 安全攻防测试

核心方法：先审查代码，然后写脚本真刀真枪打一遍

请你现在不要扮演开发者，而是扮演一名专业的测试和安全工程师，对我的后端接口做一次全方位的攻防测试。请分两步执行，先审查后端代码，从源头找出下面这些问题，再尽量写出克运行的脚本，真的对我的接口发起这些请求，实测扛不扛得住。请站在攻击者的角度，系统性地逐条尝试：
1. 数据越权：把请求里的订单号、用户 ID 改成别人的，看能不能查到、改掉、删掉别人的数据
2. 功能越权：用一个普通用户的身份，去调那些本该只有管理员才能用的接口，看拦不拦得住
3. 身份认证：不登录、伪造、篡改身份身份凭证（比如token）去调用接口，看能不能蒙混过关
4. 偷改字段提权：在提交的数据里，偷偷多塞一个字段，比如把角色改成管理员，把价格改成0，把金额改成负数，看后端认不认
5. 恶意输入与注入：在各个输入框里，构造精心设计的恶意内容，尝试 SQL 注入、命令注入、脚本注入
6. 绕过前端限制：完全绕开页面，直接对接口发请求，看那些只做在前端的校验是不是形同虚设
7. 敏感信息泄露：检查接口返回的内容里，有没有带出密码、密钥、别人的手机号这类本不该暴露的信息
8. 资源滥用与防刷：对同一个接口（尤其是登录、发短信、下单）高频、超大并发地请求，看有没有限流，会不会被刷爆

请把发现的每一个问题都列成一份清单，逐条标明风险高低、会造成的后果以及你是怎么复现（发了什么请求、返回了什么）。

## 报告保存

安全攻防测试完成后，必须将最终报告保存为 Markdown 文件。

默认目录：`docs/security/reports/`

文件命名格式：`YYYY-MM-DD-<scope>-security.md`

例如：`docs/security/reports/2026-08-31-cli-security.md`

要求：
* `<scope>` 使用本次测试的模块、功能或系统名称，并保持简短。
* 若 `docs/security/reports/` 不存在，则创建该目录。
* 最终报告必须落盘，不得只在终端或对话中输出。
* 临时扫描结果、原始日志和一次性中间文件不得放入该目录。
* 不得覆盖已有报告；同日同范围重复测试时，在文件名后增加简短区分标识，例如 `-2` 或 `-rerun`。
* 完成后，在最终回复中明确给出报告的实际保存路径。
