# 创建自定义 Subagents

> 来源：[创建自定义 subagents - 官方文档](https://code.claude.com/docs/zh-CN/sub-agents)

在 Claude Code 中创建自定义 subagents（代理）主要有两种方式：**使用交互式命令自动生成**，或者**手动创建 Markdown 文件**。

## 方法一：使用 `/agents` 命令（推荐）

这是最简单且不易出错的方法，Claude 会通过交互式界面引导你完成创建，甚至可以直接帮你生成系统提示词：

1. 在 Claude Code 会话中，输入并运行命令：
```bash
/agents
```

2. 切换到 **Library** 选项卡，选择 **Create new agent**。
3. 选择代理的**范围（Scope）**：
   - **Project**（当前项目）：保存至 `./.claude/agents/`，可提交到 Git 与团队共享。
   - **Personal**（全局用户）：保存至 `~/.claude/agents/`，在你电脑上的所有项目中都能使用。

4. 选择 **Generate with Claude**，然后用自然语言描述你想让这个代理做什么（例如："一个专门用来审查安全漏洞的专家"）。Claude 会自动为你生成标识符、描述和系统提示词。
5. 根据提示选择该代理可以使用的**工具权限**、**AI 模型**（如 Sonnet 或 Haiku）、显示颜色以及是否开启**持久内存**。
6. 按 `s` 或 `Enter` 保存，代理即可立即投入使用。

## 方法二：手动创建 Markdown 文件

如果你喜欢直接写配置，可以直接在对应目录下手动创建 `.md` 文件。Subagent 文件由两部分组成：顶部的 **YAML frontmatter** 配置和底部的 **Markdown 系统提示词**。

### 1. 确定放置文件的目录

- **项目级（共享）**：在项目根目录下创建 `/.claude/agents/your-agent-name.md`
- **用户级（个人）**：在用户家目录下创建 `~/.claude/agents/your-agent-name.md`

### 2. 编写文件内容

文件的基本结构如下（以官方提供的代码审查代理为例）：

```markdown
---
name: code-reviewer
description: 专家级代码审查专家。主动审查代码的质量、安全性和可维护性。
tools: Read, Grep, Glob, Bash
model: sonnet
---
你是一名高级代码审查员，负责确保代码质量和安全的高标准。
当被唤醒时：
1. 运行 git diff 查看最近的更改。
2. 重点关注修改过的文件。
...
```

> 注意：如果你是通过手动在磁盘上创建或修改 `.md` 文件的，需要**重启当前的 Claude Code 会话**才能加载并生效。

## 核心配置参数说明（Frontmatter）

在手动编写时，有几个关键字段可以控制 Subagent 的能力：

| 参数 | 必填 | 说明 |
|------|------|------|
| `name` | 是 | 唯一标识符，使用小写字母和连字符（如 `security-checker`） |
| `description` | 是 | **非常重要！** Claude 会根据这个描述来决定何时自动把任务委托给这个代理 |
| `tools` | 否 | 允许该代理使用的工具列表（如 `Read, Grep, Glob, Bash`） |
| `disallowedTools` | 否 | 禁止该代理使用的工具列表 |
| `model` | 否 | 指定使用的 AI 模型（如 `sonnet`、`haiku`） |
| `memory` | 否 | 设置为 `project` 或 `user`，开启持久内存 |

### 关键参数详解

**`description` 字段**：这是最重要的字段。Claude 会根据任务描述自动匹配最合适的子代理，所以 description 要清晰描述该代理的专长和适用场景。

**`tools` 字段**：限制工具 = 聚焦执行。给的工具越少，代理越不容易跑偏。例如：
- 代码审查代理不需要 `Edit` 和 `Write` 权限
- 测试运行代理只需要 `Bash` 和 `Read`

**`model` 字段**：
- `sonnet` — 适合复杂推理和代码生成
- `haiku` — 适合简单研究任务，速度快、延迟低、费用便宜（Explore 代理默认就是 Haiku）

## 五大效率提升特性

### 1. 隔离高容量操作（最能省钱省 Token）

运行测试、获取长篇文档或分析庞大的日志文件时，会产生惊人的文本量。

- **为什么高效**：如果你在主对话里做这些，主上下文会瞬间被垃圾信息填满，导致后续对话变慢且极度消耗 Token。
- **如何实现**：把任务委托给一个专门的 subagent（例如内置的 `Explore` 或自定义的 `test-runner`）。它会在**独立的窗口**里把脏活累活干完，**只把最终的摘要或错误报告返回给你的主对话**，保持主会话极其干净、轻量。

### 2. 路径规则按需加载（Path-scoped Rules）

如果你的项目是一个庞大的单仓（Monorepo）或者前后端混在一起，不需要每次都让 Claude 加载所有的规范。

- **为什么高效**：你可以通过 `.claude/rules/` 配合 YAML 中的 `paths` 字段（例如限定 `"src/api//*.ts"`）。
- **如何实现**：只有当 Claude 真正去读取或处理匹配的文件时，这些规则才会**按需延迟加载**。这既保证了指令的精准遵循，又避免了 Token 的无谓浪费。

### 3. 持久内存（Persistent Memory）让代理"越用越聪明"

在配置自定义代理时，开启 `memory: project` 或 `memory: user` 范围。

- **为什么高效**：这允许子代理在跨越不同的会话（Sessions）时，依然能记住当前项目的架构决策、常见的 Bug 模式和团队特有的代码库规范。
- **如何实现**：在你的代理提示词里加上一句：*"在完成任务后，把你学到的新知识保存到你的 memory 中"*。随着时间推移，它会建立起关于你项目的专属知识库，后续提问时它能秒懂你的意图。

### 4. 显式调用（通过 `@-mention`）

当自动委托不够灵敏时，别用大白话慢慢引导 Claude 切换角色。

- **为什么高效**：直接在输入框输入 `@`，然后像提及文件一样选择你定义好的子代理（例如 `@code-reviewer`），可以**确保该特定代理立即启动**并处理当前任务，没有任何心智负担。

### 5. 灵活搭配模型（控制成本与速度）

在 Frontmatter 的 `model` 字段中，不一定全都要用最贵的 Sonnet。

- **为什么高效**：对于纯粹的代码搜索、文件发现或格式检查等简单研究任务，可以直接指定 `model: haiku`。它的速度极快、延迟极低，而且费用非常便宜，非常适合作为前置的研究员（Explore 代理默认就是 Haiku）。

## 持久内存（Persistent Memory）工作机制

通过启用持久内存特性，Subagent 可以实现跨越不同对话会话的"自主学习"和经验积累。

### 1. 它是如何做到"记住"的？

当你在 Subagent 的 Frontmatter 配置中指定了 `memory` 范围（例如 `memory: project`）时，Claude Code 会自动为这个代理在本地建立一个专属的内存目录，并创建一个名为 **`MEMORY.md`** 的文件。

- 只要开启了这个开关，Subagent 系统提示词里就会被秘密自动塞入一条指令：**"要求它在发现新的代码路径、团队规范、库位置或关键架构决策时，主动更新自己的内存文件。"**

### 2. 它是如何"越用越聪明"的？

- **启动时自动加载**：下一次你再次唤醒这个 Subagent 时，它专属的 `MEMORY.md` 的前 200 行内容（或 25KB）会**作为上下文的一部分直接加载到它的脑海里**。
- **形成经验闭环**：这意味着，如果它上周帮你在调试中发现了一个因为特定配置导致的隐蔽 Bug，并把它记录在了自己的内存里；这周你再让它处理类似任务时，它甚至不需要重新去通读代码，就能直接根据上周的"记忆"指出问题所在。

### 3. 官方推荐的"训飞"技巧

为了让你的 Agent 学习效果最好，文档里给出了两条非常实用的高效率口令（最佳实践）：

- **工作前让它先查阅记忆**：
> "帮我审查一下这个 PR，**顺便检查一下你的 memory**，看看里面有没有你之前见过的类似代码模式。"

- **完工后命令它总结归纳**：
> "既然你已经把这个 Bug 修复了，**现在把你在这次调试中学到的新知识/经验保存到你的 memory 中吧**。"

通过这种有意识的引导，这个 Agent 就会随着你项目开发时间的推移，逐渐变成一个最懂你这个项目的"专属资深专家"。

## 项目级 vs 用户级的选择

| 维度 | 项目级（Project） | 用户级（Personal） |
|------|-------------------|-------------------|
| 路径 | `./.claude/agents/` | `~/.claude/agents/` |
| 共享 | 可提交到 Git，团队共享 | 仅本机可用 |
| 适用场景 | 团队通用的代理（代码审查、测试） | 个人偏好代理（写作助手、翻译） |
| 生效范围 | 仅当前项目 | 所有项目 |

**建议**：
- 团队通用的代理（如代码审查、安全检查）放项目级
- 个人偏好代理（如写作助手、翻译工具）放用户级
- 代理配置变更后需要重启会话才能生效
