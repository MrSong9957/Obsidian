## 开篇导语

Anthropic 内部团队正在用 Claude Code 改造工作流：开发者和非技术岗都能啃复杂项目、自动化任务，并抹平原先限制生产力的技能差。[^1]

手册来源：对自家 Claude Code 重度用户的访谈，整理各部门怎么用、对工作有什么影响，以及给其他组织的采用建议。

## 1. Claude Code for data infrastructure（数据基础设施）

**团队在做什么**

数据基础设施团队为全公司各团队组织全部业务数据。他们用 Claude Code 做：例行数据工程自动化、复杂基础设施故障排查、给技术/非技术成员写可文档化的工作流，让大家能独立取数、改数。[^2]

### 主要用例

**用 Kubernetes 截图做调试**

Kubernetes 集群挂了、不再调度新 pod 时，团队用 Claude Code 诊断。他们把仪表盘截图喂进去，Claude Code 带他们按 Google Cloud 的 UI 一级级菜单排查，直到发现「pod IP 地址耗尽」警告；随后给出创建新 IP 池并挂到集群的精确命令，**不用再叫网络专家**。

**给财务团队的纯文本工作流**

团队教财务同事：把数据工作流写成纯文本文件，再丢给 Claude Code 全自动执行。没有编码经验的员工可以写「查这个仪表盘、取信息、跑这些查询、导出 Excel」，Claude Code 会跑完整条链路，还会主动问日期等必要输入。

**新人用代码库导航**

新数据科学家入职后，被引导用 Claude Code 穿越大代码库。它会读他们的 Claude.md（文档），定位任务相关文件，解释数据管道依赖，并说明哪些上游源喂进哪些仪表盘。**这替代了传统数据目录和可发现性工具**。

**会话结束时更新文档**

每项任务收尾时，团队让 Claude Code 总结这次工作会话并提改进建议。由此形成持续改进环：按实际用法精炼 Claude.md 与工作流说明，让下一轮更有效。

**多实例并行管任务**

做长时数据任务时，他们在不同仓库/项目开多个 Claude Code 实例。每个实例各自持有完整上下文——几小时或几天后切回来，仍记得做到哪、停在哪，实现不丢上下文的真并行。

### 团队影响

- **不靠专家也能修基础设施**：Kubernetes 集群问题通常要拉系统/网络组，现在用 Claude Code 诊断并给出精确修复。
- **上手更快**：新数据分析师能较快理解复杂系统，少靠手把手指导就能有效贡献。
- **支持工作流增强**：能处理大得多的数据量并揪出异常（例如盯 200 个仪表盘）——人手不可能逐个看。
- **跨团队自助**：无编码经验的财务团队可独立跑复杂数据工作流。

### 该团队 Tips

1. **写详细的 Claude.md**：工作流、工具、期望写得越清楚，Claude Code 越强。有现成模式时，它尤其擅长搭新数据管道这类例行任务。
2. **敏感数据用 MCP server，而不是 CLI**：建议用 MCP server 而不是 BigQuery CLI，更好控制 Claude Code 能碰什么；对要审计日志或有隐私顾虑的数据尤其重要。
3. **开团队使用分享会**：成员互相演示自己的 Claude Code 工作流，传播最佳实践，也能发现各自想不到的用法。

## 2. Claude Code for product development（产品开发）

**团队在做什么**

Claude Code 团队**用自家产品做自家产品**：扩展企业能力与 agentic loop（自主循环）功能。[^3]

### 主要用例

**auto-accept mode 快速原型**

工程师开「auto-accept mode」（Shift+Tab）做快速原型：设自主循环，让 Claude 写代码、跑测试、连续迭代。他们把不熟悉的抽象问题丢给它，让它自主干，再 review 约 **80% 完成度**的方案，然后人工接手做最后打磨。团队强调：**从干净 git 状态出发，并定期提交 checkpoint**，Claude 跑偏时才能轻松回滚。

**核心功能同步写**

碰应用业务逻辑的关键功能，团队改为与 Claude Code **同步**协作：详细 prompt + 具体实现说明；实时盯过程，保证代码质量、风格指南和架构，重复劳动仍交给 Claude。

**做 Vim mode**

最成功的异步项目之一是给 Claude Code 实现 Vim 键位。他们让 Claude 独自做完整个功能（即便它不是优先级），最终实现里约 **70%** 来自 Claude 自主工作，只迭代几轮就完成。

**测试生成与修 bug**

功能写完后用 Claude Code 补全面测试；也处理 PR review 里发现的简单 bug。还靠 GitHub Actions 集成，让 Claude 自动处理 PR 评论（格式、函数改名等）。

**代码库探索**

面对不熟的 monorepo / API 侧，直接问 Claude 系统怎么工作，不必等 Slack 回复；省下大量上下文切换时间。

### 团队影响

- **功能落地更快**：如 Vim mode，约 70% 代码由 Claude 自主写出。
- **开发速度提升**：能快速原型和迭代想法，不被实现细节拖死。
- **自动化测试抬高质量**：Claude 生成全面测试、处理例行 bug，少花人力还保持标准。
- **探索更好**：成员能快速搞懂 monorepo 里不熟的部分，不用干等同事。

### 该团队 Tips

1. **建自给自足的循环**：让 Claude 自动跑 build / test / lint 自检。这样它能更久自主工作并抓自己的错；**先让它写测试再写代码**尤其有效。
2. **练任务分类直觉**：分清适合异步的（边缘功能、原型）和需要同步盯的（核心业务逻辑、关键修复）。产品边缘的抽象任务可用 auto-accept mode；核心功能要更近的监督。
3. **prompt 要清楚、具体**：组件名字/职责相近时必须极度具体。prompt 越细，越能放心让它独立干，而不至于改错地方。

## 3. Claude Code for security engineering（安全工程）

**团队在做什么**

安全工程团队负责软件开发生命周期安全、供应链安全、开发环境安全。他们大量用 Claude Code 写代码和调试。[^4]

### 主要用例

**复杂基础设施调试**

处理事故时，把 stack trace 和文档喂给 Claude Code，让它在代码库里追控制流。生产问题的解决时间显著变短：原本要 **10–15 分钟**手动扫代码的问题，大约 **5 分钟**能理清。

**Terraform 代码审查与分析**

需要安全审批的基建变更，他们把 Terraform plan 贴进 Claude Code，问：「这会做什么？我会后悔吗？」（“what’s this going to do? Am I going to regret this?”）反馈环更紧，安全组更快审/批基建变更，减少开发侧堵点。

**文档合成与 runbook**

让 Claude Code 吃进多份文档源，生成 Markdown runbook、排障指南和总览。用这些浓缩文档当调试真实问题的上下文，比在完整知识库里翻更高效。

**TDD 工作流**

旧模式是「设计文档 → 凑合能跑的代码 → 重构 → 放弃测试」。现在改为：先要伪代码，引导 Claude 走测试驱动开发，卡住时定期 check-in 纠偏，产出更可靠、可测的代码。

**跨项目切换与上手**

给已有项目（如 security 审批工作流的 web 应用 “dependant”）做贡献时，用 Claude Code 写、审、执行存在代码库里的 Markdown 规格说明；有意义的贡献从「要几周建上下文」变成「几天内」。

### 团队影响

- **事故解决更快**：原本 10–15 分钟手动扫码的基建调试，约 5 分钟。
- **安全审查周期更好**：Terraform 安全审批快得多，开发者少被卡住。
- **跨职能贡献增强**：几天内就能有效贡献，而不是几周建上下文。
- **文档工作流更好**：多源合成排障指南与 runbook，调试更高效。

### 该团队 Tips

1. **大量用自定义 slash command**：安全工程占了整个 monorepo 里自定义 slash command 实现的 **50%**。自定义命令能固化特定工作流、加速重复任务。
2. **让 Claude 先说完**：不再为代码片段问零碎问题，而是告诉它「边干边 commit」，让它自主工作、定期 check-in，方案往往更完整。
3. **文档也交给它**：Claude Code 擅长合成文档和结构化输出。提供写作样例和格式偏好，拿到可直接丢进 Slack、Google Docs 等工具的文档，减少切界面疲劳。

## 4. Claude Code for inference（推理）

**团队在做什么**

推理团队管理**记忆系统**——Claude 读你的 prompt、生成响应时用来存信息的那套。团队成员，尤其是新接触机器学习的人，大量用 Claude Code 抹平知识差、加速工作。[^5]

### 主要用例

**代码库理解与上手**

进复杂代码库时重度依赖 Claude Code 快速摸清架构。不再手动翻 GitHub 仓库，而是问 Claude「哪些文件调用了某功能」，几秒出结果，不必等同事或自己搜。

**单元测试 + 边界覆盖**

核心功能写完后让 Claude 写全面单元测试。它会自动补上被漏掉的边界情况，把原本很费心智的活压到几分钟，像一个可 review 的编码助手。

**解释机器学习概念**

没有 ML 背景的成员靠 Claude 解释模型相关函数和设置。原本要 **1 小时** Google + 读文档，现在 **10–20 分钟**，研究时间约降 **80%**。

**跨语言代码翻译**

要在不同语言里测功能时，说明想测什么，Claude 用目标语言（如 Rust）写出逻辑，不必为了测试现学新语言。

**命令回忆与 Kubernetes 管理**

不必背复杂 Kubernetes 命令；问 Claude 正确语法（例如「怎么列出所有 pod 或 deployment 状态」），直接拿到基建要用的精确命令。

### 团队影响

- **ML 概念学习加速**：研究时间约 -80%（1 小时 → 10–20 分钟）。
- **导航更快**：几秒找到相关文件、理解架构，而不是问同事。
- **测试覆盖更全**：Claude 自动生成含边界的单元测试，减负且保质。
- **抹掉语言壁垒**：能在不熟的语言（如 Rust）里实现功能，不必现学。

### 该团队 Tips

1. **先测「知识库」能力**：拿各种问题试，看 Claude 是否比 Google 更快更准。是的话，它就是工作流里很值的省时工具。
2. **从代码生成起步**：给具体指令让它写逻辑，再验正确性。建立信任后再上更复杂任务。
3. **测试交给它写**：让 Claude 写单元测试能卸掉日常开发很大压力；用它保代码质量，不必自己把所有用例想完。

## 5. Claude Code for data science and visualization（数据科学与可视化）

**团队在做什么**

数据科学与 ML 工程团队需要复杂可视化工具来理解模型表现，但做这些工具往往要会不熟的语言和框架。Claude Code 让他们**不必变成全栈**也能做出生产级分析仪表盘。[^6]

### 主要用例

**用 JS/TS 做仪表盘应用**

团队自称「几乎不懂 JavaScript / TypeScript」，却用 Claude Code 做出完整 React 应用，可视化 RL 模型表现和训练数据。他们把实现全权交给 Claude，例如写一个 **5000 行** TypeScript 应用，自己不必逐行看懂。可视化应用上下文相对少、不必理解整个 monorepo，因此能快速原型出理解训练/评估表现的工具。

**处理重复重构**

遇到合并冲突或半复杂文件重构——编辑器宏搞不定、又不值得上大工程——他们把 Claude Code 当「**老虎机**」（slot machine）：先 commit 当前状态，让它自主干 **30 分钟**，要么接受结果，要么不行就重开，不硬修。

**做持久分析工具，而不是一次性 notebook**

不再做用完即扔的 Jupyter notebook；让 Claude 造可复用的永久 React 仪表盘，跨多次模型评估复用。这很重要，因为理解 Claude 的表现是「团队最重要的事情之一」——训练和评估里模型怎么表现「其实非平凡，简单工具只盯一个数字往上跳，拿不到多少信号」。

**零依赖委派任务**

对完全不熟的代码库/语言任务，整段实现交给 Claude Code，让它自己从 monorepo 收集上下文并执行，人不参与实际写码。在专长之外也能产出，而不是先花时间学新技术。

### 团队影响

- **2–4× 省时**：原先枯燥但还能手动做的例行重构，现在快得多。
- **不熟语言里做出复杂应用**：几乎无 JS/TS 经验，仍做出 5000 行 TypeScript 应用。
- **从一次性转向持久工具**：不再用一次性 Jupyter notebook，改做可复用 React 仪表盘。
- **直接反哺模型改进**：第一手 Claude Code 体验用于改进后续模型的记忆系统和 UX。
- **可视化驱动决策**：用高级数据可视化更好地理解训练/评估中的 Claude 表现。

### 该团队 Tips

1. **当老虎机用**：让 Claude 干活前先存状态，跑 30 分钟，要么收结果要么重开，别跟修正较劲。**重开往往比修 Claude 的错成功率更高。**
2. **需要时打断，要更简单**：监督时别犹豫，直接停：「你为什么这么做？试试更简单的。」模型默认偏复杂，但对「要更简单」反应很好。

## 6. Claude Code for API

**团队在做什么**

API Knowledge 团队做 PDF 支持、引用、网页搜索等，把更多知识带进 Claude 的上下文窗口。跨大型复杂代码库意味着不断碰到不熟的代码、花大量时间搞清该看哪些文件、在改之前先建上下文。Claude Code 像向导：理解架构、定位相关文件、解释复杂交互。[^7]

### 主要用例

**任务的第一站（规划该看哪些文件）**

任何任务先问 Claude Code：修 bug / 做功能 / 做分析该看哪些文件。替代了传统「先手动翻代码库、建上下文再开干」的耗时过程。

**在不熟区域独立调试**

现在有信心在不熟的代码区自己扛 bug，而不是先问人。可以问：「你觉得能修这个 bug 吗？我看到的行为是这样」（“Do you think you can fix this bug? This is the behavior I’m seeing”），常立刻有进展——以前因为时间成本太高根本不可行。

**用 dogfooding 测模型迭代**

Claude Code 自动用最新研究模型快照，成为他们体验模型变化的主要方式。开发周期里能直接感受模型行为变化，这是以前发版时没有过的。

**消掉上下文切换开销**

不再一边复制代码片段、往 Claude.ai 拖文件、大段解释问题，而是在 Claude Code 里直接问，省掉额外收上下文，心智负担明显下降。

### 团队影响

- **敢碰不熟区域**：能在陌生代码库独立调试、查事故。
- **收集上下文省时**：不必再复制片段、拖文件进 Claude.ai，减少心智切换。
- **轮岗上手更快**：换组的工程师能快速进入陌生代码库，少大量请教同事。
- **开发者幸福感提升**：团队反映日常摩擦变少，更开心也更多产。

### 该团队 Tips

1. **当可迭代的搭档，不是一次性解药**：别指望 Claude 一次解完；当协作对象来回迭代，比逼首轮完美更好。
2. **用它建立在不熟领域的信心**：别因为「不是我的专长」就不敢修 bug 或查事故——Claude Code 让原本要大量建上下文的独立工作变得可行。
3. **从最少信息开始**：只给当下最小必需信息，让 Claude 带你走，而不是一上来塞一大段解释。

## 7. Claude Code for growth marketing（增长营销）

**团队在做什么**

增长营销团队做效果营销渠道：付费搜索、付费社交、移动应用商店、邮件营销、SEO。作为**一人非技术岗**，他们用 Claude Code 自动化重复营销任务，搭原本需要大量工程资源的 agentic 工作流。[^8]

### 主要用例

**自动生成 Google Ads 创意**

搭了一条 agentic 工作流：处理含数百条现有广告及效果指标的 CSV，找出表现差的广告做迭代，生成符合严格字数限制（标题 30 字符、描述 90 字符）的新变体。用**两个专门子代理**（一个写标题、一个写描述），几分钟内生成数百条新广告，而不是在多个广告系列里手搓。以前这规模的测试迭代要花大量时间。

**Figma 插件做海量创意**

不再手动复制/改付费社交静态图；开发了 Figma 插件：识别 frame，程序化生成最多 **100 条**广告变体（换标题/描述）。原先要几小时复制粘贴，现在每批约 **半秒**。创意产出 **10×**，能在关键社交渠道测更多变体。

**Meta Ads MCP server 做活动分析**

做了接 Meta Ads API 的 MCP server，在 Claude Desktop 里直接查活动表现、花费和广告效果，不必在平台间来回切。每一丁点效率提升都直接换成更好 ROI。

**带记忆系统的进阶 prompt 工程**

实现了初级记忆系统：跨广告迭代记录假设与实验，生成新变体时把过往测试结果拉进上下文，形成自改进测试框架。这是人手无法系统跟踪的实验方式。

### 团队影响

- **重复任务大幅省时**：广告文案从 **2 小时 → 15 分钟**，省下的时间做策略。
- **创意产出 10×**：配合自动生成和 Figma 集成，跨渠道测更多广告变体。
- **像更大的团队在干活**：能处理原本要专职工程资源的任务。
- **策略重心转移**：更多时间放在总策略和搭 agentic 自动化，而不是手工执行。

### 该团队 Tips

1. **找「有 API 的重复任务」**：涉及重复动作、且工具（广告平台、设计工具、分析平台）有 API 的工作流，是最适合自动化、Claude Code 价值最大的地方。
2. **复杂工作流拆成专门子代理**：别在一个 prompt/工作流里包办一切；按任务拆开（如标题代理 vs 描述代理），更好调试，复杂需求下输出质量也更好。
3. **写码前充分头脑风暴和 prompt 规划**：先在 Claude.ai 上花足够时间想清整条工作流，再让 Claude.ai 产出供 Claude Code 参考的完整 prompt 和代码结构；并**分步做**，不要一次要一揽子方案，以免 Claude 被复杂任务淹没。

## 8. Claude Code for product design（产品设计）

**团队在做什么**

产品设计团队支持 Claude Code、Claude.ai 和 Anthropic API，专做 AI 产品。**非开发者**也能用 Claude Code 抹平设计与工程之间的传统鸿沟，直接实现设计意图，不必和工程师大量来回。[^9]

### 主要用例

**前端打磨与状态管理改动**

视觉微调（字体、颜色、间距）不再靠长设计文档 + 多轮与工程师往返，而是用 Claude Code 直接改。工程师注意到他们做出「通常不会见到设计师做的大型状态管理改动」，能精确做到自己设想的质量。

**GitHub Actions 自动开单**

用 Claude Code 的 GitHub 集成：只需提交 issue/ticket 描述要改什么，Claude 自动提出代码方案，**不必打开 Claude Code**。给持续存在的 polish backlog 形成无缝的修 bug / 功能打磨流。

**快速交互原型**

把设计稿图片贴进 Claude Code，生成工程师能立刻看懂并迭代的**可运行原型**，替代「静态 Figma 设计 → 大量解释和翻译成代码」的老循环。

**边界发现与架构理解**

用 Claude Code 画出错误状态、逻辑流和不同系统状态，在**设计阶段**就发现边界，而不是开发后期才撞上，从根上抬高初稿质量。

**复杂文案改动与法务合规**

例如全代码库清掉 “research preview” 文案：用 Claude Code 找出全部出现点、review 周边文案、和法务实时对齐改动并落地——过程是两次 **30 分钟**通话，而不是一周来回协调。

### 团队影响

- **核心工作流被改造**：Claude Code 成为主要设计工具；Figma + Claude Code 约 **80%** 时间开着。
- **2–3× 执行更快**：原先要和工程师大量往返的视觉与状态管理改动，现在直接实现。
- **周期从周到小时**：如 GA launch 文案这类原本一周协调的项目，两次 30 分钟通话搞定。
- **两种截然不同的体验**：开发者是「增强型工作流」（更快执行）；非技术用户是「天哪我变成开发者了」的工作流（以前不可能的能力）。
- **设计-工程协作更好**：设计师提前懂系统约束和可能性，沟通与解题都更快。

### 该团队 Tips

1. **找工程师做正经初始化**：仓库初始设置和权限要工程同事帮忙——对非开发者技术上手仍难；配好之后，对日常工作流才是转型级变化。
2. **用自定义记忆文件引导 Claude 行为**：写明「我是编码经验很少的设计师，需要详细解释和更小步的增量改动」，能大幅改善 Claude 的回应质量，也更不吓人。
3. **善用贴图做原型**：Command+V 直接把截图贴进 Claude Code——它擅长读设计并生成可用代码，把静态 mockup 变成工程师能立刻理解并继续搭的交互原型。

## 9. Claude Code for RL engineering（RL 工程）

**团队在做什么**

RL 工程团队关注强化学习中的高效采样，以及集群上的权重传输。他们主要用 Claude Code 写中小功能、调试、理解复杂代码库；方法偏迭代：**频繁 checkpoint 和回滚**。[^10]

### 主要用例

**监督式自主做功能**

小到中等功能，让 Claude Code 写大部分代码，同时提供监督（例如给权重传输组件实现鉴权）。交互式工作：让它带路，跑偏时再纠。

**测试生成与代码 review**

自己改完后，让 Claude Code 补测试或 review 代码。这套自动化测试流在例行但重要的质量保障上省下大量时间。

**调试与排错**

用 Claude Code 调错误，结果有好有坏：有时立刻定位并补上相关测试；有时它搞不懂问题。整体上「有用的时候很有用」。

**代码库理解与调用栈分析**

工作流里最大的变化之一：用 Claude Code 快速拿到相关组件和调用栈摘要，替代手动读代码或生成大量调试输出。

**Kubernetes 运维问答**

经常问 Claude Code 那些原本要大量 Google 的 Kubernetes 操作，配置和部署问题能立刻得到答案。

### 工作流影响

- **能更实验性**：用「试了再回滚」（try and rollback）：频繁提交 checkpoint，测 Claude 的自主实现，不行就 revert。
- **文档加速**：Claude Code 自动加有用的注释，省下大量文档时间；他们也提到**有时注释加在奇怪位置，或代码组织方式存疑**。
- **有加速，但有限**：小到中等 PR 能在「相对少的人力时间」下做完；他们承认**首次大约只有 1/3 能成**，需要额外指导或人工介入。

### 该团队 Tips

1. **为具体模式定制 Claude.md**：在 Claude.md 里写指令，防止 Claude 反复犯工具调用错误，例如「跑 pytest 用 run，别没事 cd——直接用正确路径」。一致性显著变好。
2. **checkpoint 重度工作流**：Claude 改代码时定期 commit，实验失败能轻松回滚，开发更敢试。
3. **先 one-shot，不行再协作**：先给快速 prompt 让它尝试完整实现；成了（约 1/3）就省下大量时间；不成再切成更协作、更有引导的方式。

## 10. Claude Code for legal（法务）

**团队在做什么**

法务团队通过试验发现 Claude Code 的潜力，也想了解 Anthropic 的产品。另有一名成员有个人场景：给家人做无障碍工具，以及做出能向非开发者展示技术威力的工作原型。[^11]

### 主要用例

**给家人的定制无障碍方案**

有成员为因医疗诊断而说话困难的家人做沟通助手。**一小时内**做出预测文本应用：用系统自带语音转文字，建议回复并用 voice bank 读出来，补上了言语治疗师推荐的现有无障碍工具的缺口。

**法务部门工作流自动化**

做了原型「电话树」系统，帮成员接到 Anthropic 内正确的律师，展示法务部门如何在没有传统开发资源的情况下为常见任务自建工具。

**团队协作工具**

管理者做了 G Suite 应用：自动化每周团队更新，跟踪跨产品法务审查状态；律师点按钮就能标出待审项，而不是管一堆表格。

**快速原型验证方案**

用 Claude Code 快速搭出能运行的原型，拿给领域专家看（例如给 UCSF 专家看无障碍工具），在投入更多时间前验证想法、确认是否已有现成方案。

### 工作方式与影响

- **在 Claude.ai 规划，在 Claude Code 实现**：两步——先在 Claude.ai 头脑风暴和规划，再进 Claude Code 实现，并要求它**放慢、一步一步做**，不要一次吐完。
- **视觉优先**：常用截图告诉 Claude Code 界面该长什么样，按视觉反馈迭代，而不是用文字描述功能。
- **原型驱动创新**：强调克服「不好意思分享幼稚/玩具原型」——这些演示能启发别人看见原先没想到的可能性。

### 安全与合规意识（产品律师视角）

- **MCP 集成顾虑**：作为产品律师，他们会立刻识别深度 MCP 集成的安全含义；并指出：当 AI 工具接触更敏感系统时，偏保守的安全姿态会形成壁垒。
- **合规工具优先级**：主张随 AI 能力扩展**尽快建合规工具**，认识创新与风险管理之间的平衡。

### 该团队 Tips

1. **先在 Claude.ai 充分规划**：用对话界面把整套想法 flesh out，再进 Claude Code；然后让 Claude 把一切总结成逐步实现的 prompt。
2. **增量 + 视觉地做**：让 Claude Code 放慢，一次一步，方便你 copy-paste 而不被淹没；大量用截图展示界面想要的样子。
3. **不完美也要分享原型**：克服想藏「玩具」项目或未完成工作的冲动——分享原型帮别人看见可能性，也能点燃通常不互相来往的部门之间的创新。

| monorepo | 把很多项目塞进一个超大仓库 |

| stack trace | 报错时打印的调用栈 |
