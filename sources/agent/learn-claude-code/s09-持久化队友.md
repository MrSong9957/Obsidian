> _"任务太大一个人干不完, 要能分给队友"_ -- 持久化队友 + JSONL 邮箱。

## 问题

子智能体 (s04) 是一次性的: 生成、干活、返回摘要、消亡。没有身份, 没有跨调用的记忆。后台任务 (s08) 能跑 shell 命令, 但做不了 LLM 引导的决策。

真正的团队协作需要三样东西: (1) 能跨多轮对话存活的持久智能体, (2) 身份和生命周期管理, (3) 智能体之间的通信通道。

## 解决方案

```
Teammate lifecycle:
  spawn -> WORKING -> IDLE -> WORKING -> ... -> SHUTDOWN

Communication:
  .team/
    config.json    <- team roster + statuses
    inbox/
      alice.jsonl  <- append-only, drain-on-read
      bob.jsonl
      lead.jsonl
```

## 工作原理

1. **TeammateManager** 通过 config.json 维护团队名册。

```python
class TeammateManager:
    def __init__(self, team_dir: Path):
        self.dir = team_dir
        self.dir.mkdir(exist_ok=True)
        self.config_path = self.dir / "config.json"
        self.config = self._load_config()
        self.threads = {}
```

2. `spawn()` 创建队友并在线程中启动 agent loop。

```python
def spawn(self, name: str, role: str, prompt: str) -> str:
    member = {"name": name, "role": role, "status": "working"}
    self.config["members"].append(member)
    self._save_config()
    thread = threading.Thread(
        target=self._teammate_loop,
        args=(name, role, prompt), daemon=True)
    thread.start()
    return f"Spawned teammate '{name}' (role: {role})"
```

3. **MessageBus**: append-only 的 JSONL 收件箱。`send()` 追加一行; `read_inbox()` 读取全部并清空。

```python
class MessageBus:
    def send(self, sender, to, content, msg_type="message", extra=None):
        msg = {"type": msg_type, "from": sender,
               "content": content, "timestamp": time.time()}
        if extra:
            msg.update(extra)
        with open(self.dir / f"{to}.jsonl", "a") as f:
            f.write(json.dumps(msg) + "\n")

    def read_inbox(self, name):
        path = self.dir / f"{name}.jsonl"
        if not path.exists(): return "[]"
        msgs = [json.loads(l) for l in path.read_text().strip().splitlines() if l]
        path.write_text("")  # drain
        return json.dumps(msgs, indent=2)
```

4. 每个队友在每次 LLM 调用前检查收件箱, 将消息注入上下文。

| 组件 | 之前 (s08) | 之后 (s09) |

# 新版 Memory

根据 [Learn Claude Code](https://learn.shareai.run/zh/s09/) 课程第 **s09 Memory（记忆管理）** 章节的正文，其核心概念、工作原理与教学版代码实现提炼如下：

---

## 1. 核心痛点与解决思路

* **痛点：** 之前引入的 [Context Compact (自动上下文压缩)](https://learn.shareai.run/zh/s09/) 虽然能把复杂的历史对话压缩成摘要，但**摘要是有损的**。诸如“用 tab 缩进不要用空格”等至关重要的用户偏好细节很容易在多轮压缩中被合并丢弃。更致命的是，**大模型没有持久化状态**，一旦开启一个全新的会话（New Session），之前积累的所有用户约束、项目背景和反馈习惯都会彻底烟消云散。
* **解决思路：** **“压缩会丢细节，要有一层不丢的”**。建立一套**独立于上下文压缩、且跨会话持久化**的外部存储层——**文件记忆库**。将稳定的知识、事实与偏好写入到本地磁盘（`.memory/` 目录），通过“轻量索引常驻 System Prompt + 实时内容按需加载（On-demand borrow）”的方式，在不破坏模型 Prompt 缓存（Prompt Cache）的前提下，实现跨会话、跨压缩的细节无限续航。

---

## 2. 四类记忆分类

系统将持久化记忆分为四种类型，各司其职：

| 类型 (Type) | 回答什么 | 示例 |
| --- | --- | --- |
| **user** | 你是谁 / 用户是谁 | “用 tab 不用空格”、“以后都用单引号” |
| **feedback** | 怎么做事 / 编程偏好 | “别 mock 数据库，直接跑 Docker” |
| **project** | 正在发生什么 / 全局背景 | “auth 模块重写是由安全合规驱动的” |
| **reference** | 东西在哪找 / 导航线索 | “CI/CD 管道的 bug 排查入口在 Linear 系统的 INGEST 目录” |

## 3. 核心功能代码实现

### ① 存储层：Markdown 独立文件 + 索引清单

每条记忆以 `.md` 独立文件形式存储在持久化目录中，并带有 YAML frontmatter 元数据：

```python
import json
import re
from pathlib import Path

MEMORY_DIR = Path(".memory")
MEMORY_DIR.mkdir(exist_ok=True)

def write_memory_file(name: str, mem_type: str, description: str, body: str):
    """持久化写入单个记忆文件，并触发索引重建"""
    # 将名称规范化为 slug 文件名，如 "user-preference-tabs.md"
    slug = name.lower().replace(" ", "-")
    filepath = MEMORY_DIR / f"{slug}.md"
    
    content = f"---\nname: {name}\ndescription: {description}\ntype: {mem_type}\n---\n\n{body}\n"
    filepath.write_text(content)
    
    # 核心：写入后必须立刻增量/全量重建平面索引
    _rebuild_index()

def _rebuild_index():
    """重建 MEMORY.md 索引文件"""
    files = list_memory_files()
    lines = ["# Memory Catalog\n"]
    for f in files:
        lines.append(f"- {f['slug']} — {f['description']}")
    (MEMORY_DIR / "MEMORY.md").write_text("\n".join(lines))

```

### ② 加载层（路径一）：极轻量索引常驻 System Prompt

索引文件 `MEMORY.md` 极其精简（一行一个链接），每次启动或交互时读取它注入 System Prompt。这样能保持大模型的“全局记忆感知力”，且由于其内容稳定，能**高效命中 API 的 Prompt Cache**：

```python
def build_system_prompt() -> str:
    index_file = MEMORY_DIR / "MEMORY.md"
    catalog = index_file.read_text() if index_file.exists() else "No memories recorded yet."
    return (
        f"You are a coding agent.\n"
        f"Available long-term memory catalog:\n{catalog}\n"
        f"If the current task relates to any item above, the system will dynamically borrow its details."
    )

```

### ③ 加载层（路径二）：相关记忆细节按需注入

在把 messages 提交给大模型前，通过一个极轻量的 **Side-Query（旁路查询）** 让 LLM 进行索引匹配，选出最相关的完整记忆内容动态借调（Borrow）到当前的 user 消息中，严格限制单次最多加载 5 条，控制开销：

```python
def select_relevant_memories(messages: list) -> list[str]:
    """通过旁路轻量调用，选择与当前对话相关的记忆文件名"""
    files = list_memory_files()
    if not files:
        return []
        
    # 构造轻量级目录：只给模型看 "0: user-preference-tabs — User prefers tabs..."
    catalog = "\n".join(f"{i}: {f['slug']} — {f['description']}" for i, f in enumerate(files))
    recent_dialogue = format_recent_messages(messages[-3:]) # 取最近几轮对话
    
    try:
        # 发起一次极低 Token 消耗的旁路查询（仅返回 JSON 数组，如 [0, 2]）
        response = client.messages.create(
            model=MODEL,
            messages=[{
                "role": "user",
                "content": f"Select relevant memory indices for current conversation. Return JSON array ONLY.\n\n"
                           f"Recent dialogue:\n{recent_dialogue}\n\nMemory catalog:\n{catalog}"
            }],
            max_tokens=200
        )
        text = extract_text(response.content).strip()
        indices = json.loads(re.search(r'\[.*?\]', text).group())
        return [files[i]["slug"] for i in indices if 0 <= i < len(files)][:5]
    except Exception:
        # 降级策略：如果 API 报错或 JSON 解析失败，退化为文本关键词模糊匹配
        return fallback_keyword_match(recent_dialogue, files)

def inject_memories_to_turn(messages: list):
    """在真正调用核心大模型前，将读取到的完整记忆细节注入到最新的 user 消息块中"""
    slugs = select_relevant_memories(messages)
    if not slugs:
        return
        
    memory_contents = []
    for slug in slugs:
        raw_text = (MEMORY_DIR / f"{slug}.md").read_text()
        memory_contents.append(f"<borrowed-memory slug='{slug}'>\n{raw_text}\n</borrowed-memory>")
        
    # 将细节作为附加事实上下文，塞入最后一轮 user 的消息里
    if messages and messages[-1]["role"] == "user":
        messages[-1]["content"] += "\n\n[Borrowed Deep Memories]\n" + "\n".join(memory_contents)

```

### ④ 写入层：每轮结束后的静默提取（Extractor）

不需要强求用户显式下达“记住这个”的指令，当检测到一轮交互自然收尾（模型停下且不再调用工具）时，自动触发提取器：

```python
def extract_memories(messages: list):
    """从最近的对话快照中，自动提炼并固化出新的用户偏好或项目事实"""
    dialogue = format_recent_messages(messages[-10:]) # 获取近10轮对话
    existing = "\n".join(f"- {f['name']}: {f['description']}" for f in list_memory_files())
    
    prompt = (
        "Extract new stable preferences or project facts from the dialogue.\n"
        "Return a JSON array: [{'name', 'type', 'description', 'body'}].\n"
        "If the fact is already covered or nothing new exists, return [].\n\n"
        f"Existing memories:\n{existing}\n\nDialogue:\n{dialogue[:4000]}"
    )
    
    response = client.messages.create(model=MODEL, messages=[{"role": "user", "content": prompt}])
    try:
        new_mems = json.loads(re.search(r'\[.*?\]', extract_text(response.content)).group())
        for mem in new_mems:
            write_memory_file(mem["name"], mem["type"], mem["description"], mem["body"])
    except Exception:
        pass

```

### ⑤ 整理层：低频去重与矛盾合并 (`Dream`)

随着记忆文件积累，当总数量达到阈值（如 10 个）时，系统启动**低频去重合并管线**（在 Claude Code 中这一步被称为 **“Dream（做梦/深思）”**）：

```python
CONSOLIDATE_THRESHOLD = 10

def consolidate_memories():
    """低频合并去重：当文件数多于 10 个时触发，让 LLM 吞噬所有老文件并重写出一套更精简、无冲突的新记忆"""
    files = list_memory_files()
    if len(files) < CONSOLIDATE_THRESHOLD:
        return # 数量未达标，直接节流跳过

    # 3. 彻底清空原有目录，用 LLM 提纯后的精简结果重新调用 write_memory_file 刷盘
```

## 4. 教学版 vs. 生产级 Claude Code 源码的差异

在真实的 **Claude Code** 生产级实现中，记忆模块是一套跨设备同频的分布式持久层：

* **“做梦”机制的四层门控防御 (The 4 Gates of Dream)：** 教学版只通过一个简单的文件数阈值（`CONSOLIDATE_THRESHOLD`）来决定要不要整理。而在实际生产源码中，为了极力避免频繁调用 LLM 整理引发 API 账单暴涨，设计了严格的 **4 层复合门控锁**：
1. **时间步长控制：** 距离上次 Dream 必须过去至少 12 小时。
2. **扫描节流控制：** 检查新增行数与文件改动比率是否过载。
3. **独立会话隔离：** 绝不阻塞用户当前的前台 CLI 交互，Dream 进程会被派发（spawn）到完全不占用 TTY 的独立后台幽灵会话（Ghost Session）中异步默默运行。
4. **物理文件排他锁 (`proper-lockfile`)：** 刷盘时锁定 `.claude/memory/` 目录，防止前后台同时读写引发 TOCTOU 并发冲突。


* **全局唯一的通用提示词缓存对齐 (Prompt Cache Lockstep)：** 在真实源码里，`buildSystemPrompt()` 内的 `MEMORY.md` 索引输出被限制了最大字符和严格的字典序排序。这样做是为了确保一旦记忆库稳定下来，这个 System Prompt 块在多达数天的多次 CLI 启动中能**产生完全一致的哈希签名**，从而让大模型全量命中 Anthropic 的 Prompt Cache，帮企业节省超过 **90%** 的长会话底座 Token 费用。
* **跨设备全局同步兼容：** 生产级的记忆底层支持将文件路径与系统的本地数据同步层（如 iCloud 或企业共享网络驱动器）挂钩，使得同一个开发者在笔记本和台式机上拉起 Claude Code 时，能无缝共享同一套开发偏好记忆。
