> _"没有计划的 agent 走哪算哪"_ -- 先列步骤再动手, 完成率翻倍。

## 问题

多步任务中, 模型会丢失进度 -- 重复做过的事、跳步、跑偏。对话越长越严重: 工具结果不断填满上下文, 系统提示的影响力逐渐被稀释。一个 10 步重构可能做完 1-3 步就开始即兴发挥, 因为 4-10 步已经被挤出注意力了。

## 解决方案

```
+--------+     +-------+     +---------+
| User   | --> | LLM   | --> | Tools   |
| prompt |     |       |     | + todo  |
+--------+     +---+---+     +----+----+
   ^              |               |
   | tool_result  |               |
   +--------------+               |
         |                        |
   +-----+-----------+            |
   | TodoManager state |          |
   | [ ] task A        |          |
   | [>] task B <- doing|         |
   | [x] task C        |          |
   +--------------------+         |
         |                        |
   if rounds_since_todo >= 3:     |
   inject <reminder> into tool_result
```

## 工作原理

1. TodoManager 存储带状态的项目。同一时间只允许一个 `in_progress`。

```python
class TodoManager:
    def update(self, items: list) -> str:
        validated, in_progress_count = [], 0
        for item in items:
            status = item.get("status", "pending")
            if status == "in_progress":
                in_progress_count += 1
            validated.append({"id": item["id"], "text": item["text"],
                            "status": status})
        if in_progress_count > 1:
            raise ValueError("Only one task can be in_progress")
        self.items = validated
        return self.render()
```

2. `todo` 工具和其他工具一样加入 dispatch map。

```python
TOOL_HANDLERS = {
    # ...base tools...
    "todo": lambda **kw: TODO.update(kw["items"]),
}
```

3. nag reminder: 模型连续 3 轮以上不调用 `todo` 时注入提醒。

```python
if rounds_since_todo >= 3 and messages:
    last = messages[-1]
    if last["role"] == "user" and isinstance(last.get("content"), list):
        last["content"].insert(0, {
            "type": "text",
            "text": "<reminder>Update your todos.</reminder>",
        })
```

"同时只能有一个 in_progress" 强制顺序聚焦。nag reminder 制造问责压力 -- 你不更新计划, 系统就追着你问。

# 新版 TodoWrite

根据 [Learn Claude Code](https://learn.shareai.run/zh/) 课程第 **s05 TodoWrite（规划与协调）** 章节的正文，其核心概念、工作原理与教学版代码实现提炼如下：

---

## 1. 核心痛点与解决思路

* **痛点：** 智能体在面对复杂的多步骤任务时，如果没有显式的计划，极易“走哪算哪”。例如重构代码时，大模型修改了前几个文件，但在运行测试并修复报错的过程中，注意力会被报错完全吸引，从而遗忘最初的整体重构目标。随着上下文变长，系统提示词（System Prompt）的影响力被稀释，Agent 容易开始即兴发挥、丢三落四。
* **解决思路：** **“先计划，再动手”**。通过引入一个纯粹的规划工具 `todo_write`（它不具备任何读写文件或运行命令的能力），强迫 Agent 在动手前先理清思路，并让长任务的执行进度在每轮循环中保持显式可见和可纠正。

---

## 2. 核心工作原理

1. **显式看板：** `todo_write` 接收一个带有状态（`pending` | `in_progress` | `completed`）的任务列表，保存在当前进程内存中，并在终端动态输出直观的进度看板。
2. **Nag Timer 提醒机制（教学版独有）：** 为了防止模型把计划列出来后就“抛之脑后”，系统在外层循环中加入计数器（`rounds_since_todo`）。如果模型连续 3 轮没有更新或查看它的 TODO 状态，循环会自动拦截并强制注入一条 `<reminder>Update your todos.</reminder>`，逼迫模型校准进度。

---

## 3. 核心功能代码实现

### ① 工具 Schema 定义

定义 `todo_write` 工具，约束模型输入必须是结构化的任务数组：

```python
TOOLS = [
    # ... 其他基础文件读写工具 ...
    {
        "name": "todo_write",
        "description": "Create and manage a task list to track long-running work. Use this before starting and to update progress.",
        "input_schema": {
            "type": "object",
            "properties": {
                "todos": {
                    "type": "array",
                    "items": {
                        "type": "object",
                        "properties": {
                            "content": {"type": "string"},
                            "status": {"type": "string", "enum": ["pending", "in_progress", "completed"]}
                        },
                        "required": ["content", "status"]
                    }
                }
            },
            "required": ["todos"]
        }
    }
]

```

### ② 工具具体实现与状态维护 (`run_todo_write`)

工具仅操作内存中的全局变量，并实时格式化打印看板，不增加任何实际执行能力，只增加规划能力：

```python
# 进程内内存任务看板
CURRENT_TODOS: list[dict] = []

def run_todo_write(todos: list[dict]) -> str:
    global CURRENT_TODOS
    CURRENT_TODOS = todos

    lines = ["\n## Current Tasks"]
    for t in CURRENT_TODOS:
        # 不同的状态对应不同的终端状态图标
        icon = {"pending": " ", "in_progress": "▸", "completed": "✓"}[t["status"]]
        lines.append( f"  [ {icon} ] {t['content']}" )
        
    print("\n".join(lines)) # 在终端打印出来供人类和系统观测
    return f"Updated {len(CURRENT_TODOS)} tasks"

# 注册到工具分发表
TOOL_HANDLERS["todo_write"] = run_todo_write

```

### ③ 带有 Nag Timer 机制的 Agent Loop 内核

在主循环中，结合计数器实现自动提醒功能：

```python
def run_agent_loop(user_prompt):
    messages = [{"role": "user", "content": user_prompt}]
    rounds_since_todo = 0  # 距离上一次调用 todo_write 的轮数计数器

    while True:
        # 核心逻辑 ①：Nag 催促提醒。如果连续 3 轮装聋作哑，强制注入提醒
        if rounds_since_todo >= 3 and messages:
            messages.append({
                "role": "user",
                "content": "<reminder>Update your todos. Ensure completed tasks are marked, and current work is set to in_progress.</reminder>"
            })
            rounds_since_todo = 0 # 重置计数

        # 调用 LLM
        response = client.messages.create(model=MODEL, messages=messages, tools=TOOLS)
        messages.append({"role": "assistant", "content": response.content})

        if response.stop_reason != "tool_use":
            break

        # 核心逻辑 ②：检测当前轮次模型是否调用了 todo_write
        called_todo = any(block.name == "todo_write" for block in response.content if block.type == "tool_use")
        if called_todo:
            rounds_since_todo = 0  # 只要调用了，计数器就清零
        else:
            rounds_since_todo += 1  # 没调用，计数器递增

        # 执行工具分发
        results = []
        for block in response.content:
            if block.type == "tool_use":
                handler = TOOL_HANDLERS.get(block.name)
                output = handler(**block.input)
                results.append({"type": "tool_result", "tool_use_id": block.id, "content": output})
        
        messages.append({"role": "user", "content": results})

```

## 4. 教学版 vs. 生产级 Claude Code 源码的差异

在真实的 [Claude Code 源码](https://learn.shareai.run/zh/s05/) 中，规划机制升级为了两套系统并存，应对的复杂度高得多：

* **TodoWrite (V1) 与 Task System (V2) 的平滑切换：** 源码中存在两套内核（`tasks.ts`）。V1 即为上面演示的平铺式内存 Todo 列表（对应 `TodoWriteTool.ts`）；V2 则升级为了支持文件持久化、`blockedBy` 依赖图及分布式原子锁的完整 [Task System](https://learn.shareai.run/zh/s12/)。系统通过 `isTodoV2Enabled()` 自动识别：交互式终端默认开启高阶 V2，非交互的 SDK 脚本中默认开启轻量 V1。
* **UI 状态感知与 Spinner 挂钩：** 教学版只负责将看板 `print` 到控制台。生产级 Claude Code 的 Todo 结构体中包含一个 `activeForm` 字段，当某个任务进入 `in_progress` 时，CLI 终端框架会捕获该字段并自动在终端下方渲染出带有对应文字的动态加载动画（Spinner），提供极佳的人机交互感。
* **提醒机制（Nudge）的差异：** 教学版简单粗暴地使用“固定 3 轮计数器”注入提醒。而 Claude Code 实际源码中没有固定轮数逻辑，它的策略更聪明（`TodoWriteTool.ts:72-107`）：当检测到列表内所有任务均已转为 `completed`、但模型仍不退出、且没有生成任何 `verification`（验证通过）的条目时，系统会精准追加一条验证提示，防止模型无限闲逛。
