> _不是把所有知识永远塞进 prompt，而是在需要的时候再加载正确那一份。_

## 这一章要解决什么问题

到了 `s04`，你的 agent 已经会：

* 调工具
* 做会话内规划
* 把大任务分给子 agent

接下来很自然会遇到另一个问题：

> 不同任务需要的领域知识不一样。

例如：

* 做代码审查，需要一套审查清单
* 做 Git 操作，需要一套提交约定
* 做 MCP 集成，需要一套专门步骤

如果你把这些知识包全部塞进 system prompt，就会出现两个问题：

1. 大部分 token 都浪费在当前用不到的说明上
2. prompt 越来越臃肿，主线规则越来越不清楚

所以这一章真正要做的是：

**把"长期可选知识"从 system prompt 主体里拆出来，改成按需加载。**

## 先解释几个名词

### 什么是 skill

这里的 `skill` 可以先简单理解成：

> 一份围绕某类任务的可复用说明书。

它通常会告诉 agent：

* 什么时候该用它
* 做这类任务时有哪些步骤
* 有哪些注意事项

### 什么是 discovery

`discovery` 指"发现有哪些 skill 可用"。

这一层只需要很轻量的信息，例如：

* skill 名字
* 一句描述

### 什么是 loading

`loading` 指"把某个 skill 的完整正文真正读进来"。

这一层才是昂贵的，因为它会把完整内容放进当前上下文。

## 最小心智模型

把这一章先理解成两层：

```
第 1 层：轻量目录
  - skill 名称
  - skill 描述
  - 让模型知道"有哪些可用"

第 2 层：按需正文
  - 只有模型真正需要时才加载
  - 通过工具结果注入当前上下文
```

可以画成这样：

```
system prompt
|
+-- Skills available:
    - code-review: review checklist
    - git-workflow: branch and commit guidance
    - mcp-builder: build an MCP server
```

当模型判断自己需要某份知识时：

```
load_skill("code-review")
|
v
tool_result
|
v
完整审查说明
```

这就是这一章最核心的设计。

## 关键数据结构

### 1. SkillManifest

先准备一份很轻的元信息：

```json
{
  "name": "code-review",
  "description": "Checklist for reviewing code changes",
}
```

它的作用只是让模型知道：这份 skill 存在，并且大概是干什么的。

### 2. SkillDocument

真正被加载时，再读取完整内容：

```json
{
  "manifest": {...},
  "body": "... full skill text ...",
}
```

### 3. SkillRegistry

更清楚的方式是做一个统一注册表：

```python
registry = {
    "code-review": SkillDocument(...),
    "git-workflow": SkillDocument(...),
}
```

它至少要能回答两个问题：

1. 有哪些 skill 可用
2. 某个 skill 的完整内容是什么

## 最小实现

### 第一步：把每个 skill 放成一个目录

```
skills/
  code-review/
    SKILL.md
  git-workflow/
    SKILL.md
```

### 第二步：从 `SKILL.md` 里读取最小元信息

```python
class SkillRegistry:
    def __init__(self, skills_dir):
        self.skills = {}
        self._load_all()

    def _load_all(self):
        for path in skills_dir.rglob("SKILL.md"):
            meta, body = parse_frontmatter(path.read_text())
            name = meta.get("name", path.parent.name)
            self.skills[name] = {
                "manifest": {
                    "name": name,
                    "description": meta.get("description", ""),
                },
                "body": body,
            }
```

### 第三步：把 skill 目录放进 system prompt

```python
SYSTEM = f"""You are a coding agent.

Skills available:
{SKILL_REGISTRY.describe_available()}
"""
```

注意这里放的是**目录信息**，不是完整正文。

### 第四步：提供一个 `load_skill` 工具

```python
TOOL_HANDLERS = {
    "load_skill": lambda **kw: SKILL_REGISTRY.load_full_text(kw["name"]),
}
```

当模型调用它时，把完整 skill 正文作为 `tool_result` 返回。

### 第五步：让 skill 正文只在当前需要时进入上下文

核心思想：平时只展示"有哪些知识包"，真正工作时才把那一包展开。

## skill、memory、CLAUDE.md 的边界

### skill

可选知识包。只有在某类任务需要时才加载。

### memory

跨会话仍然有价值的信息。它是系统记住的东西，不是任务手册。

### CLAUDE.md

更稳定、更长期的规则说明。它通常比单个 skill 更"全局"。

一个简单判断法：

* 这是某类任务才需要的做法或知识：`skill`
* 这是需要长期记住的事实或偏好：`memory`
* 这是更稳定的全局规则：`CLAUDE.md`

## 它如何接到主循环里

这一章以后，system prompt 不再只是一段固定身份说明。

它开始长出一个很重要的新段落：

* 可用技能目录

而消息流里则会出现新的按需注入内容：

* 某个 skill 的完整正文

也就是说，系统输入现在开始分成两层：

```
稳定层：
  身份、规则、工具、skill 目录

按需层：
  当前真的加载进来的 skill 正文
```

## 初学者最容易犯的错

### 1. 把所有 skill 正文永远塞进 system prompt

这样会让 prompt 很快臃肿到难以维护。

### 2. skill 目录信息写得太弱

如果只有名字，没有描述，模型就不知道什么时候该加载它。

### 3. 把 skill 当成"绝对规则"

skill 更像"可选工作手册"，不是所有轮次都必须用。

### 4. 把 skill 和 memory 混成一类

skill 解决的是"怎么做一类事"，memory 解决的是"记住长期事实"。

### 5. 一上来就讲太多多源加载细节

教学主线真正要先讲清的是：**轻量发现，重内容按需加载。**

## 教学边界

这章只要先守住两层就够了：

* 轻量发现：先告诉模型有哪些 skill
* 按需深加载：真正需要时再把正文放进输入

## 一句话记住

**Skill 系统的核心，不是"多一个工具"，而是"把可选知识从常驻 prompt 里拆出来，改成按需加载"。**

# 新版 Skills

根据 [Learn Claude Code](https://learn.shareai.run/zh/s07/) 课程第 **s07 Skills（按需知识加载）** 章节的正文，其核心概念、工作原理与教学版代码实现提炼如下：

---

## 1. 核心痛点与解决思路

* **痛点：** 随着项目规模扩大，团队通常会积累大量的规范文档，例如《React 组件开发规范》（2000行）、《SQL 编写风格指南》（1500行）、《API 设计规约》（3000行）。如果直接把这些上万行的文档全部硬编码塞进系统提示词（System Prompt）中，大模型每轮交互都会白白重复消耗巨大的 Token 成本，且大量无关知识会严重稀释模型的注意力。
* **解决思路：** **“用到时再加载，别全塞 prompt 里”**。采用两级加载（On-demand loading）架构。启动时只扫描所有技能的摘要（目录）注入 System Prompt（极轻量），当模型在任务中评估自己需要某项专业规范时，才主动调用 `load_skill` 工具将完整文档通过 `tool_result` 或 `messages` 注入当前上下文。

---

## 2. 核心工作原理

系统在架构上分为两层设计，完美平衡了“感知力”与“Token 成本”：

| 层级 | 存储位置 | 触发时机 | 成本代价 |
| --- | --- | --- | --- |
| **1. 技能目录 (Catalog)** | System Prompt | 框架启动时自动扫描注入 | 每项技能约 100 Tokens，每轮调用常驻，保持模型全局感知 |
| **2. 完整内容 (Content)** | `tool_result` / 消息历史 | 模型主动触发 `load_skill(name)` | 每项技能约 2000 Tokens，仅在需要时一次性消耗 |

---

## 3. 核心功能代码实现

### ① 技能目录结构

本地技能以模块化文件夹形式存储在 `skills/` 目录下，每个技能包含一个 `SKILL.md` 规范文件，头部带有 YAML frontmatter 标记元数据：

```
skills/
  ├── react-style/
  │     └── SKILL.md  (包含 # name: react-style)
  └── sql-style/
        └── SKILL.md  (包含 # name: sql-style)

```

### ② 启动时静态扫描与目录注入（第一级）

系统启动时自动运行一次，解析规范元数据并将其组装进全局系统提示词中：

```python
from pathlib import Path

SKILLS_DIR = Path("skills")
SKILL_REGISTRY: dict[str, dict] = {}  # 全局技能注册表，防路径遍历安全隐患

def _parse_frontmatter(raw_text: str) -> tuple[dict, str]:
    """教学版简化解析：提取前几行中的 name 和 description"""
    meta = {}
    lines = raw_text.split("\n")
    for line in lines[:5]:
        if line.startswith("# name:"):
            meta["name"] = line.replace("# name:", "").strip()
        elif line.startswith("# description:"):
            meta["description"] = line.replace("# description:", "").strip()
    return meta, raw_text

def _scan_skills():
    """启动时运行一次，填充注册表"""
    if not SKILLS_DIR.exists(): 
        return
    for d in sorted(SKILLS_DIR.iterdir()):
        if not d.is_dir(): 
            continue
        manifest = d / "SKILL.md"
        if manifest.exists():
            raw = manifest.read_text()
            meta, body = _parse_frontmatter(raw)
            name = meta.get("name", d.name)
            desc = meta.get("description", "No description provided.")
            # 完整内容存入内存注册表
            SKILL_REGISTRY[name] = {"name": name, "description": desc, "content": raw}

# 1. 启动时单例加载
_scan_skills()

def list_skills() -> str:
    """生成极简的目录文本"""
    return "\n".join(f"- **{s['name']}**: {s['description']}" for s in SKILL_REGISTRY.values())

def build_system_prompt() -> str:
    catalog = list_skills()
    return (
        f"You are a coding agent.\n"
        f"Skills available to you:\n{catalog}\n"
        f"CRITICAL: If a task requires specific guidelines, you MUST call load_skill(name) first."
    )

# 最终注入给 LLM 的常驻 System Prompt
SYSTEM = build_system_prompt()

```

### ③ 运行时动态技能加载工具（第二级）

模型在需要时调用此工具，工具不走物理文件路径，而是直接查注册表返回，彻底杜绝路径穿越（`../`）攻击：

```python
# 注册到工具池中的 Schema 定义
TOOLS = [
    # ... 其他基础文件和 Bash 工具 ...
    {
        "name": "load_skill",
        "description": "Load the full, detailed instructions and style guides for a specific skill.",
        "input_schema": {
            "type": "object",
            "properties": {
                "name": {"type": "string", "description": "The name of the skill to load from the catalog."}
            },
            "required": ["name"]
        }
    }
]

def run_load_skill(name: str) -> str:
    """工具具体实现：直接查注册表字典，安全可控"""
    skill = SKILL_REGISTRY.get(name)
    if not skill:
        return f"Error: Skill '{name}' not found in registry."
    
    print(f"\n[HOOK] load_skill: Loading expert system for '{name}'...")
    return skill["content"]

# 绑定到大循环的分发表中
TOOL_HANDLERS["load_skill"] = run_load_skill

```

## 4. 教学版 vs. 生产级 Claude Code 源码的差异

在真实的 [Claude Code 生产级源码](https://learn.shareai.run/zh/s07/)（如 `loadSkillsDir.ts`, `SkillTool.ts`, `bundledSkills.ts`）中，技能管理机制要精密、严苛得多：

* **多源技能聚合与条件激活 (`paths`)**：教学版只假设了一个 `skills/` 目录。真实的 Claude Code 从 9 种渠道并发加载技能（内置内置技能、用户全局配置、项目本地、MCP 远程扩展等）。此外，源码支持 **Conditional Skills（条件激活）**，其 frontmatter 包含 `paths: ["/*.sql"]` 字段。一旦人类分配的任务涉及 SQL 文件，系统会在启动时**自动为其激活并加载**对应技能，无需模型手动去 call 工具。
* **隔离上下文运行模式 (`context: 'fork'`)**：在生产级 frontmatter 中，技能可以配置 `context: 'fork'`。当模型调用此类高危或复杂的技能（如自动化测试重构）时，框架不会直接在当前主会话里平铺展开文本，而是会在底层直接衍生出一个临时的 [Subagent](https://learn.shareai.run/zh/s06/) 进程隔离运行该技能，跑完再回收。
* **严格的工具白名单限制 (`allowed-tools`)**：Claude Code 源码支持技能级别的安全门控。某个技能被加载后，其 frontmatter 中定义的 `allowed-tools: ["read_file"]` 会立刻对底层框架生效，强行**暂扣或剥夺**大模型的 `bash` 或 `write_file` 等高危写工具权限，直到该技能执行域结束才归还。
* **1% 的精细化上下文预算控制 (`getSkillListingAttachments`)**：为了防止技能列表本身撑爆 System Prompt，CC 在启动时会计算 `getSkillListingAttachments()`，将其严格限制在当前模型总上下文窗口的 **1%（上限 8000 字符）**。如果企业注册了成百上千个技能，系统会自动触发文本截断或按历史热度优先排序注入，确保底座绝对轻量。
