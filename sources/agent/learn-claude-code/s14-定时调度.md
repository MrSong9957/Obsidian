> _如果后台任务解决的是"稍后回来拿结果"，那么定时调度解决的是"将来某个时间再开始做事"。_

## 这一章要解决什么问题

`s13` 已经让系统学会了把慢命令放到后台。但后台任务默认还是"现在就启动"。

很多真实需求并不是现在做，而是：

* 每天晚上跑一次测试
* 每周一早上生成报告
* 30 分钟后提醒我继续检查某个结果

所以这一章要加上的能力是：

**把一条未来要执行的意图，先记下来，等时间到了再触发。**

## 最小心智模型

```
1. 调度记录
2. 定时检查器
3. 通知队列

schedule_create(...)
-> 把记录写到列表或文件里
-> 后台检查器每分钟看一次"现在是否匹配"
-> 如果匹配，就把 prompt 放进通知队列
-> 主循环下一轮把它当成新的用户消息喂给模型
```

**定时调度并不是另一套 agent。它最终还是回到同一条主循环。**

## 最小实现

### 第一步：允许创建一条调度记录

```python
def create(self, cron_expr: str, prompt: str, recurring: bool = True):
    job = {
        "id": new_id(),
        "cron": cron_expr,
        "prompt": prompt,
        "recurring": recurring,
        "created_at": time.time(),
        "last_fired_at": None,
    }
    self.jobs.append(job)
    return job
```

### 第二步：写一个定时检查循环

```python
def check_loop(self):
    while True:
        now = datetime.now()
        self.check_jobs(now)
        time.sleep(60)
```

### 第三步：时间到了就发通知

```python
def check_jobs(self, now):
    for job in self.jobs:
        if cron_matches(job["cron"], now):
            self.queue.put({
                "type": "scheduled_prompt",
                "schedule_id": job["id"],
                "prompt": job["prompt"],
            })
            job["last_fired_at"] = now.timestamp()
```

### 第四步：主循环像处理后台通知一样处理定时通知

```python
notifications = scheduler.drain()
for item in notifications:

        "role": "user",

    })
```

# 新版 Cron Scheduler （定时任务调度）

根据 [Learn Claude Code](https://learn.shareai.run/zh/s14/) 课程第 **s14 Cron Scheduler（定时任务调度）** 章节的正文，其核心概念、工作原理与教学版代码实现提炼如下：

---

## 1. 核心痛点与解决思路

* **痛点：** 软件工程中有很多工作是**周期性、重复性**的（例如“每天清晨自动审查 open 的 PR”、“每周五下午生成周报总结”、“每两小时同步一次 upstream 仓库”）。如果让模型自己去“记住”这些定时任务，一旦会话结束或用户下线，这些任务就会彻底遗失。大模型具有无状态性，无法扮演定时器的角色。
* **解决思路：** **“周期性工作由 Harness（外壳运行时）创建并驱动，而不是让模型去记忆（Recurring work should be created by the harness, not remembered by the model）”**。建立一套**独立的本地定时调度器（Cron Scheduler）**。大模型只负责将用户的自然语言指令（如“每个工作日帮我审查 PR”）转化为结构化的定时任务卡片（Schedule Card）并录入配置，而由外壳系统在后台通过时间状态机持久化跟踪并按时触发，实现“一次设定，无人值守续航”。

---

## 2. 三轨内核工作原理

系统通过底层的三个核心组件协同，将自然语言转化为确定性的定时执行流：

| 组件 / 概念 | 物理角色 | 核心职责 |
| --- | --- | --- |
| **1. Schedule Book** | 任务配置账本 | 存储持久化的结构化定时规则（包含自然语言 Prompt 原型与 Cron/间隔表达式）。 |
| **2. Due Queue** | 到期等待队列 | 时间轮（Time Wheel）或 Watcher 线程持续扫描账本，一旦发现当前时间满足触发条件，立刻将任务推入到期队列。 |
| **3. Agent Inbox** | 智能体收件箱 | 只要主线程 Agent Loop 处于空闲（Available）状态，它就会自动从队列中“收件”，拉起会话静默执行任务。 |

## 3. 核心功能代码实现（645 LOC 教学版内核）

### ① 数据结构与本地账本持久化

定义单个定时卡片 `ScheduleCard` 及核心管理类：

```python
import json
import time
from dataclasses import dataclass, asdict
from pathlib import Path

SCHEDULE_FILE = Path(".cron_schedules.json")

@dataclass
class ScheduleCard:
    id: str
    prompt: str          # 核心执行指令，如 "Review open PRs"
    cron_expr: str       # 简化版 Cron 策略，如 "every_day", "every_minute"
    last_run: float = 0.0 # 上次运行的时间戳

class ScheduleBook:
    def __init__(self):
        self.cards: dict[str, ScheduleCard] = {}
        self.load()

    def load(self):
        if SCHEDULE_FILE.exists():
            data = json.loads(SCHEDULE_FILE.read_text())
            for k, v in data.items():
                self.cards[k] = ScheduleCard(**v)

    def save(self):
        data = {k: asdict(v) for k, v in self.cards.items()}
        SCHEDULE_FILE.write_text(json.dumps(data, indent=2))

    def add_schedule(self, card_id: str, prompt: str, cron_expr: str):
        self.cards[card_id] = ScheduleCard(id=card_id, prompt=prompt, cron_expr=cron_expr)
        self.save()

```

### ② 运行时配置工具（Tools）

将账本操作封装为工具供大模型调用，实现“自然语言 $\rightarrow$ 定时卡片”的转化：

```python
BOOK = ScheduleBook()

TOOLS = [
    {
        "name": "create_cron_schedule",
        "description": "Register a recurring automation schedule card based on user prompts.",
        "input_schema": {
            "type": "object",
            "properties": {
                "card_id": {"type": "string", "description": "Unique slug like 'daily-pr-review'"},
                "prompt": {"type": "string", "description": "The exact goal the agent should accomplish when triggered"},
                "cron_expr": {"type": "string", "enum": ["every_minute", "every_hour", "every_day"]}
            },
            "required": ["card_id", "prompt", "cron_expr"]
        }
    }
]

def run_create_cron_schedule(card_id: str, prompt: str, cron_expr: str) -> str:
    BOOK.add_schedule(card_id, prompt, cron_expr)
    return f"Successfully established recurring card '{card_id}'. The system will now execute it on schedule."

TOOL_HANDLERS = {"create_cron_schedule": run_create_cron_schedule}

```

### ③ 后台时间轮 Watcher 与 Agent Inbox 闭环

利用守护线程充当 Weekly Clock / Time Wheel 持续扫描，并在前台安全节点唤醒智能体执行：

```python
import queue

# 充当 Due Queue + Agent Inbox 缓冲带
AGENT_INBOX = queue.Queue()

def _should_trigger(card: ScheduleCard, now: float) -> bool:
    """时间戳级联判满状态机"""
    elapsed = now - card.last_run
    if card.cron_expr == "every_minute" and elapsed >= 60: return True
    if card.cron_expr == "every_hour" and elapsed >= 3600: return True
    if card.cron_expr == "every_day" and elapsed >= 86400: return True
    return False

def cron_watcher_daemon():
    """后台独立守护进程：高精度时间扫描车道"""
    print("[CRON] Clock watcher thread initialized.")
    while True:
        now = time.time()
        for card in list(BOOK.cards.values()):
            if _should_trigger(card, now):
                print(f"\n[CLOCK ⏰] Schedule triggered: {card.id}! Pushing to Inbox.")
                AGENT_INBOX.put(card)
                card.last_run = now # 乐观锁占位，防止重复投递
                BOOK.save()
        time.sleep(5) # 每 5 秒扫描一次时间轮

def run_cron_orchestrator():
    """主线程：前台空闲时消费 Inbox"""
    import threading
    # 启动后台守护时钟
    t = threading.Thread(target=cron_watcher_daemon, daemon=True)
    t.start()
    
    print("[SYSTEM] Agent main loop is available. Waiting for user input or cron cards...")
    while True:
        try:
            # 采用非阻塞或短超时拉取，兼顾用户主动交互（CLI Prompt）与定时任务
            card: ScheduleCard = AGENT_INBOX.get(timeout=1)
            print(f"\n🤖 [AUTOMATION EXECUTE] Activating cron card: {card.id}")
            
            # 为定时任务自动组装干净的会话沙箱环境并执行
            automation_history = [{
                "role": "user", 
                "content": f"[TIMED AUTONOMOUS TASK] Goal: {card.prompt}. Execute thoroughly and log the outcome."
            }]
            
            # 默默跑完核心的 Agent 攻坚循环 (s02)
            # run_single_agent_loop(automation_history)
            print(f"🎉 [AUTOMATION DONE] Card {card.id} executed successfully. Back to idle.")
            AGENT_INBOX.task_done()
        except queue.Empty:
            # 收件箱目前为空，若有用户临时的 CLI 输入则在此行处理
            pass

```

## 4. 教学版 vs. 生产级 Claude Code 源码的差异

在真实的 **Claude Code** 工业级生产源码中，定时调度的复杂度和防抖防脏设计有着严格的要求：

* **企业级持久化 Cron 表达式解析器 (`cron-parser`)：** 教学版只支持简化版的 `every_minute` 枚举。CC 真实源码中集成了完备的标准五段式/六段式 Cron 解析引擎（支持 `0 9 * * 1-5` 这种“每个工作日早上 9 点”的标准企业级语义）。系统还具备 **Timezone Alignment（时区对齐）** 能力，会自动读取开发者本地系统的 `process.env.TZ` 或本地硬件时钟，防止开发者在跨国出差、或远程 SSH 服务器时因为服务器 UTC 时间差引发凌晨爆表打扰。
* **冷启动补偿追赶机制 (`Missed Trigger Catch-up`)：** 这是一个关键的工业级防御。如果用户关闭了笔记本电脑或掐断了 CLI 进程，导致某个每天下午 3 点跑的重构脚本错过了触发点，教学版代码在下次开机时会直接跳过。而 CC 源码中包含 **`catchUpMissedSchedules()`** 算法：在 CLI 每次冷启动的瞬间，系统会比对当前的物理时间戳与 `.claude/schedules.json` 中记录的 `expectedNextRun`。如果判定在上一次关机期间错过了某次执行，它会立刻弹窗询问人类，或在后台低优先级默默“补跑（Catch-up）”那次丢失的对齐任务。
* **绝对单例互斥锁守护 (`process.pid` 物理重入锁)：** 定时任务是在后台静默跑的，如果开发者同时拉起了两个终端或者启动了多个独立项目工程，多个前台运行时读取同一个持久化账本，会导致同一项 PR 审查任务在同一秒被触发多次。真实的 Claude Code 在启动 Watcher 时会强行向系统注册一个物理 **`.lock` 文件排他锁** 并写入当前的 `process.pid`。任何衍生出的子进程在试图操纵该定时账本前，都必须通过单例模式（Singleton）向主互斥锁报备，彻底杜绝了并发重入导致的代码污染风险。
