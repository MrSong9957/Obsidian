# 会话持久化实测坑（terminal-chat 007，2026-10-10）

母本 openai/codex rollout 层的本地化实现（分支 dev/007-session-persistence）。全部坑已实测验证，证据在仓库 logs/2026-10-10-007-implementation.md。

## 写入纪律

- **提交点必须定义在"含 \n 的整行 write_all 成功"**：write_all 失败可能已写部分字节（RLIMIT_FSIZE 下 Linux 先写满限额再返回 EFBIG），没有 durable_len 截回，补写会重复或粘连。
- **RLIMIT_FSIZE 下的 ftruncate 缩小恒成功**（扩展到限额之上也成功，只有超过限额的扩展失败）——"截回失败→停用"分支在本环境不可注入，只能靠同族真实停用路径（行超限/创建失败）覆盖。
- **"打印一次错误"与"退出排空必须报错"冲突**：排空是最后机会，不能被 once 过滤器吞掉——拆 raw flush 与打印纪律两层。
- **内存历史即待写缓冲**：切换会话（/resume 丢弃确认）前必须先排空旧待写段，否则旧记录既没落盘又随内存被丢。

## 锁与装载

- **锁顺序：打开即锁→同一 fd 持锁装载/尾置/追加**。先装载后取锁的降级方会截掉活动写者未提交的半行。
- **降级只读零修改**：不补换行、不截断、不追加；写者进行中的半行按坏行跳过即可（EOF 即行尾的装载规则使这成为安全投影）。
- **结果归属按文件顺序分组**：被拒批（重复 id 判坏）仍是分组边界——把被拒批的紧随结果贴给前批悬空调用＝伪造执行结果。测试要演示这一点，被拒批结果的 id 必须恰与前批调用相同，否则测不到。
- **修复只表达未知**：结果缺失＝副作用可能已发生，文案写"未执行"就是编造事实。
- **会话文件表征与协议格式不同**：持久层是平铺 {"id","name","arguments"}，协议是嵌套 {"id","type","function":{…}}——种子文件用错格式会静默跳行。

## 测试技术

- **PTY 测试 send 双重换行**：harness 的 send(line) 自补 \n，调用方再传带 \n 的参数＝每条输入多一空行，确认流错位且难排查（echo 顺序与消费顺序不同）。wait 要带 consumed 游标只匹配新输出。
- **管道模式没有提示符**（rustyline 非 tty 不打印 "你> "）；重复运行时审计静默（文件已 0600 不再收紧）——就绪同步要用横幅＋短沉降。
- **RLIMIT 受限 CLI 首轮会写 auto_catalog.json**（配置初始化在审计/命令之前）——受限运行前先无限制跑一次 /models 预初始化。
- **大历史替换后的行为验证轮会被 10 MiB 请求上限本地拒绝**——行为断言要在请求可发的会话规模（≤几 MiB）上做。
- **变异测试暴露测试空转**：M3（被拒批不闭合）存活直到把测试结果 id 改成与前批相同——断言要能区分"碰巧对"和"机制对"。

## 注入与环境

- **时钟/pid 注入提供者（TCHAT_SESSION_TS/PID）必须进 .env 信任根跳过名单**：否则项目 .env 可固定时间戳，破坏 auto 文件名"字典序＝时间序"的最近会话选择。
- **chattr +i 在容器内无权限**（需 CAP_LINUX_IMMUTABLE）；SIGXFSZ 默认终止进程，注入 EFBIG 必须同时 SIG_IGN。
