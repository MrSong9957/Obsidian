# s06 上下文压缩 -- 让 Agent 永远干下去

> 源码：`agents/s06_context_compact.py`

## 核心问题

Agent 的对话历史（messages 列表）会越来越长。每轮工具调用的输入输出都塞在里面。
当 token 数逼近上下文窗口上限时，Agent 就没法继续工作了 -- API 会报错，或者模型开始"忘记"前面的指令。

**比喻**：想象你的笔记本只有固定页数。写满了就得擦掉一些，但得把重点抄到新页上，才能继续记笔记。

## 解决方案：三层压缩

```
每轮结束时：
+------------------+
| 工具返回结果      |
+------------------+
        |
        v
[第 1 层: micro_compact]        <-- 每轮静默执行
  把超过 3 条的旧 tool_result 替换为占位符
  如 "[Previous: used bash]"
        |
        v
[检查: token > 50000?]
   |               |
   否              是
   |               |
   v               v
继续           [第 2 层: auto_compact]
                 保存完整记录到 .transcripts/
                 让 LLM 写摘要
                 用 2 条消息替代所有历史
                      |
                      v
              [第 3 层: compact 工具]
                 模型主动调用 compact 工具
                 效果同 auto，手动触发
```

三层的设计哲学：
- **第 1 层**：无感、低成本，像自动清理浏览器缓存
- **第 2 层**：有成本（要调一次 LLM 做摘要），但保住了关键信息
- **第 3 层**：把控制权交给模型自己，它觉得"该压缩了"就可以主动触发

## 完整数据流

```
用户输入
  |
  v
agent_loop(history)
  |
  +-- 1. micro_compact(messages)          # 第 1 层：静默压缩旧结果
  +-- 2. estimate_tokens(messages) > 50000?  # 检查是否需要第 2 层
  |       |-- 是: auto_compact(messages)   # 保存 + 摘要 + 替换
  |       +-- 否: 跳过
  +-- 3. 调用 LLM (client.messages.create)
  +-- 4. 处理工具调用
  |       |-- 如果调了 compact 工具: auto_compact(messages)  # 第 3 层
  |       +-- 否则正常执行
  +-- 5. 回到第 1 步
```

## 源代码逐段解析

### estimate_tokens() -- 粗略估算 token 数

```python
def estimate_tokens(messages: list) -> int:
    """Rough token count: ~4 chars per token."""
    return len(str(messages)) // 4
```

把整个 messages 列表转成字符串，算长度，除以 4。

为什么是 4？经验值 -- 英文大概 1 token 约 4 个字符，中文大约 1-2 个字符。这不是精确计算，但足够做"要不要压缩"的阈值判断。

精确计算需要用 tiktoken 库，但对于"够不够 50000"这种粗判断，这个启发式足够了。

### 第 1 层：micro_compact() -- 每轮静默压缩

```python
KEEP_RECENT = 3  # 保留最近 3 条工具结果

def micro_compact(messages: list) -> list:
    # 第一步：收集所有 tool_result 的位置
    tool_results = []
    for msg_idx, msg in enumerate(messages):
        if msg["role"] == "user" and isinstance(msg.get("content"), list):
            for part_idx, part in enumerate(msg["content"]):
                if isinstance(part, dict) and part.get("type") == "tool_result":
                    tool_results.append((msg_idx, part_idx, part))

    # 不超过 3 条就不压缩
    if len(tool_results) <= KEEP_RECENT:
        return messages

    # 第二步：建一个 tool_use_id -> tool_name 的映射表
    # 这样压缩时知道这条结果是哪个工具产生的
    tool_name_map = {}
    for msg in messages:
        if msg["role"] == "assistant":
            content = msg.get("content", [])
            if isinstance(content, list):
                for block in content:
                    if hasattr(block, "type") and block.type == "tool_use":
                        tool_name_map[block.id] = block.name

    # 第三步：替换旧结果（保留最后 3 条）
    to_clear = tool_results[:-KEEP_RECENT]
    for _, _, result in to_clear:
        if isinstance(result.get("content"), str) and len(result["content"]) > 100:
            tool_id = result.get("tool_use_id", "")
            tool_name = tool_name_map.get(tool_id, "unknown")
            result["content"] = f"[Previous: used {tool_name}]"
    return messages
```

**关键技巧**：tool_use_id 的配对。当 assistant 消息里有 `tool_use` 块（包含 id 和 name），下一条 user 消息里有对应的 `tool_result` 块（包含 tool_use_id）。通过 id 配对，就知道这条结果来自哪个工具。

**比喻**：像快递站的取件码。tool_use_id 是取件码，tool_name 是包裹内容。旧的包裹被换成一个小标签"之前收到过 bash 的包裹"。

### 第 2 层：auto_compact() -- 超阈值自动压缩

```python
THRESHOLD = 50000  # token 阈值
TRANSCRIPT_DIR = WORKDIR / ".transcripts"

def auto_compact(messages: list) -> list:
    # 第一步：把完整对话保存到磁盘（防丢失）
    TRANSCRIPT_DIR.mkdir(exist_ok=True)
    transcript_path = TRANSCRIPT_DIR / f"transcript_{int(time.time())}.jsonl"
    with open(transcript_path, "w") as f:
        for msg in messages:
            f.write(json.dumps(msg, default=str) + "\n")

    # 第二步：让 LLM 自己写摘要
    conversation_text = json.dumps(messages, default=str)[:80000]
    response = client.messages.create(
        model=MODEL,
        messages=[{"role": "user", "content":
            "Summarize this conversation for continuity. Include: "
            "1) What was accomplished, 2) Current state, 3) Key decisions made. "
            "Be concise but preserve critical details.\n\n" + conversation_text}],
        max_tokens=2000,
    )
    summary = response.content[0].text

    # 第三步：用 2 条消息替代所有历史
    return [
        {"role": "user", "content":
            f"[Conversation compressed. Transcript: {transcript_path}]\n\n{summary}"},
        {"role": "assistant", "content":
            "Understood. I have the context from the summary. Continuing."},
    ]
```

三个动作：**保存 -> 摘要 -> 替换**。

- 保存到 `.transcripts/` 目录（JSONL 格式，每行一条消息），这样信息不会真的丢失
- 用 LLM 生成摘要（有 API 调用成本，但只在超阈值时触发）
- 替换为固定的 user+assistant 对话对，模型从摘要继续工作

**为什么要保存完整记录？** 因为摘要可能有遗漏。如果后续需要翻看原始对话，文件还在磁盘上。

### 第 3 层：compact 工具 -- 模型主动触发

```python
# 工具定义
{"name": "compact", "description": "Trigger manual conversation compression.",
 "input_schema": {"type": "object",
   "properties": {"focus": {"type": "string",
     "description": "What to preserve in the summary"}}}}

# 在 agent_loop 中的处理
for block in response.content:
    if block.type == "tool_use":
        if block.name == "compact":
            manual_compact = True
            output = "Compressing..."
        ...

# 处理完所有工具调用后
if manual_compact:
    messages[:] = auto_compact(messages)  # 复用 auto_compact 的逻辑
```

模型可以传一个 `focus` 参数，告诉摘要"重点关注什么"。这给了模型对压缩过程的控制权。

### agent_loop 中的完整流程

```python
def agent_loop(messages: list):
    while True:
        # 第 1 层：每次调用 LLM 前先微压缩
        micro_compact(messages)

        # 第 2 层：检查 token 是否超阈值
        if estimate_tokens(messages) > THRESHOLD:
            print("[auto_compact triggered]")
            messages[:] = auto_compact(messages)

        # 调用 LLM
        response = client.messages.create(...)

        # 处理工具调用
        manual_compact = False
        for block in response.content:
            if block.type == "tool_use":
                if block.name == "compact":
                    manual_compact = True   # 标记，稍后处理
                ...

        # 第 3 层：手动压缩
        if manual_compact:
            messages[:] = auto_compact(messages)
```

注意 `messages[:] = ...` 的写法 -- 这是原地修改列表内容，不影响外部对 `messages` 的引用。

## Python 知识点

| 用法 | 说明 |
|------|------|
| `len(str(obj)) // 4` | 粗略估算对象大小，整数除法 |
| `messages[:] = new_list` | 原地替换列表内容，不改变引用 |
| `json.dumps(msg, default=str)` | 序列化时遇到非标准类型自动转字符串 |
| `Path.mkdir(exist_ok=True)` | 目录不存在则创建，已存在不报错 |
| `list[:-KEEP_RECENT]` | 切片取"除了最后 N 个之外的所有元素" |
| `enumerate()` | 同时获得索引和值 |
| `f.write(line + "\n")` | JSONL 格式：每行一个 JSON 对象 |

## 一句话总结

三层压缩让 Agent "有策略地遗忘"：每轮清理旧工具结果（第 1 层），超阈值时保存+摘要（第 2 层），模型也能主动触发（第 3 层），从而在有限上下文窗口内无限工作。
