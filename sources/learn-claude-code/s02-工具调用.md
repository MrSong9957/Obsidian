# s02 工具调用

## 核心问题

s01 的 Agent 只会用 bash 一个工具。但实际开发中，Agent 需要读文件、写文件、编辑代码——总不能让模型每次都 `cat`、`echo >`、`sed` 吧？

怎么给 Agent 加新工具，同时不改循环本身？

## 解决方案：工具分发表

**核心循环从 s01 一字未改。** 只是多加了几把"扳手"，然后用一个字典（dispatch map）来路由。

```
s01: agent_loop → 硬编码 if "bash" → run_bash
s02: agent_loop → TOOL_HANDLERS["bash"] → run_bash   ← 查字典
                   TOOL_HANDLERS["read_file"] → run_read
                   TOOL_HANDLERS["write_file"] → run_write
                   TOOL_HANDLERS["edit_file"] → run_edit
```

> 比喻：s01 是一个只会用锤子的工人。s02 给他发了一个工具箱——里面有锤子、螺丝刀、扳手、钳子。但他的工作流程没变：看任务 → 选工具 → 用工具 → 看结果 → 继续。


## 源代码逐段解析

### 1. safe_path：防止目录穿越

```python
from pathlib import Path

WORKDIR = Path.cwd()

def safe_path(p: str) -> Path:
    path = (WORKDIR / p).resolve()          # 拼接后转绝对路径，消除 ../ 和符号链接
    if not path.is_relative_to(WORKDIR):    # 检查结果是否还在工作目录内
        raise ValueError(f"Path escapes workspace: {p}")
    return path
```

这一关是 s01 没有的新防线。假设恶意输入 `path="../../etc/passwd"`：

```
WORKDIR / "../../etc/passwd"
→ resolve() → "/etc/passwd"
→ is_relative_to(WORKDIR) → False
→ 抛异常，拒绝访问
```

> `resolve()` 会把所有 `..`、`.`、符号链接都展开成真实的绝对路径。`is_relative_to()` 检查一个路径是否是另一个路径的子路径。这两个方法配合使用，是 Python 里做路径沙箱的标准做法。

### 2. 四个工具函数

#### run_bash（和 s01 完全一样）

```python
def run_bash(command: str) -> str:
    dangerous = ["rm -rf /", "sudo", "shutdown", "reboot", "> /dev/"]
    if any(d in command for d in dangerous):
        return "Error: Dangerous command blocked"
    try:
        r = subprocess.run(command, shell=True, cwd=WORKDIR,
                           capture_output=True, text=True, timeout=120)
        out = (r.stdout + r.stderr).strip()
        return out[:50000] if out else "(no output)"
    except subprocess.TimeoutExpired:
        return "Error: Timeout (120s)"
```

#### run_read：读文件

```python
def run_read(path: str, limit: int = None) -> str:
    try:
        text = safe_path(path).read_text()      # safe_path 先检查路径安全性
        lines = text.splitlines()                # 按行分割
        if limit and limit < len(lines):
            lines = lines[:limit] + [f"... ({len(lines) - limit} more lines)"]
            # limit 参数让模型只读前 N 行，避免一次性加载大文件
        return "\n".join(lines)[:50000]
    except Exception as e:
        return f"Error: {e}"
```

> `splitlines()` 比 `split("\n")` 更好——它能处理 `\r\n`（Windows）、`\r`（老 Mac）等各种换行符。

#### run_write：写文件

```python
def run_write(path: str, content: str) -> str:
    try:
        fp = safe_path(path)
        fp.parent.mkdir(parents=True, exist_ok=True)  # 自动创建父目录
        fp.write_text(content)                          # 写入内容
        return f"Wrote {len(content)} bytes to {path}"
    except Exception as e:
        return f"Error: {e}"
```

`mkdir(parents=True, exist_ok=True)` 是一个很实用的模式：`parents=True` 类似 `mkdir -p`，会递归创建所有中间目录；`exist_ok=True` 表示目录已存在时不报错。

#### run_edit：编辑文件

```python
def run_edit(path: str, old_text: str, new_text: str) -> str:
    try:
        fp = safe_path(path)
        content = fp.read_text()
        if old_text not in content:            # 先检查要替换的文本是否存在
            return f"Error: Text not found in {path}"
        fp.write_text(content.replace(old_text, new_text, 1))  # 只替换第一个匹配
        return f"Edited {path}"
    except Exception as e:
        return f"Error: {e}"
```

`str.replace(old, new, 1)` 的第三个参数 `1` 表示只替换第一个匹配。这很重要——如果文件里有多个相同的代码片段，全部替换可能会改错地方。

### 3. TOOL_HANDLERS：分发表

```python
TOOL_HANDLERS = {
    "bash":       lambda **kw: run_bash(kw["command"]),
    "read_file":  lambda **kw: run_read(kw["path"], kw.get("limit")),
    "write_file": lambda **kw: run_write(kw["path"], kw["content"]),
    "edit_file":  lambda **kw: run_edit(kw["path"], kw["old_text"], kw["new_text"]),
}
```

这就是整个设计的精华。模型返回一个工具调用，比如 `{name: "read_file", input: {path: "main.py"}}`，代码只需要：

```python
handler = TOOL_HANDLERS.get(block.name)       # 查字典找到对应函数
output = handler(**block.input)               # 把参数解包传进去
```

`s01` 里硬编码了 `run_bash(block.input["command"])`，只能处理一种工具。现在加新工具只需要：

1. 写一个 `run_xxx` 函数
2. 在 `TOOL_HANDLERS` 里加一行
3. 在 `TOOLS` 列表里加一个 schema 声明

**循环代码不用动。**

> `lambda **kw: ...` 是匿名函数。`**kw` 收集所有关键字参数为字典，比如调用 `handler(path="main.py", limit=50)` 时，`kw` 就是 `{"path": "main.py", "limit": 50}`。

### 4. TOOLS：告诉模型有哪些工具可用

```python
TOOLS = [
    {"name": "bash", "description": "Run a shell command.",
     "input_schema": {"type": "object", "properties": {"command": {"type": "string"}}, "required": ["command"]}},
    {"name": "read_file", "description": "Read file contents.",
     "input_schema": {"type": "object", "properties": {"path": {"type": "string"}, "limit": {"type": "integer"}}, "required": ["path"]}},
    {"name": "write_file", "description": "Write content to file.",
     "input_schema": {"type": "object", "properties": {"path": {"type": "string"}, "content": {"type": "string"}}, "required": ["path", "content"]}},
    {"name": "edit_file", "description": "Replace exact text in file.",
     "input_schema": {"type": "object", "properties": {"path": {"type": "string"}, "old_text": {"type": "string"}, "new_text": {"type": "string"}}, "required": ["path", "old_text", "new_text"]}},
]
```

每个工具声明包含三个关键信息：
- `name`：工具名称，必须和 `TOOL_HANDLERS` 的 key 一致
- `description`：告诉模型这个工具干什么用
- `input_schema`：JSON Schema，定义输入参数的类型和必填项

### 5. agent_loop——和 s01 对比

```python
def agent_loop(messages: list):
    while True:
        response = client.messages.create(
            model=MODEL, system=SYSTEM, messages=messages,
            tools=TOOLS, max_tokens=8000,
        )
        messages.append({"role": "assistant", "content": response.content})
        if response.stop_reason != "tool_use":
            return
        results = []
        for block in response.content:
            if block.type == "tool_use":
                handler = TOOL_HANDLERS.get(block.name)           # ← 唯一的区别
                output = handler(**block.input) if handler else f"Unknown tool: {block.name}"
                print(f"> {block.name}: {output[:200]}")
                results.append({"type": "tool_result", "tool_use_id": block.id, "content": output})
        messages.append({"role": "user", "content": results})
```

和 s01 唯一的区别在这一行：

```
s01: output = run_bash(block.input["command"])              # 硬编码
s02: handler = TOOL_HANDLERS.get(block.name)                # 查字典
     output = handler(**block.input) if handler else ...
```

这就是开放-封闭原则的体现：对扩展开放（加新工具），对修改封闭（不改循环）。

## 实际运行示例

用户输入：`读一下 README.md 的前 5 行`

```
=== 第 1 轮 ===

模型看到 TOOLS 里有 read_file，决定调用:
  tool_use(name="read_file", input={"path": "README.md", "limit": 5})

TOOL_HANDLERS["read_file"] → run_read("README.md", 5)

输出:
  # My Project
  A simple web application.
  ## Getting Started
  ... (47 more lines)

=== 第 2 轮 ===

模型拿到内容，整理后回复:
  "README.md 前 5 行内容如下：
   # My Project
   A simple web application.
   ## Getting Started"

stop_reason == "end_turn" → 循环结束
```

## 关键 Python 知识点

### 字典分派模式

```python
HANDLERS = {
    "add": lambda a, b: a + b,
    "sub": lambda a, b: a - b,
}
action = "add"
HANDLERS[action](3, 5)   # 8
```

用字典代替 `if/elif` 链，是 Python 里实现分派（dispatch）的惯用手法。加新分支只需加一行，不用改逻辑。

### `**` 关键字参数解包

```python
def run_read(path, limit=None): ...

kwargs = {"path": "main.py", "limit": 50}
run_read(**kwargs)       # 等价于 run_read(path="main.py", limit=50)
```

`**` 把字典展开成关键字参数。反过来，`def f(**kw)` 把传入的关键字参数收集成字典。

### pathlib 路径操作

```python
Path("dir") / "file.txt"   # Path("dir/file.txt") — 用 / 拼路径，比 os.path.join 更直观
Path(".").resolve()        # 转绝对路径
Path(".").is_relative_to(Path("/home"))  # True — 检查是否是子路径
```

---

## 一句话总结

**循环没变，只是工具箱变大了。** 分发表（TOOL_HANDLERS）把"选什么工具"和"怎么执行"解耦，加新工具不需要动核心循环。
