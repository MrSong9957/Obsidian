# s05 技能按需加载

## 核心问题

把所有领域知识塞进系统提示词 → **又贵又慢**。

假设有 10 个技能，每个完整内容 1000 tokens，全部塞进系统提示词就是 10000 tokens。而且每次对话都要带着这些 tokens，即使用户只问了一个简单问题。

## 解决方案：两层按需加载

```
Layer 1（系统提示词里）            Layer 2（调用工具时才加载）
name + description                完整技能内容（可能上千 tokens）
约 100 tokens/技能                模型用来"怎么做"
模型用来"选哪个"
```

> 比喻：像餐厅菜单——菜单上只写菜名和简介（Layer 1），客人点了菜才把完整做法给厨师（Layer 2）。

---

## 完整数据流

```
┌─────────────────────────────────────────────────┐
│  skills/                                         │
│    pdf/SKILL.md          ← 技能文件              │
│    code-review/SKILL.md                          │
│    agent-builder/SKILL.md                        │
│    mcp-builder/SKILL.md                          │
└────────────────────┬────────────────────────────┘
                     │ 启动时 SkillLoader._load_all() 扫描解析
                     ▼
┌─────────────────────────────────────────────────┐
│  self.skills = {                                 │
│    "pdf": {                                      │
│      "meta": {"name": "pdf", "description": ...},│
│      "body": "# PDF Processing Skill\n...",      │
│      "path": "skills/pdf/SKILL.md"               │
│    },                                            │
│    "code-review": { ... }                        │
│  }                                               │
└──────────┬────────────────────┬──────────────────┘
           │                    │
     get_descriptions()    get_content(name)
           │                    │
           ▼                    ▼
    写进系统提示词          工具调用时返回
    （Layer 1）            （Layer 2）
```

## 源代码逐段解析

### 1. SkillLoader 类——扫描和解析技能文件

```python
class SkillLoader:
    def __init__(self, skills_dir: Path):
        self.skills_dir = skills_dir    # 技能文件夹路径，比如 /project/skills/
        self.skills = {}                # 空字典，用来存放解析后的技能
        self._load_all()                # 初始化时就扫描所有技能文件
```

#### \_load_all()：扫描所有 SKILL.md

```python
def _load_all(self):
    if not self.skills_dir.exists():
        return                          # 文件夹不存在就跳过，不报错
    for f in sorted(self.skills_dir.rglob("SKILL.md")):
        # sorted: 按字母排序，保证每次加载顺序一致
        # rglob: 递归搜索所有子目录里的 SKILL.md

        text = f.read_text()            # 读取文件内容
        meta, body = self._parse_frontmatter(text)  # 解析出元数据和正文
        name = meta.get("name", f.parent.name)       # 元数据里有 name 就用，没有就用文件夹名
        self.skills[name] = {"meta": meta, "body": body, "path": str(f)}
```

一个 SKILL.md 文件长这样：

```
---
name: pdf
description: Process PDF files - extract text, create PDFs...
---

# PDF Processing Skill

You now have expertise in PDF manipulation...
```

`---` 之间的部分是 **YAML frontmatter**（元数据），下面是 **body**（完整技能内容）。

#### \_parse_frontmatter()：解析 YAML frontmatter

```python
def _parse_frontmatter(self, text: str) -> tuple:
    match = re.match(r"^---\n(.*?)\n---\n(.*)", text, re.DOTALL)
    # 匹配模式：开头 --- → 元数据 → --- → 正文
    # re.DOTALL 让 . 能匹配换行符

    if not match:
        return {}, text                 # 没有 frontmatter 就整个当正文

    meta = {}
    for line in match.group(1).strip().splitlines():
        if ":" in line:
            key, val = line.split(":", 1)  # split(":", 1) 只切第一刀
            meta[key.strip()] = val.strip()
    return meta, match.group(2).strip()
```

> 为什么用 `split(":", 1)` 而不是 `split(":")`？
> 因为 description 里可能包含冒号，比如 `description: Process PDF files: extract, create`。只切第一刀，保证值完整。

### 2. Layer 1：技能摘要写进系统提示词

```python
def get_descriptions(self) -> str:
    """Layer 1: short descriptions for the system prompt."""
    if not self.skills:
        return "(no skills available)"

    lines = []
    for name, skill in self.skills.items():
        desc = skill["meta"].get("description", "No description")  # 防御性取值
        tags = skill["meta"].get("tags", "")                       # 没有标签就是空字符串
        line = f"  - {name}: {desc}"
        if tags:
            line += f" [{tags}]"       # 有标签就追加显示
        lines.append(line)

    return "\n".join(lines)            # 用换行符把列表拼成字符串
```

实际拼进系统提示词后，模型看到的是：

```
You are a coding agent at /project.
Use load_skill to access specialized knowledge...

Skills available:
  - pdf: Process PDF files - extract text, create PDFs...
  - code-review: Perform thorough code reviews...
  - agent-builder: Build custom agents...
  - mcp-builder: Build MCP servers...
```

> 每个 skill 只占约 100 tokens，4 个技能加起来约 400 tokens。如果放完整内容可能要 4000+ tokens。

### 3. Layer 2：按需加载完整技能内容

```python
def get_content(self, name: str) -> str:
    """Layer 2: full skill body returned in tool_result."""
    skill = self.skills.get(name)
    if not skill:
        # 找不到 → 报错并提示可用的技能名
        return f"Error: Unknown skill '{name}'. Available: {', '.join(self.skills.keys())}"

    return f"<skill name=\"{name}\">\n{skill['body']}\n</skill>"
```

返回结果长这样：

```xml
<skill name="pdf">

# PDF Processing Skill

You now have expertise in PDF manipulation. Follow these workflows:

## Reading PDFs
**Option 1: Quick text extraction (preferred)**
```bash
pdftotext input.pdf -
```
...
</skill>
```

> 为什么用 XML 标签包裹？这是跟 LLM 交互的常见模式。相比纯文本或 JSON，XML 标签让模型更容易区分"结构"和"内容"，减少解析歧义。

### 4. 工具注册——把 load_skill 注册为模型可调用的工具

```python
TOOL_HANDLERS = {
    "bash":       lambda **kw: run_bash(kw["command"]),
    "read_file":  lambda **kw: run_read(kw["path"], kw.get("limit")),
    "write_file": lambda **kw: run_write(kw["path"], kw["content"]),
    "edit_file":  lambda **kw: run_edit(kw["path"], kw["old_text"], kw["new_text"]),
    "load_skill": lambda **kw: SKILL_LOADER.get_content(kw["name"]),  # ← 技能加载
}
```

```python
TOOLS = [
    # ... 其他工具 ...
    {"name": "load_skill",
     "description": "Load specialized knowledge by name.",
     "input_schema": {
         "type": "object",
         "properties": {"name": {"type": "string", "description": "Skill name to load"}},
         "required": ["name"]
     }
    },
]
```

模型通过 `TOOLS` 知道有 `load_skill` 这个工具可用，调用时传入技能名，`TOOL_HANDLERS` 里的 lambda 负责实际执行。

### 5. agent_loop——模型调用工具的主循环

```python
def agent_loop(messages: list):
    while True:
        response = client.messages.create(
            model=MODEL, system=SYSTEM, messages=messages,
            tools=TOOLS, max_tokens=8000,
        )
        messages.append({"role": "assistant", "content": response.content})

        if response.stop_reason != "tool_use":
            return                      # 模型不再调用工具 → 返回文字回复，循环结束

        # 模型调用了工具 → 执行工具，把结果加回对话
        results = []
        for block in response.content:
            if block.type == "tool_use":
                handler = TOOL_HANDLERS.get(block.name)
                output = handler(**block.input) if handler else f"Unknown tool: {block.name}"
                results.append({"type": "tool_result", "tool_use_id": block.id, "content": str(output)})

        messages.append({"role": "user", "content": results})
        # 然后回到 while True 顶部，带着工具结果再次调用模型
```

## 实际运行示例

用户输入：`帮我读一下 report.pdf`

```
第 1 轮对话：
  模型看到系统提示词里有 Skills available: - pdf: Process PDF files...
  模型决定调用 load_skill("pdf")

第 2 轮对话：
  tool_result 返回完整的 PDF 处理技能内容
  模型读取技能内容，知道要用 pdftotext 命令
  模型调用 bash("pdftotext report.pdf -")

第 3 轮对话：
  tool_result 返回 PDF 文本内容
  模型整理后输出给用户
  stop_reason == "end_turn" → 循环结束
```

## 关键 Python 知识点

### .get() 防御性取值

```python
skill["meta"]["description"]       # 键不存在 → KeyError 报错
skill["meta"].get("description", "No description")  # 键不存在 → 返回默认值，不报错
```

### join() 列表拼接

```python
lines = ["第一行", "第二行", "第三行"]
"\n".join(lines)    # "第一行\n第二行\n第三行"
```

- `join` 是字符串方法，不是列表方法
- 接受任何可迭代对象（列表、元组、字典、字符串）
- 只处理一层，不能处理嵌套

### re.match 正则解析

```python
r"^---\n(.*?)\n---\n(.*)"
#  ^     开头必须是 ---
#  .*?   非贪婪匹配元数据（遇到第一个 --- 就停）
#  .*)   贪婪匹配正文（匹配到最后）
#  re.DOTALL 让 . 能匹配换行符
```

### lambda 匿名函数

```python
lambda **kw: SKILL_LOADER.get_content(kw["name"])
# 等价于：
def load_skill_handler(**kw):
    return SKILL_LOADER.get_content(kw["name"])
```

`**kw` 把工具调用的参数收集成字典，比如 `{"name": "pdf"}`。

## 一句话总结

**别把所有知识都放进提示词——给模型一个目录，让它自己按需查。**

这跟 Claude Code 的 skill 系统（`/commit`、`/review-pr` 等）是同一个设计思路：目录随提示词发送，内容在调用时才加载。
