# s08 后台任务 -- 不阻塞的并行执行

> 源码：`agents/s08_background_tasks.py`

## 核心问题

有些命令跑很久（编译、训练模型、下载大文件）。如果 Agent 用同步方式执行，整个循环就卡在那里等结果，什么也干不了。

**比喻**：你在厨房做饭。如果烧水的时候干等着（同步），其他菜都没法做。应该把水烧上（后台任务），转头去切菜（继续别的工作），等水开了再回来处理。

## 解决方案：后台线程 + 通知队列

```
主线程 (Agent 循环)              后台线程
+------------------+             +------------------+
| 处理用户请求      |             |                  |
| 调用 LLM         |             |                  |
| drain 通知队列  <--+----------- | 命令执行完毕      |
| 注入结果到对话    |             | 推入通知队列      |
| 继续工作...       |             |                  |
+------------------+             +------------------+

时间线：
Agent ----[spawn A]----[spawn B]----[做其他事]----
             |              |
             v              v
          [A 运行中]     [B 运行中]           (并行)
             |              |
             +-- 通知队列 --> [结果被注入下一轮对话]
```

**核心思想**：发射后不管（Fire and forget）-- Agent 不会在命令运行时阻塞。

## BackgroundManager 类详解

### 初始化

```python
class BackgroundManager:
    def __init__(self):
        self.tasks = {}                    # task_id -> {status, result, command}
        self._notification_queue = []      # 已完成任务的通知列表
        self._lock = threading.Lock()      # 线程锁，保护队列安全
```

三个属性：
- `tasks`：字典，key 是 task_id，value 是任务状态和结果
- `_notification_queue`：通知队列 -- 后台线程把结果推到这里
- `_lock`：线程锁 -- 因为主线程和后台线程同时访问队列，需要加锁

### run() -- 启动后台任务（非阻塞）

```python
def run(self, command: str) -> str:
    """启动后台线程，立即返回 task_id"""
    task_id = str(uuid.uuid4())[:8]  # 取 UUID 前 8 位作为短 ID
    self.tasks[task_id] = {"status": "running", "result": None, "command": command}

    thread = threading.Thread(
        target=self._execute,        # 线程要执行的函数
        args=(task_id, command),      # 传给函数的参数
        daemon=True                   # 守护线程：主程序退出时自动结束
    )
    thread.start()                    # 启动线程，立即返回
    return f"Background task {task_id} started: {command[:80]}"
```

**比喻**：你在快递柜寄包裹。柜子给你一个取件码（task_id），你拿着码先走，不用等快递员送完。

关键点：
- `daemon=True`：主程序结束时后台线程自动终止，不会卡住程序退出
- `thread.start()` 后立即返回，不等待命令执行完
- `uuid.uuid4()[:8]`：生成 8 位随机 ID，够短且几乎不会冲突

### _execute() -- 线程实际执行的内容

```python
def _execute(self, task_id: str, command: str):
    """线程入口：跑子进程，捕获输出，推入通知队列"""
    try:
        r = subprocess.run(
            command, shell=True, cwd=WORKDIR,
            capture_output=True, text=True, timeout=300  # 5 分钟超时
        )
        output = (r.stdout + r.stderr).strip()[:50000]
        status = "completed"
    except subprocess.TimeoutExpired:
        output = "Error: Timeout (300s)"
        status = "timeout"
    except Exception as e:
        output = f"Error: {e}"
        status = "error"

    # 更新任务状态
    self.tasks[task_id]["status"] = status
    self.tasks[task_id]["result"] = output or "(no output)"

    # 推入通知队列（加锁）
    with self._lock:
        self._notification_queue.append({
            "task_id": task_id,
            "status": status,
            "command": command[:80],
            "result": (output or "(no output)")[:500],  # 通知里截断，节省 token
        })
```

**线程安全**：`with self._lock` 确保主线程在读队列、后台线程在写队列时不会冲突。

**输出截断**：通知里的 result 只保留前 500 字符（节省 token），但 tasks 字典里存完整结果（最多 50000 字符）。

### check() -- 查询任务状态

```python
def check(self, task_id: str = None) -> str:
    """查看单个任务或列出所有任务"""
    if task_id:
        t = self.tasks.get(task_id)
        if not t:
            return f"Error: Unknown task {task_id}"
        return f"[{t['status']}] {t['command'][:60]}\n{t.get('result') or '(running)'}"

    lines = []
    for tid, t in self.tasks.items():
        lines.append(f"{tid}: [{t['status']}] {t['command'][:60]}")
    return "\n".join(lines) if lines else "No background tasks."
```

两种用法：
- `check(task_id="abc123")`：查看特定任务的状态和完整结果
- `check()`（不传参数）：列出所有后台任务的简要状态

### drain_notifications() -- 排空通知队列

```python
def drain_notifications(self) -> list:
    """取出并清空所有待处理的通知"""
    with self._lock:
        notifs = list(self._notification_queue)  # 复制一份
        self._notification_queue.clear()          # 清空原队列
    return notifs
```

原子操作：复制并清空在同一个锁内完成，不会漏掉通知也不会重复取。

## agent_loop 中的集成

```python
def agent_loop(messages: list):
    while True:
        # 每次调用 LLM 前：排空通知队列，注入到对话中
        notifs = BG.drain_notifications()
        if notifs and messages:
            notif_text = "\n".join(
                f"[bg:{n['task_id']}] {n['status']}: {n['result']}"
                for n in notifs
            )
            # 注入一条 user 消息包含后台结果
            messages.append({"role": "user", "content":
                f"<background-results>\n{notif_text}\n</background-results>"})
            # 配对的 assistant 确认（保持对话格式正确）
            messages.append({"role": "assistant", "content":
                "Noted background results."})

        # 正常调用 LLM
        response = client.messages.create(...)
        ...
```

**注入格式**：用 `<background-results>` XML 标签包裹，让模型知道这是后台任务的结果，不是用户新输入。配对的 assistant 消息（"Noted background results."）确保消息列表的 user/assistant 交替格式不被破坏。

**为什么每轮都 drain？** 因为后台线程随时可能完成。在每次 LLM 调用前检查一次，保证结果不会漏掉。

| `background_run` | 启动后台命令 | 否，立即返回 task_id |
| `check_background` | 查询后台任务状态 | 否 |

```python
TOOL_HANDLERS = {
    "background_run":   lambda **kw: BG.run(kw["command"]),
    "check_background": lambda **kw: BG.check(kw.get("task_id")),
}
```

普通 `bash` 工具仍然保留，用于短命令（ls、cat 等）。长命令才需要 `background_run`。

## 完整数据流示例

```
时间线：
T0  用户: "运行测试套件，同时开始写 README"

T1  Agent 思考后执行:
    > background_run(command="pytest --tb=short")   # 返回 task_id="a1b2c3d4"
    > write_file(path="README.md", content="...")   # 立刻做别的事

T2  Agent 继续工作:
    > edit_file(path="README.md", ...)               # 还在后台跑测试

T3  后台线程完成 pytest:
    -> _notification_queue.append({task_id: "a1b2c3d4", ...})

T4  Agent 下一轮:
    drain_notifications() -> 发现 a1b2c3d4 完成了
    注入: "<background-results>[bg:a1b2c3d4] completed: 42 passed</background-results>"
    Agent 看到: "测试全过了，README 也写好了，任务完成。"
```

## Python 知识点

| 用法 | 说明 |
|------|------|
| `threading.Thread(target=fn, args=(), daemon=True)` | 创建守护线程 |
| `thread.start()` | 启动线程，不阻塞主线程 |
| `threading.Lock()` | 线程锁，保护共享数据 |
| `with lock:` | 上下文管理器自动加锁/解锁 |
| `uuid.uuid4()[:8]` | 生成短随机 ID |
| `subprocess.run(..., timeout=300)` | 带超时的子进程执行 |
| `list(original)` | 复制列表（浅拷贝），不修改原列表 |
| `list.clear()` | 清空列表（原地操作） |

## 一句话总结

用后台线程跑长命令，通过线程安全的通知队列把结果注入回对话，Agent 在等待期间可以继续干别的 -- 发射后不管，结果自动回来。
