# s03 进度追踪

## 核心问题

模型在执行多步任务时容易"跑偏"——忘了做到哪一步，漏掉中间步骤，或者在某个细节上反复兜圈子。

模型自己不记得进度，但我们可以给它一面"进度板"，让它随时更新、随时看到。

## 解决方案：TodoManager + 催促提醒

给模型一个 `todo` 工具，让它自己维护任务列表。再加一个"催促机制"：如果模型连续 3 轮没更新进度，就自动插一条提醒。

```
s02: 模型干活 → 没有任何进度记录 → 容易迷失
s03: 模型干活 → 用 todo 规划 → 每完成一步打个勾 → 不容易跑偏
```

> 比喻：想象你让一个实习生去做 10 件事。如果你不给他纸笔，他做了 3 件可能就忘了剩下 7 件是什么。给他一个待办清单，让他每做完一件打个勾，他就不会乱。而"催促提醒"就是你每隔一段时间问他："进度更新了吗？"

## 源代码逐段解析

### 1. TodoManager 类——结构化的进度板

```python
class TodoManager:
    def __init__(self):
        self.items = []     # 任务列表，每个元素是一个字典 {id, text, status}
```

#### update()：更新任务列表（带校验）

```python
def update(self, items: list) -> str:
    if len(items) > 20:
        raise ValueError("Max 20 todos allowed")       # 防止列表过长

    validated = []
    in_progress_count = 0
    for i, item in enumerate(items):
        text = str(item.get("text", "")).strip()       # 任务文本
        status = str(item.get("status", "pending")).lower()  # 状态
        item_id = str(item.get("id", str(i + 1)))      # ID，没有就自动编号

        # 校验 1：文本不能为空
        if not text:
            raise ValueError(f"Item {item_id}: text required")
        # 校验 2：状态只能是三种之一
        if status not in ("pending", "in_progress", "completed"):
            raise ValueError(f"Item {item_id}: invalid status '{status}'")
        # 校验 3：同时只能有一个 in_progress
        if status == "in_progress":
            in_progress_count += 1

        validated.append({"id": item_id, "text": text, "status": status})

    if in_progress_count > 1:
        raise ValueError("Only one task can be in_progress at a time")

    self.items = validated       # 校验通过，替换整个列表
    return self.render()         # 返回渲染后的文本
```

三条校验规则的意图：

| 规则 | 为什么 |
|------|--------|
| 最多 20 条 | 防止模型生成几百条任务，浪费 token |
| 状态只有三种 | `pending`→`in_progress`→`completed`，简单明确 |
| 只能一个 in_progress | 强制模型"一次只做一件事"，避免并行混乱 |

> 注意：`update()` 是**整体替换**，不是增量修改。每次调用都要传完整的任务列表。这让模型始终保持一个全局视图，而不是只看到局部变化。

#### render()：渲染成可读文本

```python
def render(self) -> str:
    if not self.items:
        return "No todos."
    lines = []
    for item in self.items:
        marker = {
            "pending": "[ ]",
            "in_progress": "[>]",    # 箭头表示"正在做"
            "completed": "[x]"
        }[item["status"]]
        lines.append(f"{marker} #{item['id']}: {item['text']}")
    done = sum(1 for t in self.items if t["status"] == "completed")
    lines.append(f"\n({done}/{len(self.items)} completed)")
    return "\n".join(lines)
```

渲染结果示例：

```
[ ] #1: 分析现有代码结构
[>] #2: 重构核心模块        ← 正在进行
[x] #3: 编写测试用例        ← 已完成

(1/3 completed)
```

这段文本会作为 `tool_result` 返回给模型，模型就能看到当前的整体进度。

### 2. 工具注册——todo 加入 TOOL_HANDLERS

```python
TOOL_HANDLERS = {
    "bash":       lambda **kw: run_bash(kw["command"]),
    "read_file":  lambda **kw: run_read(kw["path"], kw.get("limit")),
    "write_file": lambda **kw: run_write(kw["path"], kw["content"]),
    "edit_file":  lambda **kw: run_edit(kw["path"], kw["old_text"], kw["new_text"]),
    "todo":       lambda **kw: TODO.update(kw["items"]),   # ← 新增
}
```

todo 工具的 schema 声明：

```python
{"name": "todo",
 "description": "Update task list. Track progress on multi-step tasks.",
 "input_schema": {
     "type": "object",
     "properties": {
         "items": {
             "type": "array",
             "items": {
                 "type": "object",
                 "properties": {
                     "id": {"type": "string"},
                     "text": {"type": "string"},
                     "status": {"type": "string", "enum": ["pending", "in_progress", "completed"]}
                 },
                 "required": ["id", "text", "status"]
             }
         }
     },
     "required": ["items"]
 }
}
```

模型看到这个 schema，就知道它可以传一个 `items` 数组，每个元素有 `id`、`text`、`status` 三个字段。

### 3. agent_loop——加入催促逻辑

```python
def agent_loop(messages: list):
    rounds_since_todo = 0          # 计数器：多少轮没更新 todo 了
    while True:
        response = client.messages.create(
            model=MODEL, system=SYSTEM, messages=messages,
            tools=TOOLS, max_tokens=8000,
        )
        messages.append({"role": "assistant", "content": response.content})
        if response.stop_reason != "tool_use":
            return

        results = []
        used_todo = False          # 本轮是否更新了 todo
        for block in response.content:
            if block.type == "tool_use":
                handler = TOOL_HANDLERS.get(block.name)
                try:
                    output = handler(**block.input) if handler else f"Unknown tool: {block.name}"
                except Exception as e:
                    output = f"Error: {e}"
                print(f"> {block.name}: {str(output)[:200]}")
                results.append({"type": "tool_result", "tool_use_id": block.id, "content": str(output)})
                if block.name == "todo":
                    used_todo = True   # 标记：本轮更新了 todo

        # 更新计数器
        rounds_since_todo = 0 if used_todo else rounds_since_todo + 1

        # 催促提醒：连续 3 轮没更新 → 注入提醒
        if rounds_since_todo >= 3:
            results.insert(0, {"type": "text", "text": "<reminder>Update your todos.</reminder>"})
            # insert(0, ...) 放在最前面，确保模型第一时间看到

        messages.append({"role": "user", "content": results})
```

和 s02 的 agent_loop 对比，新增了三样东西：

```
新增 1: rounds_since_todo 计数器
新增 2: used_todo 标记
新增 3: 催促提醒注入（results.insert(0, ...)）
```

> 催促提醒不是用户发的消息，也不是工具的输出——它是 harness 自己注入的。这是一种"被动引导"：不强制模型怎么做，但在它忘记的时候推一把。`<reminder>` 标签是故意用 XML 格式写的，让模型能区分这是系统提醒而不是普通内容。

## 实际运行示例

用户输入：`帮我给项目加一个日志模块`

```
=== 第 1 轮 ===
模型规划任务:
  todo.update([
    {"id": "1", "text": "分析现有代码结构", "status": "in_progress"},
    {"id": "2", "text": "编写日志模块", "status": "pending"},
    {"id": "3", "text": "集成到现有代码", "status": "pending"},
    {"id": "4", "text": "测试", "status": "pending"},
  ])
  → used_todo = True, rounds_since_todo = 0

=== 第 2 轮 ===
模型开始分析:
  read_file("main.py")
  → used_todo = False, rounds_since_todo = 1

=== 第 3 轮 ===
模型继续分析:
  bash("find . -name '*.py' | head -20")
  → used_todo = False, rounds_since_todo = 2

=== 第 4 轮 ===
模型还没更新 todo:
  rounds_since_todo = 3 → 注入 <reminder>Update your todos.</reminder>
  模型看到提醒，先更新进度:
  todo.update([
    {"id": "1", "text": "分析现有代码结构", "status": "completed"},
    {"id": "2", "text": "编写日志模块", "status": "in_progress"},
    ...
  ])
  → used_todo = True, rounds_since_todo = 0 （重置）
```

## 关键 Python 知识点

### 列表推导式的条件计数

```python
done = sum(1 for t in self.items if t["status"] == "completed")
```

这行代码统计已完成的任务数。`sum(1 for ... if ...)` 是 Python 里条件计数的惯用写法，等价于：

```python
done = 0
for t in self.items:
    if t["status"] == "completed":
        done += 1
```

### list.insert() 在指定位置插入

```python
results.insert(0, {"type": "text", "text": "<reminder>..."})
```

`insert(0, ...)` 在列表最前面插入元素。这里是为了让催促提醒出现在其他 tool_result 之前，模型先看到提醒再看其他结果。

### enumerate() 带索引遍历

```python
for i, item in enumerate(items):
    item_id = str(item.get("id", str(i + 1)))
```

`enumerate` 同时给出索引和值。`i + 1` 是因为任务编号从 1 开始而不是 0。
