# s12 - Worktree Task Isolation：目录级隔离的并行执行

> 源码：`agents/s12_worktree_task_isolation.py`
> 核心洞察：**靠目录隔离，靠任务 ID 协调**。

## 问题：多个任务并行改文件，怎么避免冲突？

s11 的队友们共享同一个工作目录，如果两个队友同时改同一个文件就会冲突。s12 的解决方案：

**每个任务一个独立的 git worktree（独立目录 + 独立分支）。**

比喻：就像一个办公室（主仓库）旁边开了多个独立的工作间（worktree）。每个任务在自己的工作间里干活，互不干扰。任务之间通过"任务编号"（task ID）关联。

## 架构总览：控制面 vs 执行面

```
控制面 (.tasks/)                    执行面 (.worktrees/)
task_1.json                         .worktrees/auth-refactor/
  "id": 1,                            git branch: wt/auth-refactor
  "subject": "重构认证",               独立的工作目录
  "worktree": "auth-refactor"          独立的文件系统

task_2.json                         .worktrees/add-tests/
  "id": 2,                            git branch: wt/add-tests
  "subject": "添加测试",
  "worktree": "add-tests"

.worktrees/index.json               .worktrees/events.jsonl
  记录所有 worktree 的元数据           记录所有生命周期事件
```

## 1. detect_repo_root() -- 找到 git 仓库根目录

```python
def detect_repo_root(cwd: Path) -> Path | None:
    try:
        r = subprocess.run(
            ["git", "rev-parse", "--show-toplevel"],
            cwd=cwd, capture_output=True, text=True, timeout=10,
        )
        if r.returncode != 0:
            return None
        root = Path(r.stdout.strip())
        return root if root.exists() else None
    except Exception:
        return None

REPO_ROOT = detect_repo_root(WORKDIR) or WORKDIR
```

s12 的所有路径都基于 `REPO_ROOT`（git 仓库根目录），不是当前工作目录。因为 worktree 必须在 git 仓库内才能工作。

## 2. EventBus：只追加的事件日志

```python
class EventBus:
    def __init__(self, event_log_path: Path):
        self.path = event_log_path   # .worktrees/events.jsonl
        # ...

    def emit(self, event: str, task=None, worktree=None, error=None):
        payload = {
            "event": event,          # 事件名
            "ts": time.time(),       # 时间戳
            "task": task or {},      # 关联的任务
            "worktree": worktree or {},  # 关联的 worktree
        }
        if error:
            payload["error"] = error
        with self.path.open("a") as f:
            f.write(json.dumps(payload) + "\n")
```

EventBus 记录所有生命周期事件，类似审计日志。事件类型包括：

```
worktree.create.before    -- 创建前
worktree.create.after     -- 创建成功
worktree.create.failed    -- 创建失败
worktree.remove.before    -- 删除前
worktree.remove.after     -- 删除成功
worktree.remove.failed    -- 删除失败
worktree.keep             -- 标记保留
task.completed            -- 任务完成
```

`before/after/failed` 三阶段模式让我们能：
- 在 before 阶段记录意图
- 在 after 阶段记录成功
- 在 failed 阶段记录失败原因

## 3. TaskManager：带 worktree 绑定的任务看板

### 任务创建

```python
def create(self, subject: str, description: str = "") -> str:
    task = {
        "id": self._next_id,
        "subject": subject,
        "description": description,
        "status": "pending",
        "owner": "",
        "worktree": "",            # 绑定的 worktree 名称
        "blockedBy": [],
        "created_at": time.time(),
        "updated_at": time.time(),
    }
    self._save(task)
    self._next_id += 1
```

和 s11 相比，任务多了 `worktree` 字段。

### bind_worktree() / unbind_worktree() -- 任务与 worktree 的绑定

```python
def bind_worktree(self, task_id: int, worktree: str, owner: str = "") -> str:
    task = self._load(task_id)
    task["worktree"] = worktree        # 记录绑定的 worktree 名
    if owner:
        task["owner"] = owner
    if task["status"] == "pending":
        task["status"] = "in_progress"  # 绑定自动变成 in_progress
    self._save(task)

def unbind_worktree(self, task_id: int) -> str:
    task = self._load(task_id)
    task["worktree"] = ""              # 解除绑定
    self._save(task)
```

绑定 = 任务和 worktree 建立关联。一个任务最多绑定一个 worktree。

## 4. WorktreeManager：核心类

### create() -- 创建 worktree

```python
def create(self, name: str, task_id: int = None, base_ref: str = "HEAD") -> str:
    self._validate_name(name)          # 名字只能含字母数字和 . _ -
    # 检查重名、检查 task 是否存在

    path = self.dir / name             # .worktrees/<name>
    branch = f"wt/{name}"              # 分支名：wt/<name>

    self.events.emit("worktree.create.before", ...)    # 事件：创建前

    try:
        # 核心操作：git worktree add
        self._run_git(["worktree", "add", "-b", branch, str(path), base_ref])

        # 记录到 index.json
        entry = {
            "name": name,
            "path": str(path),
            "branch": branch,
            "task_id": task_id,
            "status": "active",
        }
        idx = self._load_index()
        idx["worktrees"].append(entry)
        self._save_index(idx)

        # 如果有 task_id，绑定任务
        if task_id is not None:
            self.tasks.bind_worktree(task_id, name)

        self.events.emit("worktree.create.after", ...)  # 事件：创建成功
    except Exception as e:
        self.events.emit("worktree.create.failed", ..., error=str(e))
        raise
```

创建流程：
1. 验证名称合法性
2. 发 before 事件
3. 执行 `git worktree add -b wt/<name> <path> <base_ref>`
4. 记录到 `index.json`
5. 如果有 task_id，自动绑定任务
6. 发 after 事件

### run() -- 在 worktree 中执行命令

```python
def run(self, name: str, command: str) -> str:
    wt = self._find(name)
    path = Path(wt["path"])
    # 在 worktree 的目录下执行命令，而不是主仓库目录
    r = subprocess.run(command, shell=True, cwd=path, ...)
```

关键：`cwd=path` -- 命令在 worktree 目录里运行，改的文件是 worktree 的文件，不影响主仓库。

### remove() -- 删除 worktree

```python
def remove(self, name: str, force: bool = False, complete_task: bool = False) -> str:
    self.events.emit("worktree.remove.before", ...)

    try:
        # git worktree remove
        args = ["worktree", "remove"]
        if force:
            args.append("--force")
        args.append(wt["path"])
        self._run_git(args)

        # 可选：同时把绑定的任务标记为完成
        if complete_task and wt.get("task_id") is not None:
            self.tasks.update(task_id, status="completed")
            self.tasks.unbind_worktree(task_id)
            self.events.emit("task.completed", ...)

        # 更新 index.json 中的状态为 "removed"
        # ...

        self.events.emit("worktree.remove.after", ...)
    except Exception as e:
        self.events.emit("worktree.remove.failed", ..., error=str(e))
```

删除时可以选 `complete_task=True`，一步完成"删除 worktree + 标记任务完成"。

### keep() -- 保留 worktree

```python
def keep(self, name: str) -> str:
    # 不删除 worktree，只是标记为 "kept"
    item["status"] = "kept"
    item["kept_at"] = time.time()
    self.events.emit("worktree.keep", ...)
```

有时候任务做完了但想保留 worktree（比如要 review 代码），用 `keep()` 代替 `remove()`。

### status() -- 查看 worktree 的 git 状态

```python
def status(self, name: str) -> str:
    wt = self._find(name)
    path = Path(wt["path"])
    r = subprocess.run(
        ["git", "status", "--short", "--branch"],
        cwd=path, ...
    )
```

就是在 worktree 目录里跑 `git status`。

## 6. 典型使用流程

```
1. task_create("重构认证模块")
   -> 创建 task_1.json，status=pending

2. worktree_create("auth-refactor", task_id=1)
   -> git worktree add -b wt/auth-refactor .worktrees/auth-refactor HEAD
   -> task_1.json 的 worktree="auth-refactor", status="in_progress"
   -> 发出 create.before + create.after 事件

3. worktree_run("auth-refactor", "vim src/auth.py")
   -> 在 .worktrees/auth-refactor/ 目录下执行命令
   -> 改的文件在 worktree 里，不影响主仓库

4. worktree_remove("auth-refactor", complete_task=True)
   -> git worktree remove .worktrees/auth-refactor
   -> task_1.json 的 status="completed"
   -> 发出 remove.before + task.completed + remove.after 事件
```

## 关键设计总结

1. **任务是控制面，worktree 是执行面**：任务记录"要做什么"，worktree 是"在哪里做"
2. **git worktree = 免费的目录隔离**：不需要自己管理目录复制，git 原生支持
3. **任务 ID 是关联键**：一个 worktree 绑定一个 task_id，通过这个 ID 把两者联系起来
4. **before/after/failed 事件三阶段**：完整的生命周期可观测性
5. **keep vs remove**：做完了可以选择删除或保留，保留方便后续 review
6. **index.json 是索引**：不依赖 `git worktree list`，自己维护一份元数据索引
