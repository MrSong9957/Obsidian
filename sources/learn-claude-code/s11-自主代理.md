# s11 - Autonomous Agents：自己找活干的代理

> 源码：`agents/s11_autonomous_agents.py`
> 核心洞察：**代理自己去找活干**。

## 问题：怎么让队友不闲着？

s10 的队友做完分配的活就 idle 了，需要队长手动再分配新任务。问题是：能不能让队友自己去找活？

s11 的答案是：**任务看板 + 空闲轮询 + 自动认领**。

比喻：把任务贴在公告板上（`.tasks/` 目录），空闲的队友每隔几秒去看一眼，看到没人认领的任务就自己拿来做。就像公司里的任务池，谁有空谁就领。

## 1. 任务看板：`.tasks/` 目录

每个任务是一个 JSON 文件：

```python
# .tasks/task_1.json
{
    "id": 1,
    "subject": "修复登录 bug",
    "description": "用户点击登录后没有反应",
    "status": "pending",       # pending / in_progress / completed
    "owner": "",               # 空表示没人认领
    "worktree": "",
    "blockedBy": []            # 依赖的任务 ID 列表
}
```

### scan_unclaimed_tasks() -- 扫描无人认领的任务

```python
def scan_unclaimed_tasks() -> list:
    TASKS_DIR.mkdir(exist_ok=True)
    unclaimed = []
    for f in sorted(TASKS_DIR.glob("task_*.json")):
        task = json.loads(f.read_text())
        if (task.get("status") == "pending"
                and not task.get("owner")          # 没有主人
                and not task.get("blockedBy")):    # 没有被阻塞
            unclaimed.append(task)
    return unclaimed
```

三个条件缺一不可：
- `status == "pending"` -- 还没开始
- `owner` 为空 -- 没人认领
- `blockedBy` 为空 -- 没有前置依赖

### claim_task() -- 原子性认领

```python
def claim_task(task_id: int, owner: str) -> str:
    with _claim_lock:                    # 线程锁防止并发冲突
        path = TASKS_DIR / f"task_{task_id}.json"
        task = json.loads(path.read_text())
        task["owner"] = owner
        task["status"] = "in_progress"
        path.write_text(json.dumps(task, indent=2))
    return f"Claimed task #{task_id} for {owner}"
```

`_claim_lock` 是关键。多个队友可能同时看到同一个任务，锁确保只有一个人能认领成功。

## 2. 身份重注入：上下文压缩后保持自我认知

```python
def make_identity_block(name: str, role: str, team_name: str) -> dict:
    return {
        "role": "user",
        "content": f"<identity>You are '{name}', role: {role}, team: {team_name}. "
                   f"Continue your work.</identity>",
    }
```

为什么需要这个？当对话历史太长时，LLM 的上下文会被压缩或截断。压缩后队友可能"忘了自己是谁"。这个 identity block 就是在压缩后重新注入身份信息。

比喻：就像长时间开会后，中间休息回来，主持人再提醒一下你的角色和职责。

## 3. 核心设计：两阶段生命周期（WORK / IDLE）

这是 s11 最重要的设计。队友的线程循环变成两阶段：

```
+-------+
| spawn |
+---+---+
    |
    v
+-------+  tool_use    +-------+
| WORK  | <----------- |  LLM  |    正常的 agent 循环，最多 50 轮
+---+---+              +-------+
    |
    | stop_reason != tool_use  或  调用了 idle 工具
    v
+--------+
| IDLE   |  每 5 秒轮询一次，最多等 60 秒
+---+----+
    |
    +---> 检查 inbox → 有消息？ → 恢复 WORK
    |
    +---> 扫描 .tasks/ → 有未认领任务？ → 认领 → 恢复 WORK
    |
    +---> 60 秒超时 → shutdown（真的没活了）
```

### WORK 阶段

```python
# -- WORK PHASE: standard agent loop --
for _ in range(50):
    inbox = BUS.read_inbox(name)
    for msg in inbox:
        if msg.get("type") == "shutdown_request":
            self._set_status(name, "shutdown")
            return                        # 收到关闭请求，直接退出
        messages.append({"role": "user", "content": json.dumps(msg)})

    # 调用 LLM...
    # 执行工具...
    # 如果调用了 idle 工具，break 跳出循环
    if idle_requested:
        break
```

新增的 `idle` 工具让 LLM 自己声明"我没活了"。这是关键：**由 LLM 决定自己什么时候闲**。

### IDLE 阶段

```python
# -- IDLE PHASE: poll for inbox messages and unclaimed tasks --
self._set_status(name, "idle")
resume = False
polls = IDLE_TIMEOUT // POLL_INTERVAL     # 60 / 5 = 12 次轮询

for _ in range(polls):
    time.sleep(POLL_INTERVAL)             # 等 5 秒
    # 检查收件箱
    inbox = BUS.read_inbox(name)
    if inbox:
        # 有消息就恢复工作
        resume = True
        break
    # 扫描任务看板
    unclaimed = scan_unclaimed_tasks()
    if unclaimed:
        task = unclaimed[0]
        claim_task(task["id"], name)       # 自动认领！
        # 把任务信息注入对话
        task_prompt = f"<auto-claimed>Task #{task['id']}: {task['subject']}\n..."
        messages.append({"role": "user", "content": task_prompt})
        resume = True
        break

if not resume:
    self._set_status(name, "shutdown")    # 超时，真的关闭
    return
self._set_status(name, "working")         # 恢复工作
```

轮询逻辑很清晰：
1. 每 5 秒检查一次 inbox
2. 每 5 秒扫描一次任务看板
3. 有消息或有任务就立即恢复 WORK
4. 60 秒都没等到就关闭

### 自动认领后的身份重注入

```python
if unclaimed:
    task = unclaimed[0]
    claim_task(task["id"], name)
    # 如果对话历史很短（可能经过压缩），注入身份信息
    if len(messages) <= 3:
        messages.insert(0, make_identity_block(name, role, team_name))
        messages.insert(1, {"role": "assistant", "content": f"I am {name}. Continuing."})
    messages.append({"role": "user", "content": task_prompt})
    messages.append({"role": "assistant", "content": f"Claimed task #{task['id']}. Working on it."})
```

如果对话历史很短（说明可能经过压缩），就在开头插入 identity block。

## 6. 交互式命令

s11 的主循环增加了 `/tasks` 命令：

```
s11 >> /tasks
  [ ] #1: 修复登录 bug
  [>] #2: 实现用户注册 @alice
  [x] #3: 添加单元测试
```

`[ ]` = pending，`[>]` = in_progress，`[x]` = completed。

## 关键设计总结

1. **两阶段生命周期**：WORK（干活）-> IDLE（找活）-> WORK（继续干）-> ... -> shutdown
2. **idle 工具**：LLM 自己决定什么时候闲，不是外部强制
3. **轮询扫描**：空闲时每 5 秒检查 inbox + 任务看板
4. **原子认领**：`_claim_lock` 确保并发安全
5. **身份重注入**：上下文压缩后仍然知道"我是谁"
6. **自适应关闭**：60 秒找不到活就自动 shutdown，不需要手动关闭

s09 解决了"队友能说话"，s10 解决了"说话有协议"，s11 解决了"能自己找活"。三个脚本层层递进，每一步只加一个核心能力。
