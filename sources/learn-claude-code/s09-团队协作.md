# s09 - Agent Teams：能互相说话的队友

> 源码：`agents/s09_agent_teams.py`
> 核心洞察：**队友之间可以互相对话**。

## 子代理 vs 队友：生命周期的根本区别

这是理解 s09 最关键的一点。回忆 s04 的子代理：

```
子代理 (s04)：  spawn -> 执行任务 -> 返回摘要 -> 销毁
队友 (s09)：    spawn -> 工作 -> 空闲 -> 再工作 -> ... -> 关闭
```

比喻：子代理像**临时工**（干完活就走），队友像**坐班的同事**（一直在工位上，随时可以接新活、随时可以互相交流）。

## 整体架构：文件即通信

```
.team/config.json                   .team/inbox/
+----------------------------+      +------------------+
| {"team_name": "default",   |      | alice.jsonl      |
|  "members": [              |      | bob.jsonl        |
|    {"name":"alice",        |      | lead.jsonl       |
|     "role":"coder",        |      +------------------+
|     "status":"idle"}       |
|  ]}                        |      send_message("alice", "fix bug"):
+----------------------------+        往 alice.jsonl 追加一行 JSON
```

每个队友有一个自己的 JSONL 收件箱文件。发送消息 = 往对方文件追加一行；读取消息 = 读出自己的文件然后清空。

## 1. MessageBus：文件即收件箱

`MessageBus` 是整个通信系统的核心，管理 `.team/inbox/` 目录下的 JSONL 文件。

### send() -- 发消息就是追加一行

```python
def send(self, sender: str, to: str, content: str,
         msg_type: str = "message", extra: dict = None) -> str:
    msg = {
        "type": msg_type,
        "from": sender,
        "content": content,
        "timestamp": time.time(),
    }
    if extra:
        msg.update(extra)
    inbox_path = self.dir / f"{to}.jsonl"
    with open(inbox_path, "a") as f:        # "a" 模式 = 追加
        f.write(json.dumps(msg) + "\n")
    return f"Sent {msg_type} to {to}"
```

要点：
- 每条消息是一个 JSON 对象，占一行
- `"a"` 模式打开文件，保证不会覆盖已有消息
- `extra` 参数允许附加额外字段（s10 的协议会用到）

### read_inbox() -- 读消息就是读后清空

```python
def read_inbox(self, name: str) -> list:
    inbox_path = self.dir / f"{name}.jsonl"
    if not inbox_path.exists():
        return []
    messages = []
    for line in inbox_path.read_text().strip().splitlines():
        if line:
            messages.append(json.loads(line))
    inbox_path.write_text("")    # 清空文件 = "drain"（消费即清除）
    return messages
```

要点：
- 读完后立即 `write_text("")` 清空，类似从邮箱取信
- 这叫 **drain（排空）模式**：消息只读一次，读完就没了
- 线程安全靠 Python GIL（同一时刻只有一个线程在操作文件）

### broadcast() -- 给所有人发

```python
def broadcast(self, sender: str, content: str, teammates: list) -> str:
    count = 0
    for name in teammates:
        if name != sender:              # 不发给自己
            self.send(sender, name, content, "broadcast")
            count += 1
    return f"Broadcast to {count} teammates"
```

广播 = 遍历队友列表，逐个调用 `send()`。

## 2. TeammateManager：管理持久化的队友

### spawn() -- 创建队友线程

```python
def spawn(self, name: str, role: str, prompt: str) -> str:
    # 检查是否已存在，如果空闲或已关闭则可以重新启用
    member = self._find_member(name)
    if member:
        if member["status"] not in ("idle", "shutdown"):
            return f"Error: '{name}' is currently {member['status']}"
        member["status"] = "working"
    else:
        member = {"name": name, "role": role, "status": "working"}
        self.config["members"].append(member)
    self._save_config()
    # 启动一个守护线程跑 agent loop
    thread = threading.Thread(
        target=self._teammate_loop,
        args=(name, role, prompt),
        daemon=True,
    )
    self.threads[name] = thread
    thread.start()
```

要点：
- 每个队友跑在独立的 `daemon=True` 线程中
- `config.json` 持久记录所有成员的名字、角色、状态
- 已有队友如果是 idle/shutdown 状态，可以重新激活

- 循环结束后自动变为 idle 状态

### _teammate_tools() -- 队友有 6 个工具

```python
def _teammate_tools(self) -> list:
    return [
        # 4 个基础工具
        bash, read_file, write_file, edit_file,
        # 2 个通信工具
        send_message,    # 发消息给别的队友
        read_inbox,      # 读自己的收件箱
    ]
```

注意：队友**没有** `task` 工具，也就是说队友不能再创建子代理（防止递归爆炸）。这是有意的限制。

## 3. Lead agent：9 个工具的队长

Lead（队长）是和用户交互的主 agent，拥有 9 个工具：

| 工具 | 用途 |
|------|------|
| bash / read_file / write_file / edit_file | 4 个基础工具 |
| spawn_teammate | 创建队友 |
| list_teammates | 查看所有队友状态 |
| send_message | 给某个队友发消息 |
| read_inbox | 读队长的收件箱 |
| broadcast | 给所有队友广播消息 |

Lead 在每次 agent 循环开头也会检查自己的收件箱，这样队友发来的消息能及时处理：

## 通信的消息类型

s09 定义了 5 种消息类型（但只实际使用了 `message` 和 `broadcast`）：

```
message                 -- 普通文本消息（s09 使用）
broadcast               -- 广播消息（s09 使用）
shutdown_request        -- 请求关闭（s10 实现）
shutdown_response       -- 关闭响应（s10 实现）
plan_approval_response  -- 计划审批（s10 实现）
```

这叫**提前声明、延后实现**。先定义好消息类型的全集，后面 s10 再逐个实现处理逻辑。

```

    v                      v

+------------------+     +------------------+
| 读 inbox         |     | 读 inbox         |

+------------------+     +------------------+
```

## 关键设计总结

1. **文件即收件箱**：不需要数据库、不需要消息队列，一个 JSONL 文件搞定
2. **Drain 模式**：消息读完即清空，保证不会重复处理
3. **持久生命周期**：和 s04 的"用完即弃"不同，队友是持久的
4. **线程隔离**：每个队友独立线程、独立对话历史、独立工具集
5. **提前定义消息类型**：为后续的协议（s10）预留了消息类型
