# s07 任务系统 -- 压缩不丢状态

> 源码：`agents/s07_task_system.py`

## 核心问题

s06 解决了上下文窗口被填满的问题，但带来了新问题：**压缩会丢失对话中的任务状态**。

如果 Agent 在对话里维护了一个"待办列表"（比如用变量存着），auto_compact 一执行，这些变量就没了。压缩后的摘要可能遗漏细节，Agent 就不知道"做到哪了"。

**比喻**：你把工作进度写在白板上（对话内存），但白板空间不够要擦掉重写（压缩）。如果进度只存在白板上，擦了就没了。解决方案：把进度写到纸上（磁盘文件），白板怎么擦都不影响。

## 解决方案：持久化任务到磁盘

```
对话内存 (会被压缩丢失)          磁盘文件 (永远在)
+-------------------+           +-------------------+
| messages 列表      |           | .tasks/            |
| - "帮我建个项目"   |  ----->   |   task_1.json      |
| - "先写测试"       |           |   task_2.json      |
| - (被压缩掉了)     |           |   task_3.json      |
+-------------------+           +-------------------+
     易失                         持久
```

**核心思想**：状态存活于压缩之外，因为它存在对话外面。

## TaskManager 类详解

### 初始化：自动递增 ID

```python
class TaskManager:
    def __init__(self, tasks_dir: Path):
        self.dir = tasks_dir
        self.dir.mkdir(exist_ok=True)
        self._next_id = self._max_id() + 1  # 从现有最大 ID 续编

    def _max_id(self) -> int:
        ids = [int(f.stem.split("_")[1]) for f in self.dir.glob("task_*.json")]
        return max(ids) if ids else 0
```

启动时扫描 `.tasks/` 目录，找到最大的编号，下一个 ID 从它 +1 开始。这样即使程序重启，ID 也不会重复。

### create() -- 创建任务

```python
def create(self, subject: str, description: str = "") -> str:
    task = {
        "id": self._next_id,
        "subject": subject,        # 任务标题
        "description": description, # 详细描述
        "status": "pending",        # 初始状态：待处理
        "blockedBy": [],            # 被哪些任务阻塞
        "blocks": [],               # 阻塞了哪些任务
        "owner": "",                # 负责人
    }
    self._save(task)
    self._next_id += 1
    return json.dumps(task, indent=2)
```

每个任务是一个 JSON 文件，文件名 `task_{id}.json`。字段含义：

| 字段 | 说明 |
|------|------|
| `id` | 自增编号 |
| `subject` | 一句话描述 |
| `status` | `pending` / `in_progress` / `completed` |
| `blockedBy` | 前置依赖列表（这些任务完成后才能开始） |
| `blocks` | 后续被阻塞列表（本任务完成后它们才能开始） |
| `owner` | 分配给谁（可选） |

### get() / _load() / _save() -- 读写基础

```python
def _load(self, task_id: int) -> dict:
    path = self.dir / f"task_{task_id}.json"
    if not path.exists():
        raise ValueError(f"Task {task_id} not found")
    return json.loads(path.read_text())

def _save(self, task: dict):
    path = self.dir / f"task_{task['id']}.json"
    path.write_text(json.dumps(task, indent=2))
```

每个任务一个文件，读写都是直接的 JSON 序列化/反序列化。简单粗暴但有效。

### update() -- 更新状态 + 依赖管理

```python
def update(self, task_id: int, status: str = None,
           add_blocked_by: list = None, add_blocks: list = None) -> str:
    task = self._load(task_id)

    if status:
        if status not in ("pending", "in_progress", "completed"):
            raise ValueError(f"Invalid status: {status}")
        task["status"] = status
        # 完成时，自动清除所有其他任务对此任务的 blockedBy 引用
        if status == "completed":
            self._clear_dependency(task_id)

    if add_blocked_by:
        task["blockedBy"] = list(set(task["blockedBy"] + add_blocked_by))

    if add_blocks:
        task["blocks"] = list(set(task["blocks"] + add_blocks))
        # 双向更新：被阻塞的任务也要更新其 blockedBy
        for blocked_id in add_blocks:
            try:
                blocked = self._load(blocked_id)
                if task_id not in blocked["blockedBy"]:
                    blocked["blockedBy"].append(task_id)
                    self._save(blocked)
            except ValueError:
                pass

    self._save(task)
    return json.dumps(task, indent=2)
```

两个关键机制：

**1. 完成时自动解除依赖（_clear_dependency）**

```python
def _clear_dependency(self, completed_id: int):
    """Remove completed_id from all other tasks' blockedBy lists."""
    for f in self.dir.glob("task_*.json"):
        task = json.loads(f.read_text())
        if completed_id in task.get("blockedBy", []):
            task["blockedBy"].remove(completed_id)
            self._save(task)
```

当任务 1 完成时，扫描所有任务文件，把 `blockedBy` 里包含 1 的都删掉。这样之前被阻塞的任务自动解锁。

**2. 双向依赖维护**

当调用 `addBlocks: [2, 3]` 时，不仅当前任务的 `blocks` 加上 `[2, 3]`，还会去更新任务 2 和 3 的 `blockedBy`，把当前任务 ID 加进去。

**比喻**：依赖关系像一条生产线。任务 1 完成了，下游的任务 2 和 3 自动收到"原材料就绪"的通知。

### list_all() -- 展示所有任务

```python
def list_all(self) -> str:
    tasks = []
    for f in sorted(self.dir.glob("task_*.json")):
        tasks.append(json.loads(f.read_text()))
    if not tasks:
        return "No tasks."
    lines = []
    for t in tasks:
        marker = {"pending": "[ ]", "in_progress": "[>]", "completed": "[x]"}.get(t["status"], "[?]")
        blocked = f" (blocked by: {t['blockedBy']})" if t.get("blockedBy") else ""
        lines.append(f"{marker} #{t['id']}: {t['subject']}{blocked}")
    return "\n".join(lines)
```

输出效果：
```
[x] #1: 搭建项目框架
[>] #2: 编写测试用例
[ ] #3: 实现核心功能 (blocked by: [2])
[ ] #4: 添加文档
```

状态标记：`[ ]` 待处理、`[>]` 进行中、`[x]` 已完成。

## 依赖关系的数据流

```
初始状态：
  task_1: {status: "pending", blocks: [2]}
  task_2: {status: "pending", blockedBy: [1], blocks: [3]}
  task_3: {status: "pending", blockedBy: [2]}

task_1 完成 (update(id=1, status="completed"))：
  1. task_1.status -> "completed"
  2. _clear_dependency(1) 扫描所有任务
     -> task_2.blockedBy 中有 1，移除
  结果：
  task_1: {status: "completed", blocks: [2]}
  task_2: {status: "pending", blockedBy: [], blocks: [3]}  <-- 解锁了！
  task_3: {status: "pending", blockedBy: [2]}
```

## 工具注册

模型可以通过 4 个任务工具来管理工作：

| 工具名 | 功能 | 关键参数 |
|--------|------|----------|
| `task_create` | 创建新任务 | subject, description |
| `task_update` | 更新状态/依赖 | task_id, status, addBlockedBy, addBlocks |
| `task_list` | 列出所有任务 | 无 |
| `task_get` | 查看单个任务详情 | task_id |

```python
TOOL_HANDLERS = {
    "task_create": lambda **kw: TASKS.create(kw["subject"], kw.get("description", "")),
    "task_update": lambda **kw: TASKS.update(
        kw["task_id"], kw.get("status"),
        kw.get("addBlockedBy"), kw.get("addBlocks")),
    "task_list":   lambda **kw: TASKS.list_all(),
    "task_get":    lambda **kw: TASKS.get(kw["task_id"]),
}
```

## 实际运行示例

```
s07 >> 帮我规划一个 Web 项目的开发任务

> bash: npm install express

> task_list:
  [x] #1: 搭建项目框架
  [ ] #2: 编写测试用例                     # 不再显示 blocked by
  [ ] #3: 实现核心功能 (blocked by: [2])
```

## Python 知识点

| 用法 | 说明 |
|------|------|
| `Path.glob("task_*.json")` | 用通配符匹配目录下的文件 |
| `f.stem.split("_")[1]` | 从文件名提取 ID：`task_3.json` -> `3` |
| `list(set(a + b))` | 合并两个列表并去重 |
| `json.loads(f.read_text())` | 读文件并解析 JSON |
| `json.dumps(obj, indent=2)` | 格式化输出 JSON（缩进 2 空格） |
| `raise ValueError(msg)` | 参数校验失败时抛异常 |
| `dict.get("key", [])` | 安全取值，key 不存在返回空列表 |
| `sorted(glob(...))` | 按文件名排序，保证输出顺序稳定 |

## 一句话总结

把任务状态存到磁盘上的 JSON 文件里，再配上自动解除依赖的双向引用，让 Agent 在上下文被压缩后依然知道自己"做到哪了、接下来该做什么"。
